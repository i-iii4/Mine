## Основание

Внешний повторный аудит приложения Mine для macOS и Chrome-клиппера по коммиту
`791a5f5`. Метод аудита: чтение исходников, требований и тестов, без запуска
приложения. 29.09.2026 каждое утверждение перепроверено по коду на `1c33c90`
пятью независимыми проверками: 58 утверждений, из них 52 подтверждены
полностью, 6 частично, ложных нет. Проверки нашли ещё шесть дефектов, они
включены в каталог с пометкой «сверх аудита».

Номера находок повторяют разделы аудита: А2 сохранность файлов, А3 клиппер,
А4 дизайн-система, А5 анимации, А6 функциональность приложения, А7 видео,

## Общая причина

Дефекты находятся на границах существующих частей, а не в отсутствии общего
механизма:

1. Модель отображения (`Block`, `Frontmatter` с закрытым набором полей)
   используется как полная модель исходного документа. Около пятнадцати путей
   записи собирают заметку заново через `serialize_block` и теряют текст,
   незнакомые свойства и комментарии YAML.
2. Операция теряет идентичность: вкладку, захват, пространство, задание.
   Выбор определяется в момент исполнения, а не в момент действия
   пользователя.
3. Поздний ответ или событие не проверяет актуальность: устаревший индекс,
   отложенное удаление, восстановление наблюдателя, выдача поиска.
4. Служебная ошибка блокирует независимое действие: ошибка создания коллекции
   убирает редактор, сбой потока замера шрифтов оставляет ленту на заготовках.

Исправлять эти границы, а не добавлять новый общий слой управления
состояниями. Конечный результат проверять автоматикой на том слое, где он
возникает (файл на диске, сохранённая карточка), а не на промежуточном.

## Контракты

**Ф1. Запись исходника сохраняет исходный текст.** Любая операция, меняющая
существующий `.md`, правит только затронутые поля или ссылки поверх исходных
байтов. Неизвестные ключи frontmatter, их порядок, комментарии YAML, пустые
строки и тело остаются байт в байт. Заметка без frontmatter не получает
служебных полей, если операция их не требует. Образец уже есть:
`patch_collections_frontmatter` (mine-core, collection.rs) и точечные правки в
file_identity. Переименование без смены содержимого выполняется
переименованием файла, а не заменой байтов.

**Ф2. Публикация и откат со сверкой.** Запись в пространство публикуется
только если файл на диске совпадает с тем, что было прочитано при подготовке
операции. Откат возвращает прежнее содержимое тоже только при совпадении с
тем, что опубликовала сама операция. При расхождении операция отказывается и
сообщает о внешней правке, ничего не перезаписывая. Защищённая запись
`write_atomically_if_unchanged` (files.rs) становится обязательной для всех
путей изменения исходников.

**Ф3. Ссылки обновляются по разрешению, а не по строке.** Переименование и
слияние находят обратные ссылки через `LinkIndex::resolve`, включая короткую
форму `[[Foo]]` для `Cards/Foo`, и переписывают их через `shortest_link`.

**Ф4. Удаление сверяется с исходниками.** Решение «файл не используется»
перед удалением медиа принимается по текущим исходникам кандидатов, а не по
индексу. Команды окна настроек, удаляющие или меняющие файлы, передают
`vault_id` пространства, для которого построен список; при несовпадении с
открытым пространством команда отказывается.

**Ф5. Что показано, то и сохранено.** Окончательное содержимое захвата
клиппера фиксируется в одном месте, в запросе сохранения, и ни помощник, ни
ядро не добавляют и не удаляют материал. Признак «это выделение» передаётся в
протоколе сохранения обоим исполнителям. Одинаковые файлы переиспользуются
одним физическим файлом, но авторские повторы в тексте и их подписи
сохраняются. Одинаковый `alt` не доказывает дубликат
(SPEC_PRODUCT_EXTRACTION.md).

**Ф6. Операция клиппера привязана с момента действия.** Буферы контекстного
меню и Instagram, снимок экрана, запасное окно и команды автономного режима
несут идентификатор вкладки, захвата и пространства, полученный при действии
пользователя. Редактор принимает материал только своей вкладки и адреса.

**Ф7. Индекс следует за файлами без внешнего повода.** Отложенное удаление
исполняется по таймеру, а не следующим событием. Восстановление файла
отменяет его отложенное удаление. Перемещение в Корзину, которое macOS
сообщает переименованием, считается удалением. Восстановление наблюдателя
пространства A не заменяет наблюдатель, если открыто уже другое
пространство.

**Ф8. Пространство открывается по идентичности.** При запуске путь из
настроек открывается, только если его `.mine/vault-id` совпадает с записью
реестра; иначе пространство ищется по идентичности (П30). В папку без `.mine`
приложение не записывает идентификатор без явного выбора пользователя.

**Ф9. Задание загрузки видео.** Идентичность задания: пространство, карточка
и ролик. У каждого задания своя рабочая папка. Отмена действует и до
регистрации процесса. Результат публикуется в пространство, где задание
начато, если его папка на месте и идентичность совпадает, даже если открыто
другое пространство; иначе остаётся в производном хранилище и предлагается
при возвращении.

**Ф10. Сетевой фильтр по адресу подключения.** Проверка частных и служебных
адресов выполняется над адресом, к которому реально идёт подключение
(собственный резолвер для HTTP-клиента), а не над отдельным DNS-запросом.
Запрещены IPv4 внутри IPv6 (`::ffff:127.0.0.1`), 100.64.0.0/10 и групповые
адреса.

**Ф11. Клавиши только из реестра команд.** Каждая переназначаемая команда
читает сочетание из `commandRegistry`; старое сочетание после переназначения
не работает.

**Ф12. Уменьшение движения и прерываемость.** Одна настройка управляет
CSS-переходами и программными анимациями: меню, диалоги, полоса вторичного
меню, масштаб изображения, камера графа, плавная прокрутка. Жест
пользователя прерывает программное движение и продолжает от текущего
экранного положения.

**Ф13. Автоматическая проверка обновлений.** Приложение само проверяет канал
обновлений после первого интерактивного кадра и затем раз в 24 часа (интервал
утверждён пользователем 29.09.2026). Найденное обновление показывается так
же, как при проверке кнопкой; установка только по действию пользователя.
Пустой канал не считается ошибкой. Автоматическая проверка не трогает
загрузку, проверенный архив и установку в работе; неудачу сети она не
показывает как ошибку, а повторяет на следующем проходе. Без настроенного
канала проверка не запускается.
