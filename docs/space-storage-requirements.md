# Требования к пространству и сохранению файлов

Пространство определяется корневой папкой. Внутренняя раскладка файлов влияет только на место создания новых файлов и не определяет состав пространства, содержимое карточек или связи между материалами.

Это внутренний документ требований по обсуждению с пользователем. Настройки записи и перемещения с сохранённым реестром реализованы и проверены. Приведённый ниже контракт совместимости уточнён 23.09.2026; его полное выполнение текущей реализацией ещё не подтверждено.

## Совместимость с Obsidian

Одно пространство является одной общей папкой, одновременно открытой в Mine и Obsidian. Пользователь видит одинаковое содержимое документов, вложения, свойства и связи независимо от приложения, в котором внесены изменения. Различие интерфейсов допустимо; отдельная скрытая организация материалов только в базе Mine недопустима.

1. Источником содержимого и связей являются Markdown, свойства документов и медиа. Коллекции представлены документами, а принадлежность к ним хранится в совместимых ссылках свойств. Mine сохраняет неизвестные пользовательские свойства и не требует своего плагина в Obsidian.
2. Mine записывает внутренние ссылки в синтаксисе Obsidian: `[[Имя]]` для заметок и `![[имя.jpg]]` для вложений. Используется кратчайший однозначный путь, а не полный путь по умолчанию. Для уникального имени папка не нужна; при совпадениях добавляется минимальная различающая часть пути. Псевдонимы, ссылки на заголовки и блоки сохраняются.
3. Для новых файлов Mine выбирает свободное имя во всём пространстве, при необходимости с суффиксом. Существующие файлы из Obsidian с одинаковыми именами в разных папках остаются самостоятельными материалами; их нельзя автоматически переименовывать, скрывать или объединять.
4. Чтение обычных Markdown-ссылок из существующих документов сохраняется. Уникальность имени не разрешает менять смысл относительного адреса по правилам другого синтаксиса.
5. Действующие связи восстанавливаются из документов без реестра. Удаление реестра и производных кэшей, затем произвольное перемещение файлов с уникальными именами между папками без переименования, затем открытие Mine не меняют цели ссылок. То же требуется для материалов, добавленных клиппером при закрытом Mine.
6. Для устаревшего пути во внутренней Obsidian-ссылке Mine ищет единственную цель по имени во всём пространстве. Если адрес нужно исправить, обновляется сама ссылка в документе, чтобы оба приложения показывали один материал. Неоднозначность не разрешается выбором ближайшего или первого файла.
7. Реестр сохраняется только как вспомогательная история для распознавания внешних переименований. Он не является альтернативным источником действующих связей и не имеет приоритета над изменённой пользователем ссылкой. После распознанного переименования обновляются ссылки в документах; результат доступен Obsidian без доступа к реестру.
8. При параллельной работе Mine перечитывает внешние изменения, не перезаписывает их устаревшим снимком и не запускает бесконечный цикл взаимных переписываний. При конкурентной записи нельзя молча терять правку пользователя.

Без истории нельзя гарантировать распознавание произвольного внешнего переименования, если старое имя исчезло из ссылки и файлов. Также невозможно однозначно восстановить утраченный адрес среди нескольких одноимённых целей без различающих сведений. Эти случаи не оправдывают зависимость обычного чтения и перемещений уникальных имён от реестра.

Переход текущей реализации должен сначала сохранить известные соответствия в однозначных совместимых ссылках. Удалять существующий реестр до проверки такой записи нельзя. Реестр после перехода продолжает обслуживать внешние переименования.

### Приёмка совместимости

1. Открыть одну папку одновременно в Mine и Obsidian. Создать и изменить заметки, вложения, свойства и связи в каждом приложении; проверить одинаковые цели и содержимое в обоих.
2. Закрыть Mine, добавить материал клиппером, удалить реестр, переместить файлы с уникальными именами в корень и вложенные папки, открыть Mine. Проверить исходные медиа и связи, а не только прежние превью. Повторить для нативного и автономного клиппера.
3. Повторить с удалёнными индексом и превью. Не должно быть потерь, подмен и дубликатов.
4. Проверить кратчайшие пути для уникальных имён и существующих одноимённых файлов. Совпадения нельзя разрешать произвольно.
5. С сохранённой историей переименовать файл через Finder при закрытом Mine. После открытия проверить обновлённую ссылку и её цель в обоих приложениях.
6. Изменить ссылку в Obsidian после её регистрации Mine. Проверить, что старая запись реестра не возвращает прежнюю цель. Проверить конкурентное изменение документа перед записью Mine.

Эти проверки являются открытыми задачами, а не результатами ранее пройденных тестов перемещения с сохранённым реестром.

## Пространство и его содержимое

1. Одна подключённая корневая папка соответствует одному пространству. Повторное подключение той же папки не создаёт второе пространство с тем же содержимым.
2. При создании нового пространства автоматически появляются три папки: `Cards`, `Media`, `Collections`. Они становятся начальными местами записи карточек, медиа и документов коллекций соответственно.
3. Эти три папки имеют обычный статус. Их наличие, название и расположение не являются условиями работы пространства.
4. Mine читает подходящие файлы во всём пространстве, включая корень и вложенные папки. Действующие правила отображения определяют, что показывать; путь сохранения новых файлов не ограничивает чтение.
5. Тип содержимого определяется самим файлом и поддерживаемыми правилами чтения. Перенос документа коллекции в папку с медиа не превращает его в медиа и не скрывает коллекцию.
6. Пользователь может перемещать файлы между папками, выносить их в корень, переименовывать папки, менять вложенность и удалять освободившиеся папки. Карточки, коллекции и связи сохраняются.
7. Правило действует при открытом и закрытом Mine. После повторного открытия приложение отражает фактическое содержимое выбранной корневой папки.

## Настройки места создания новых файлов

В интерфейсе задаются три независимых пути внутри выбранного пространства:

| Поле | Какие новые файлы направляет |
| --- | --- |
| Карточки | Документы карточек |
| Медиа | Новые сохраняемые медиафайлы |
| Коллекции | Документы новых коллекций |

Поля задают адрес создания файлов. Они не являются командами переименования или перемещения папок.

1. Заданный путь применяется только к новым файлам соответствующего типа. Это единое правило для приложения, клиппера и остальных способов добавления материалов.
2. Изменение пути не перемещает, не переименовывает и не переписывает существующие файлы. Редактирование существующего материала сохраняет его фактическое расположение. Повторное использование существующего медиа не создаёт его копию в новой папке.
3. Пустое поле означает корень пространства для соответствующего типа. Наличие папок с привычными названиями не меняет это значение автоматически.
4. Начальные пути нового пространства задаются при его создании. Отсутствующий путь в уже существующей настройке означает корень, а не попытку угадать назначение папок по их именам.
5. Допустимы вложенные пути. Несколько типов могут записываться в одну папку, включая корень.
6. Если заданной папки нет, она создаётся при следующей записи нового файла по этому пути. Само чтение пространства не восстанавливает удалённые папки.
7. Удаление или переименование папки через Finder не очищает введённый путь записи. Чтобы новые файлы попадали в корень, пользователь оставляет поле пустым; чтобы они попадали в другую папку, задаёт новый путь.
8. Путь остаётся внутри корневой папки пространства. Если запись по заданному адресу невозможна, приложение не перенаправляет файл молча в другое место и не сообщает об успешном сохранении.

Для интерфейса достаточно обозначить назначение полей: «Куда сохранять новые файлы». Пустое значение подписывается как «Корень пространства». Управление существующими папками не подменяется этими настройками.

## Основной сценарий: полностью заменить раскладку

1. Пользователь создаёт пространство. Mine создаёт `Cards`, `Media`, `Collections` и задаёт их как места сохранения.
2. Пользователь добавляет материалы. Новые файлы распределяются по этим трём папкам.
3. Пользователь переносит все файлы из трёх папок в корень пространства и удаляет освободившиеся папки.
4. Все прежние карточки, коллекции, изображения, видео и связи продолжают работать. Приложение не требует вернуть прежнюю структуру или вручную исправить ссылки.
5. Пользователь создаёт новые папки, например `Заметки`, `Вложения`, `Подборки`.
6. В настройках он указывает эти три пути для карточек, медиа и коллекций соответственно.
7. Следующее сохранение создаёт документы и медиа в новых папках. Старые файлы остаются в корне и продолжают работать вместе с новыми.
8. Пользователь очищает все три поля. Следующие новые файлы сохраняются в корне. Материалы из новых папок остаются на месте и также продолжают работать.

Тот же результат требуется, если папки вложены друг в друга, перемещена только часть материалов или перестановка выполнена при закрытом приложении. Структура заметна пользователю в Finder; сама перестановка не меняет состав и содержимое пространства в Mine.

## Связи и одинаковые имена

Связь должна указывать на тот же материал после изменения его расположения. Это относится к медиа карточек, вложениям в тексте, документам коллекций и связям между заметками. Смена пути сохранения сама по себе эти связи не меняет.

Одинаковые имена в разных папках допустимы. Например, `Фото/photo.jpg` и `Архив/photo.jpg` могут быть разными изображениями. Приложение должно различать их и сохранять существующие привязки:

1. Появление второго файла с тем же именем не переключает уже существующую карточку на новый файл.
2. Перемещение одного из одноимённых файлов не подменяет его другим и не объединяет два материала.
3. Совпадение имени, текста карточки или содержимого файла само по себе не доказывает, что это один объект. Совпадение названий коллекций также не даёт права потерять их различающееся содержимое.
4. При создании нового файла Mine не перезаписывает существующий файл с совпадающим именем. Новый материал получает свободное имя, а его ссылки указывают именно на него.
5. Если пользователь переносит одноимённые файлы в одну папку и Finder меняет имя одного из них для сохранения обоих, связи должны сохраняться с фактически оставшимися файлами.
6. Поиск «ближайшего» файла или первого совпадения по алфавиту не считается решением неоднозначности. Он может незаметно показать чужой материал.

### Что делает Obsidian

[Документация Obsidian](https://obsidian.md/help/settings) описывает режим кратчайшего однозначного пути: для уникального имени достаточно имени файла, а для различения совпадений путь включает папку. Например, ссылки на два разных `photo.jpg` могут содержать `Фото/photo.jpg` и `Архив/photo.jpg`. В той же документации описано автоматическое обновление внутренних ссылок при переименовании файла.

Поэтому наличие пути в ссылке само по себе не является архитектурной ошибкой. Для Mine требуется сохранять её назначение при перестановке файлов. Простая замена всех ссылок на голые имена не решает задачу одинаковых имён.

Справка Obsidian не подтверждает гарантированное восстановление любой перестановки, сделанной вне приложения при закрытом Obsidian. Требование Mine охватывает этот сценарий самостоятельно; поведение другого приложения не заменяет его проверку.

### Что должна обеспечить реализация Mine

Приложение различает существующие файлы, сохраняет соответствие между ссылкой и её целью и обновляет адрес цели после перемещения. При необходимости изменяются затронутые ссылки в документах. Изменение текста или других свойств материала ради перестановки не требуется.

Тот же результат обязателен для старых ссылок по имени и для ссылок с путём. Ссылка в документе и материал, который показывает Mine, не должны противоречить друг другу. Временная доступность старого превью не доказывает сохранность связи.

Этот документ не выбирает формат идентификаторов или схему хранения соответствий. Конкретный механизм должен доказать сохранность привязок при одинаковых именах и внешних перемещениях, включая закрытое приложение. Только поиск по имени или только совпадение хэша такого доказательства не дают.

## Проверка результата

| Действие | Требуемый результат |
| --- | --- |
| Создать пространство | Одна корневая папка, три начальные папки и три заданных пути записи |
| Перенести всё в корень и удалить пустые папки | Все прежние материалы и связи доступны |
| Назначить три новые папки | Только следующие новые файлы попадают в них; старые остаются на месте |
| Оставить один путь пустым | Новые файлы только этого типа сохраняются в корень |
| Оставить все пути пустыми при наличии стандартных папок | Все новые файлы сохраняются в корень |
| Удалить пустую папку, путь к которой остаётся заданным | Чтение работает; следующая запись создаёт папку по этому пути |
| Переименовать папку с материалами или вложить её в другую | Сохраняются те же материалы, коллекции и связи |
| Переместить карточку отдельно от её медиа | Карточка продолжает открывать исходное медиа |
| Переместить документ коллекции | Состав и свойства коллекции сохраняются |
| Добавить одноимённый файл и затем переместить исходный | Ссылки остаются привязаны к исходному файлу |
| Повторить перестановки при закрытом Mine | После открытия получается тот же результат |
| Повторить чтение и перезапуск | Нет дубликатов, исчезнувших материалов и повторного создания старой структуры |
| Повторить после пересоздания производного индекса и превью | Восстанавливаются те же материалы и связи из данных пространства |

Проверяются старые и новые карточки, ссылки по имени и с путём, изображения и видео, одинаковые имена, одинаковое содержимое разных документов и вложенные папки. Одинаковый результат требуется в ленте, открытой карточке, поиске и коллекциях. Проверка связи включает открытие исходного медиа, а не только показ сохранённой миниатюры.
