# Проверка совместимости ссылок

Контракт: [хранение пространства](</Users/i_iii/Проекты/Личные проекты/local-arena/docs/space-storage-requirements.md#совместимость-с-obsidian>).
Архитектура: [общее ядро и история переименований](</Users/i_iii/Проекты/Личные проекты/local-arena/SPEC_IDENTITY_ROBUSTNESS.md#архитектура-нового-механизма>).

## Проверено 23.09.2026

Obsidian 1.13.7 запущен с отдельным временным профилем и тестовым пространством. Официальный CLI читает реальные результаты `metadataCache.getFirstLinkpathDest` и `metadataCache.resolvedLinks`. Пользовательские пространства в проверке не участвуют.

| Сценарий | Результат |
| --- | --- |
| `[[Collection]]` в свойстве `Mine Collections` | Оба механизма находят `Collections/Collection.md` |
| `[[Related#Heading\|Related label]]` | Найдена вложенная заметка, якорь и подпись остаются в исходном тексте |
| `![[unique.svg]]` | Найдено вложение во вложенной папке |
| `![[A/same.svg]]` и `![[B/same.svg]]` | Найдены разные файлы в `Archive/A` и `Archive/B` |
| `Design.md` в корне и `Nested/Design.md` | Obsidian выбирает корневой документ для `[[Design]]`; Mine повторяет это правило |
| Удаление истории перед перемещением | Короткие ссылки продолжают работать без прежнего реестра |
| Перемещение заметки в корень, остальных материалов в новые подпапки | Obsidian не сообщает неразрешённых ссылок; Mine находит те же пять целей |
| Построение индекса с нуля, повторное открытие и повторное удаление производных данных | Состав карточек и коллекции стабилен, исходные файлы не изменены |
| Переименование вложенной заметки официальной командой Obsidian при открытом пространстве | Obsidian обновил ссылку, сохранив якорь и подпись; повторная индексация Mine прошла без изменения документов |

Obsidian может генерировать полный путь при совпадении имён. Mine генерирует более короткий различающий суффикс. Реальная проверка подтверждает одинаковую цель для этих вариантов, а не побайтовое совпадение генераторов ссылок.

Регрессионные проверки находятся в [тестах совместимости](</Users/i_iii/Проекты/Личные проекты/local-arena/src-tauri/tests/obsidian_compatibility.rs>) и [тестах хранения пространства](</Users/i_iii/Проекты/Личные проекты/local-arena/src-tauri/tests/space_storage_acceptance.rs>). Проверка живого временного пространства явно помечена `ignore`: ей нужно передать путь через `MINE_OBSIDIAN_ORACLE_ROOT`. Для перемещённой раскладки также задаётся `MINE_OBSIDIAN_ORACLE_SHUFFLED=1`. Обычный прогон не ищет и не открывает пользовательские пространства.

## Границы результата

Это проверка целей ссылок и файловых представлений, не визуальная приёмка интерфейсов. Наличие якоря в сохранённой ссылке не подтверждает прокрутку интерфейса до заголовка или блока.

Действующая ссылка имеет приоритет над историей. Если прежний файл переименован, а его старое имя занял другой файл, ссылка на существующее старое имя обозначает текущий файл. Без дополнительной информации нельзя одновременно соблюдать это правило и считать такую ссылку указателем на прежнее содержимое.

Внешнее переименование без истории не восстанавливается угадыванием по одинаковому содержимому. История распознаёт подтверждённое сохранение физического файла, а не произвольное копирование между устройствами.

Защита конкурентного исправления проверяет замену файла редактором. Она не является общей блокировкой Obsidian и Mine и не даёт гарантии для записи через ранее открытый дескриптор после замены файла.
