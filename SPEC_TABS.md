## Статус

Требования записаны 02.10.2026 со слов пользователя, спецификация 03.10.2026. Модель выбрана 02.10.2026 после сравнения с системными вкладками macOS: своя полоса вкладок и отдельная страница интерфейса на каждую вкладку, как в Figma. Не реализовано.

Проверка по PRINCIPLES.md и коду 03.10.2026: 21 замечание (1 блокирующее, 16 крупных, 4 мелких) внесено в этот текст.

Решения РП1 по РП7 приняты пользователем 03.10.2026 по рекомендованным вариантам. Работа начинается с пробы Э0: если проба не пройдёт, выбор модели возвращается пользователю.

## Требования пользователя

| | Требование |
|---|---|
| Т1 | В каждой вкладке можно открыть своё пространство. |
| Т2 | У каждой вкладки своя память. |
| Т3 | Вкладки сохраняются между запусками приложения. |
| Т4 | Перетаскивание вкладки меняет порядок. |
| Т5 | Перетаскивание вкладки за пределы окна создаёт ещё одно окно. |
| Т6 | Вид вкладок наш, по дизайн-системе Mine (вопрос пользователя о настройке вида системных вкладок, 02.10.2026). |

Т2 обязательна в двух смыслах. Состояние интерфейса одной вкладки не видно другой: у каждой вкладки свой процесс страницы. И вкладка возвращается такой, какой её оставили (место, открытая карточка, прокрутка), в том числе после выгрузки и перезапуска.

## Термины

- **Окно**: нативное окно macOS со вкладками, без собственной страницы. Метка `window-<window_id>`. Окно настроек окном вкладок не считается.
- **Полоса вкладок**: отдельная страница интерфейса вверху окна, одна на окно. Метка `tabbar-<window_id>`.
- **Вкладка**: запись с постоянным `tab_id`. У живой вкладки есть страница интерфейса с меткой `tab-<tab_id>`.
- **Живая вкладка**: её страница создана. **Выгруженная**: страницы нет, запись есть.
- **Видимая вкладка**: активная вкладка окна. В каждом окне видна ровно одна.
- **Последнее окно**: окно вкладок, последним бывшее в фокусе. Его хранит `TabRegistry`; фокус окна настроек или другого приложения его не меняет.
- **Пространство вкладки**: пространство (`vault_id`), которое показывает вкладка, или выбор пространства, когда показывать нечего.
- **Открытое пространство** (`OpenSpace`): единственный в процессе объект, который держит пространство открытым: индекс, наблюдатель за файлами, очереди обслуживания. Слово «владелец» здесь не используется: оно занято владельцем папки (SPEC_VAULT_LIFECYCLE.md, П22).
- **Ведущая вкладка пространства**: видимая вкладка этого пространства, а если таких несколько, та, что в окне, которое было в фокусе позже других. Если видимой вкладки пространства нет, ведущей нет.
- **Сохранённые окна**: окна, их вкладки, порядок и память вкладок в файле `windows.json`. Слово «сессия» здесь не используется: оно занято сессией ожиданий iCloud (SPEC_CLOUD_STORAGE.md, Х16).

## Устройство

```
Процесс Mine (один)
├── SpaceHost: открытые пространства, по одному на vault_id
├── TabRegistry: окна, вкладки, порядок, видимые вкладки, последнее окно, привязка вкладок к пространствам
├── WindowStore: windows.json
└── окна
    ├── window-A
    │   ├── tabbar-A            полоса вкладок
    │   ├── tab-1 (видна)       пространство X
    │   └── tab-2 (скрыта)      пространство Y
    └── window-B
        ├── tabbar-B
        └── tab-3 (видна)       пространство X, то же открытое пространство, что у tab-1
```

**В1.** Процесс один, бэкенд один. Окна и вкладки служат только видами. Второй экземпляр приложения по-прежнему завершается сразу (`acquire_single_instance`), ничего не передавая.

**В2.** Окно вкладок создаётся без собственной страницы (`WindowBuilder` из флага Tauri `unstable`) с `titleBarStyle: Overlay` и скрытым заголовком, как сейчас. Минимальный размер 904 × 600 плюс `TAB_BAR_HEIGHT_PX` по высоте. Дочерние страницы окна: полоса вкладок и живые вкладки (`Window::add_child`). Окно `main` из `tauri.conf.json` убирается: окна создаёт `TabRegistry` по сохранённым окнам. Окно настроек остаётся обычным окном со своей страницей `settings`.

**В3.** Рамки дочерних страниц считает бэкенд на `WindowEvent::Resized` и при смене полноэкранного режима: полоса во всю ширину высотой `TAB_BAR_HEIGHT_PX`, вкладки занимают остальное. `set_auto_resize` не используется: он хранит доли размера окна, и полоса постоянной высоты поплывёт (tauri #9611).

**В4.** Видна только активная вкладка окна, остальные живые вкладки скрыты (`hide()`). WebKit переводит скрытую страницу в `visibilityState = hidden`, останавливает её кадры и замедляет таймеры. Накрытую, но не скрытую страницу WebKit считает видимой, поэтому неактивная вкладка всегда скрывается, а не просто накрывается.

**В5.** Переключение вкладки идёт в три шага, чтобы не мигал пустой фон. Бэкенд ставит страницу новой вкладки в слой прямо под видимой и показывает её: накрытая страница для WebKit видима и рисует кадры. Новая вкладка сообщает о нарисованном кадре командой `tab_painted`. Бэкенд скрывает прежнюю вкладку и отдаёт фокус новой (`set_focus()`); без сигнала за `TAB_ACTIVATION_PAINT_TIMEOUT_MS` он делает это всё равно. API порядка слоёв в Tauri нет (tauri #11124): слой задаётся через `with_webview` и `addSubview:positioned:relativeTo:` на objc2. Фокус отдаётся явно: при скрытии AppKit передаёт его следующему виду, возможно другой вкладке.

**В6.** Полоса не рисует всплывающих элементов в своей странице: страница полосы низкая и обрезала бы их. Меню вкладки нативное (`Menu` Tauri). Подсказка это атрибут `title`: её рисует система поверх всех страниц.

### Открытые пространства

**В7.** `SpaceHost` держит открытые пространства по `vault_id`. `OpenSpace` собирает то, что сейчас лежит в `AppState` в одном экземпляре: соединение с индексом и раскладку (`VaultState`), наблюдатель (`VaultWatcher`), наблюдение за корнем раз в 2 с (SPEC_VAULT_LIFECYCLE.md, П15), сессию ожиданий iCloud (Х16), проверку превью, проход миниатюр, фоновую сверку. Две вкладки одного пространства получают одно `OpenSpace`, поэтому в одну папку и в один `index.db` пишет один объект.

**В8.** `OpenSpace` держат аренды: живая вкладка этого пространства, идущая работа (скачивание медиа, импорт, проход превью), действие окна настроек над этим пространством. Выгруженная вкладка аренды не держит. Когда кончается последняя аренда, пространство закрывается через `SPACE_RELEASE_GRACE_MS`; новая аренда в этот промежуток получает прежнее `OpenSpace`.

**В9.** Наблюдение за корнем и сессия ожиданий iCloud живут столько, сколько `OpenSpace`, а не выбор во вкладке. Сейчас наблюдение за корнем привязано к счётчику выбора и прекращается при новом выборе (`vault.rs`). Х17 читается так: сессию ожиданий начинает открытие `OpenSpace`; повторная аренда в промежуток `SPACE_RELEASE_GRACE_MS` продолжает прежнюю сессию.

**В10.** Открытие пространства во вкладке не трогает другие вкладки. Счётчик поколения выбора (`vault_selection_request`) становится счётчиком вкладки: новый выбор во вкладке A отменяет только незавершённый выбор вкладки A. Замки `vault_selection` и `vault_publication` становятся замками `OpenSpace`. П25 выполняется буквально: недоступность одного пространства не мешает открыть другое и не трогает его вкладки.

**В11.** Команда интерфейса узнаёт своё пространство по вызвавшей странице: Tauri передаёт команде `Webview`, `TabRegistry` переводит метку `tab-<tab_id>` во вкладку, вкладку в `OpenSpace`. Неявного текущего пространства процесса больше нет: `current_vault_layout`, `is_current_vault`, `current_vault_path`, `current_read_owner` и прямые обращения к `AppState.vault_state` (151 место, около 68 из 94 команд) переходят на контекст вкладки `TabContext`. Команды окна настроек получают `vault_id` параметром.

**В12.** Общими на процесс остаются: модель смысловых векторов поиска (`FASTEMBED_MODEL`, одна на процесс, память не растёт с числом вкладок), глобальный замок записи источников, замок открытия соединений, сервер страницы YouTube, учёт синхронизации и подавленные пути (ключ уже абсолютный путь), область asset-протокола (адрес ресурса это абсолютный путь, область только растёт).

**В13.** Модель векторов обслуживает пространства по очереди вместо немедленной ошибки «semantic model is warming» (сейчас `try_lock`). Очередь построена на `Condvar`, у `std::sync::Mutex` ожидания с пределом нет. Запрос поиска из вкладки встаёт раньше фонового прогрева и индексации. Ждавший дольше `EMBEDDING_MODEL_WAIT_MS` получает типизированную ошибку занятости модели, и поиск отвечает без смыслового слоя, как сейчас при прогреве.

**В14.** Проход миниатюр (`ThumbnailSweepCoordinator`, сейчас одно идущее и одно ждущее пространство) и проверка превью (`PreviewReconcileCoordinator`, сейчас `keep_only(active)` и выход для неактивного пространства) обслуживают все открытые пространства. Первым идёт пространство видимой вкладки последнего окна, остальные по очереди.

### Вкладки одного пространства

**В15.** Изменение, сделанное во вкладке A, вкладка B того же пространства получает как внешнее. Сейчас наблюдатель отбрасывает пути, записанные самим приложением (`is_path_suppressed` в `watch.rs`), а команды коллекций и карточек событий не шлют: вкладка узнаёт о своей записи из ответа команды. Поэтому после каждой успешной команды изменения `TabContext` шлёт `vault-changed` всем живым вкладкам этого пространства, кроме вызвавшей.

**В16.** Какие команды меняют пространство, записано в одном перечне (`commands/effects.rs`): чтение или изменение. Тест сверяет перечень со всеми зарегистрированными командами; команда без записи в перечне роняет тест. Рассылку по В15 делает `TabContext` по этому перечню, а не каждая команда сама.

**В17.** `vault-changed` несёт переименования, сделанные командой: `renames: Vec<SpaceRename>` с видом (коллекция или карточка), прежним и новым именем. У событий наблюдателя список пустой.

**В18.** Получив `vault-changed`, вкладка сверяет свою память:

- коллекцию места переименовали: место следует за новым именем;
- коллекции места нет: место становится Everything;
- открытую карточку переименовали: карточка остаётся открытой под новым именем;
- открытой карточки нет (удалили, слили): карточка закрывается;
- выделение и открытые редакторы, ссылающиеся на исчезнувшее, закрываются, как сейчас при внешнем изменении.

Те же проверки идут при восстановлении вкладки по сохранённой памяти. Если там нет карточки якоря прокрутки, лента открывается с начала.

### Ведущая вкладка пространства

**В19.** Работу и уведомления за всё пространство берёт только ведущая вкладка:

- вторая фаза миниатюр в странице (`thumb:upgrade-requested`, `derived-preview-pending`, SPEC_THUMBNAILS.md);
- уведомление о ходе индексации и подготовки превью (SPEC_ONBOARDING.md, О13);
- пометка первой карточки (О19);
- рекомендация Keep Downloaded (SPEC_CLOUD_STORAGE.md, Х18).

Скрытая вкладка ведущей не бывает: в ней стоят кадры и замедлены таймеры (В4), а декодирование видео для миниатюр на них опирается. Пока у пространства нет ведущей вкладки, эта работа ждёт, уведомления не показываются.

**В20.** Смену ведущей вкладки бэкенд сообщает событием `space-lead-changed` вкладкам, у которых сменилась роль. Закрытие уведомления пространства и записи в его файлы рядом с индексом (`first-card.json`, `space-onboarding.json`, `cloud-waits.json`) делает бэкенд; состояние «уведомление закрыто в этом открытии» хранит `OpenSpace`, поэтому новая ведущая вкладка закрытое уведомление не показывает снова.

Нарушения ловит линтер.

### Окно и страница

**В23.** Действия с окном (начать перетаскивание окна, полноэкранный режим) страница вызывает командами бэкенда, который находит окно вкладки через `TabRegistry`.

**В24.** Права страниц выдаются по меткам страниц: `"webviews": ["tab-*", "tabbar-*", "settings"]`, без поля `windows`. Права по метке окна получили бы все страницы окна, а перенесённая вкладка потеряла бы свои.

**В25.** Цвет фона окна задаёт бэкенд. Страница сообщает цвет поверхности хрома, вычисленный из её CSS-токена, командой `report_window_surface`; бэкенд красит все окна и хранит цвет в `windows.json` для следующего запуска; при самом первом запуске окно получает системный цвет фона. Сейчас страница вызывает `setBackgroundColor` сама (`nativeWindowChromeSurface.ts`), но права `core:window:allow-set-background-color` нет, и отказ проглатывает пустой `catch`: этот вызов и пустой `catch` убираются.

**В26.** Новая страница вкладки скрывается сразу после создания и показывается по В5: `background_color` страницы на macOS не работает, без этого мелькнёт белый фон.

## Сохранённые окна

**В27.** Сохранённые окна лежат в `windows.json` в папке данных приложения (`~/Library/Application Support/com.mine.app/`, у отладочной копии своя `com.mine.app.dev`). Не в `config.json`: они меняются часто, а каждое изменение конфигурации поднимает поколение настроек, по которому перечитывает себя клиппер (SPEC_CLIPPER.md, К5).

**В28.** Схема версии 1. Типы живут в Rust (`domain/windows.rs`), TypeScript генерируется (`bun run bindings:generate`). Перечисления в JSON помечены полем `kind` в `snake_case`, как `CommandError`.

```rust
/// 32 lowercase hex characters from 16 random bytes (getrandom).
pub struct TabId(String);
pub struct WindowId(String);
// VaultId is the existing space identifier read from .mine/vault-id.

/// Every tab window restored at launch.
pub struct SavedWindows {
    pub version: u32,                         // SAVED_WINDOWS_VERSION
    pub windows: Vec<SavedWindow>,            // the first one is the last window (key window)
    pub window_surface: Option<RgbColor>,     // background painted before any page loads
}

pub struct SavedWindow {
    pub id: WindowId,
    pub frame: WindowFrame,
    pub fullscreen: bool,
    pub tabs: Vec<SavedTab>,                  // left to right
    pub active_tab: TabId,
    pub sidebar: SidebarLayout,               // one sidebar per window (РП5)
}

/// Logical points in global screen coordinates, as macOS reports them.
pub struct WindowFrame { pub x: f64, pub y: f64, pub width: f64, pub height: f64 }

pub struct SidebarLayout { pub width_px: u32, pub collapsed: bool }

pub struct SavedTab {
    pub id: TabId,
    pub space: TabSpace,
    pub view: TabView,
}

pub enum TabSpace {
    Space { vault_id: VaultId },
    Picker,                                   // nothing to show: no spaces yet, or the space was forgotten
}

pub struct TabView {
    pub location: TabLocation,
    pub mode: MainViewMode,                   // Grid or Graph
    pub open_card: Option<OpenCard>,
    pub scroll_anchor: Option<ScrollAnchor>,
    pub collection_filter: String,
}

pub enum TabLocation {
    Everything,
    Collection { tag: String },
}

pub struct OpenCard { pub slug: String, pub link_mode: DetailLinkMode } // All or Connected

/// The first card whose top edge is at or below the feed's top edge, and that distance.
pub struct ScrollAnchor { pub slug: String, pub offset_px: f64 }
```

`MainViewMode` и `DetailLinkMode` сейчас живут только в интерфейсе: они переезжают в Rust и генерируются, ручного дубля в TypeScript нет.

**В29.** Вкладка привязывается к пространству только по `vault_id`. Записи реестра без `vault_id` (перенесённые из старого списка путей, `space_registry.rs`) получают его при первом открытии, как сейчас. Вкладка, у которой открытие такой записи не удалось, сохраняет прежнее пространство или выбор пространства.

**В30.** В сохранённые окна не входят временные состояния: открытые меню и диалоги, оверлей поиска, редактор имени, выделение карточек, история назад и вперёд. Пока вкладка живая, они остаются в её памяти. После выгрузки или перезапуска вкладка возвращается без них.

**В31.** Вкладка сообщает свой `TabView` бэкенду командой `report_tab_view` не чаще раза в `TAB_VIEW_REPORT_DEBOUNCE_MS`. Бэкенд пишет `windows.json` не чаще раза в `SAVE_WINDOWS_DEBOUNCE_MS`: временный файл, затем переименование. Падение процесса теряет не больше последних `SAVE_WINDOWS_DEBOUNCE_MS` изменений, файл наполовину не пишется.

**В32.** Чтение сохранённых окон (чистая функция в `domain/windows.rs`, без файловой системы; список экранов передаётся ей параметром):

- нечитаемый или пустой файл: одно окно с одной вкладкой на последнем пространстве из реестра, как при запуске сейчас; прежний файл сохраняется рядом как `windows.corrupt.json`, в журнал пишется событие без путей пространств;
- версия новее известной (файл записан более новой сборкой): файл переименовывается в `windows.v<версия>.json` и не перезаписывается, запуск идёт как в первом пункте;
- пространства вкладки нет в реестре (его забыли): вкладка удаляется;
- пространство есть в реестре, а папка недоступна: вкладка остаётся и показывает экран недоступной папки (SPEC_VAULT_LIFECYCLE.md, П12);
- повтор `tab_id` или `window_id`: повтор получает новый идентификатор;
- `active_tab` не из этого окна: активной становится первая вкладка окна;
- окно без вкладок удаляется; без окон поведение первого пункта;
- полоса окна (вся ширина и `TAB_BAR_HEIGHT_PX`) видна на экранах меньше чем на `WINDOW_GRAB_MIN_VISIBLE_PX` по ширине: окно встаёт по центру главного экрана прежним размером, обрезанным по экрану;
- полноэкранное окно возвращается полноэкранным на своём экране, а без этого экрана на главном.

**В33.** Выход и закрытие окон различаются:

- ⌘Q, пункт Quit и перезапуск после обновления (`app.exit`, `app.restart` в `updater.rs`) приходят как `RunEvent::ExitRequested`. `TabRegistry` переходит в состояние выхода и сразу пишет сохранённые окна; окна, закрывающиеся после этого, сохранённое не меняют.
- Закрытие окна вкладок, когда есть другие, удаляет его из сохранённых.
- Закрытие последнего окна вкладок завершает приложение и закрывает окно настроек; сохранённым остаётся это окно, следующий запуск его вернёт. Сейчас окно настроек держит процесс живым после закрытия главного окна: это меняется.

**В34.** Нативная проверка (`bun run test:native-shell`) работает с отдельной временной папкой данных и не пишет `windows.json`. Сейчас она запускает приложение с настоящим HOME параллельно с Mine пользователя: с сохранёнными окнами она подняла бы окна пользователя и писала бы в его файл.

## Запуск

**В35.** Критический путь запуска (SPEC_STARTUP_PERFORMANCE.md, от S1 до S6) содержит только последнее окно и его видимую вкладку: чтение `windows.json`, создание окна, полосы и одной страницы вкладки, открытие снимка её пространства. Бюджеты прежние (холодный p50, холодный p95, тёплый p95): оболочка 300, 500 и 250 мс; первые сохранённые карточки 800, 1000 и 500 мс. Чтение `windows.json` входит в бюджет оболочки.

**В36.** После `first-route-committed` создаются остальные окна с их видимыми вкладками, в сохранённом порядке. Неактивные вкладки не создаются: полоса показывает их по сохранённой записи (имя пространства берётся из реестра), страница создаётся при первом выборе вкладки.

**В37.** Обслуживание (клиппер, сверка, превью) по-прежнему стартует после первого интерактивного кадра, координатор один на процесс.

## Память и фон

**В38.** Живых вкладок в процессе не больше `LIVE_TAB_LIMIT`. Каждая живая вкладка это отдельный процесс WebKit: замер 02.10.2026 на машине пользователя дал от 103 МБ (установленный Mine после суток работы) до 551 МБ (отладочная копия, пространство на 653 карточки, 33 минуты работы). Сверх предела выгружается неактивная вкладка, которую дольше всех не выбирали. Видимые вкладки не выгружаются никогда.

**В39.** По сигналу системы о нехватке памяти (уровень warning и выше) выгружаются все неактивные вкладки, кроме выбранной последней в каждом окне.

**В40.** Выгрузка: вкладка сообщает свежий `TabView` (В31), страница закрывается, запись остаётся. Выбор выгруженной вкладки создаёт страницу заново по `TabView` с проверками В18: место, режим, открытая карточка, прокрутка к сохранённой карточке.

**В41.** Скрытая вкладка ставит на паузу всё своё медиа: видео ленты, видео в открытой карточке, встроенный проигрыватель YouTube (командой паузы его API). Без этого звук скрытой вкладки продолжает играть. При показе сама она ничего не запускает: автозапуск ленты включается по своим правилам (SPEC_FEED_VIDEO.md).

**В42.** Показ вкладки не запускает принудительную сверку с диском. Её запускает возврат в приложение (фокус окна вкладок), один раз на открытое пространство, с прежним пределом частоты 10 с на пространство. Сейчас сверку запускают фокус и `visibilitychange` каждой страницы (`App.tsx`), и каждое переключение вкладки запускало бы её.

## Полоса вкладок

**В43.** Полоса это отдельный ряд над нынешним хромом во всю ширину окна (РП1). Слева резерв светофоров 80 px и кнопка бокового меню (РП6), затем вкладки, за последней вкладкой кнопка `+` (lucide `Plus`). Страница вкладки теряет свой резерв светофоров и кнопку бокового меню: её первый ряд начинается с переключателя пространства.

**В44.** Высота полосы `TAB_BAR_HEIGHT_PX` задана одной константой в Rust и попадает в сгенерированные TypeScript-типы; страница полосы берёт её оттуда. Тест сверяет её с токенами хрома: содержимое ряда `--chrome-row-content-height` (30 px) и разделитель 1 px.

**В45.** Полоса видна всегда, и при одной вкладке (РП2).

**В46.** Вкладка показывает подпись и крестик закрытия (lucide `X`) на видимой вкладке и на вкладке под указателем. Текст 13 px, иконки 13 px с линией 1 px, скругление 3 px, цвета хрома (DESIGN_SYSTEM.md). Полную подпись показывает подсказка `title`.

**В47.** Подпись (РП4): на Everything имя пространства; внутри коллекции имя коллекции цветом текста и после него имя пространства приглушённым цветом. При нехватке места первым сокращается имя пространства. Вкладка без пространства подписана `Choose Space`. Имя пространства берётся из реестра, поэтому выгруженная вкладка подписана без своей страницы.

**В48.** Вкладки одной ширины, от `TAB_MIN_WIDTH_PX` до `TAB_MAX_WIDTH_PX`: полоса делит доступную ширину поровну. Когда вкладки не помещаются и в минимальной ширине, полоса прокручивается по горизонтали с растворением краёв (SPEC_SCROLL_EDGE_FADE.md), видимая вкладка всегда прокручена в видимую часть. После закрытия вкладки крестиком ширины остальных не меняются, пока указатель над полосой: под указателем оказывается крестик следующей вкладки.

**В49.** Полоса доступна с клавиатуры: роль `tablist`, у вкладки роль `tab` и `aria-selected`; стрелки влево и вправо двигают фокус, Enter и пробел выбирают вкладку, Delete закрывает. Фокус полоса держит только при работе с клавиатуры: щелчок по вкладке отдаёт фокус выбранной вкладке.

**В50.** Правый щелчок по вкладке открывает нативное меню: `Move Tab to New Window`, разделитель, `Close Tab`, `Close Other Tabs`. Бросок файлов на полосу ничего не делает.

## Действия с вкладками

**В51.** Новая вкладка (`+`, ⌘T, File → New Tab) встаёт последней в окне, становится видимой и открывает пространство видимой вкладки на Everything (РП3). Если у видимой вкладки нет пространства, у новой тоже.

**В52.** Пространство в новой вкладке: ⌘-щелчок по пространству в переключателе пространств или пункт `Open in New Tab` в его меню. Обычный выбор в переключателе меняет пространство этой вкладки (В10). `Add Space`, `Create new space` и `Locate folder…` внутри вкладки открывают результат в этой вкладке.

**В53.** Закрыть вкладку: крестик, ⌘W, средняя кнопка мыши, меню вкладки. Подтверждения нет: Mine пишет изменения сразу. Видимой становится вкладка справа, при её отсутствии слева. Закрытие последней вкладки окна закрывает окно (В33).

**В54.** Новое окно (⌘N, File → New Window): одна вкладка с пространством видимой вкладки последнего окна на Everything (РП3). Закрыть окно: ⇧⌘W.

**В55.** Переключение по кругу: ⇧⌘] и ⌃Tab на следующую, ⇧⌘[ и ⌃⇧Tab на предыдущую; ⌘1 по ⌘8 на вкладку по номеру, ⌘9 на последнюю.

**В56.** Боковым меню владеет окно, его раскладку хранит бэкенд. Кнопка в полосе, пункт меню View (⌃⌘S), жест двумя пальцами (`swipe_gesture.rs`, окно, получившее жест) и перетаскивание края меню во вкладке меняют раскладку командой `set_window_sidebar`; бэкенд шлёт `window-sidebar-changed` всем вкладкам окна и полосе. Заголовок пункта View (`window_chrome.rs`, сейчас один на приложение) следует за боковым меню последнего окна.

## Сочетания клавиш

**В57.** Команды вкладок входят в общий реестр команд (`commandRegistry.ts`) с подписями из общего словаря клавиш (`commandBinding.ts`) и не переназначаются: macOS закрепляет эти сочетания за вкладками и окнами во всех приложениях. Сочетания с ⌘ это пункты нативного меню (File: New Tab, New Window, Close Tab, Close Window; Window: Show Previous Tab, Show Next Tab, Move Tab to New Window). Меню получает сочетание раньше страницы, поэтому они работают в любой странице окна, включая полосу. ⌃Tab и ⌃⇧Tab ловят страницы вкладки и полосы и передают командой бэкенду.

**В58.** Пункты меню File свои, а не готовый `close_window` из muda: он намертво занимает ⌘W. Close Tab и Close Window действуют на окно, которое сейчас в фокусе: если в фокусе окно настроек, ⌘W закрывает его.

**В59.** Список запрещённых для переназначения сочетаний (`RESERVED` в `shortcutValidation.ts`, уже содержит ⌘T, ⌘W и ⌘N) дополняется: ⌘1 по ⌘9, ⇧⌘[, ⇧⌘], ⌃Tab, ⌃⇧Tab, ⇧⌘W. Переназначения пользователя на эти сочетания снимаются при первом запуске новой сборки: команда остаётся без сочетания, раздел Shortcuts показывает её так, в журнал пишется событие. Простой Tab (Grid и Graph) требует точного набора модификаторов и с ⌃Tab не пересекается. SPEC_KEYBOARD.md обновляется вместе с этим.

## Перетаскивание

**В60.** Перестановка (Т4): нажать на вкладку и сдвинуть по горизонтали дальше порога жеста хрома (4 px, `useChromeDragGesture.ts`). Вкладка идёт за указателем, соседние раздвигаются за `TAB_REORDER_MOTION_MS`, без движения при уменьшении движения (`src/lib/motion.ts`). Отпускание фиксирует порядок и сразу пишет сохранённые окна; Escape возвращает вкладку на место.

**В61.** Отрыв (Т5): указатель уходит от полосы по вертикали дальше `TAB_DETACH_THRESHOLD_PX` или за пределы окна. Бэкенд создаёт окно того же размера так, чтобы вкладка в его полосе встала под указателем с тем же смещением захвата, переносит в него страницу вкладки (`reparent`), и окно идёт за указателем до отпускания кнопки. Страница не перезагружается: это тот же процесс, память вкладки сохраняется целиком.

**В62.** Окно с одной вкладкой её не отрывает: перетаскивание единственной вкладки двигает само окно, той же петлёй слежения бэкенда (В64), а не системным перетаскиванием окна. Системное перетаскивание забирает мышь, и подсветить место в чужой полосе было бы нечем.

**В63.** Присоединение: пока оторванная вкладка или окно с одной вкладкой движется, указатель над полосой другого окна вкладок подсвечивает место вставки в той полосе. Отпускание там переносит страницу вкладки в то окно на это место, и опустевшее окно закрывается. Отпускание в любом другом месте оставляет окно там, где оно стоит. Escape отменяет отрыв: вкладка возвращается в исходное окно на прежнее место, новое окно закрывается.

**В64.** Во время отрыва за указателем следит бэкенд, а не страница: события мыши за пределами окна странице не гарантированы, а перетаскивание HTML5 запускает системный сеанс, в котором окно не может идти за курсором. Способ выбирает проба Э0: локальный монитор событий `NSEvent` с `setFrame`, как в Chrome, или опрос `cursor_position`.

**В65.** В полноэкранном окне отрыв работает как `Move Tab to New Window`: новое обычное окно встаёт на обычный рабочий стол по центру главного экрана, размером окна до входа в полноэкранный режим, без следования за указателем.

**В66.** Перенос страницы идёт на главном потоке и только в уже созданное окно. Во время переноса бэкенд не шлёт этой странице `eval` и события из других потоков (взаимная блокировка, tauri #15489). Сразу после переноса бэкенд задаёт рамку страницы (`set_bounds`): сама она не пересчитывается.

**В67.** Связь вкладки с окном хранит только `TabRegistry`. При ошибке переноса Tauri уже вынул страницу из исходного окна и выбросил её, а `Webview::reparent` переписал своё окно ещё до вызова (tauri-runtime-wry 2.10.1, обработчик `Reparent`). Поэтому после ошибки `TabRegistry` создаёт страницу вкладки заново по её `TabView` в исходном окне на прежнем месте и пишет `TabError::Move` в журнал. Этот путь проверяет проба Э0.

**В68.** Выход из приложения во время перетаскивания отменяет его: сохранённые окна пишутся такими, какими были до начала перетаскивания.

## Связи с остальным приложением

**В69.** Окно настроек остаётся одно на приложение. В разделе Spaces строка `Open` выбирает вкладку этого пространства в последнем окне, а если такой нет, открывает там новую вкладку. Строки пространств, открытых хотя бы в одной вкладке, получают фон `bg-active` (SPEC_SETTINGS_WINDOW.md, Р-12: раньше так отмечалось одно активное пространство). Список обновляется по `spaces-open-changed`.

**В70.** `Forget` доступен всегда. Все вкладки забытого пространства, живые и выгруженные, переходят к выбору пространства. `Forget this space` на экране недоступной папки во вкладке забывает пространство этой вкладки по её `vault_id`; сейчас `forget_unavailable_vault` берёт общий `vault_path` (`vault.rs`). Это заменяет Р-6 и Р-9 из SPEC_SETTINGS_WINDOW.md: переключение главного окна и выбор другого пространства перед забыванием текущего.

**В71.** Разделы Orphans и Layout окна настроек действуют на пространство, выбранное в самом разделе; по умолчанию это пространство видимой вкладки последнего окна. Их команды получают `vault_id` явно.

**В72.** Открытие папки пространства из Finder и запрос расширения открыть Mine (`RunEvent::Opened`, `app_open.rs`) решает бэкенд: выбирает вкладку этого пространства, выбранную последней, переводит её на Everything и делает видимой, а если такой нет, открывает новую вкладку в последнем окне. Запрос, пришедший до восстановления окон, ждёт его в `TabRegistry`. Одноместный слот `PendingSpace` и событие `open-space-requested` уходят: решение принимает бэкенд, гонки между страницами нет.

**В73.** Переезд папки пространства (П30) замечает наблюдение за корнем его `OpenSpace` (В9). `OpenSpace` переходит на новый корень, открывает его в области asset-протокола и шлёт `space-moved` всем вкладкам пространства и окну настроек. Вкладки перечитывают свой маршрут: адреса медиа это абсолютные пути.

**В74.** `vault_path` в `config.json` (помощник клиппера и CLI читают его как текущее пространство) означает пространство видимой вкладки последнего окна. Бэкенд записывает его, только когда это пространство меняется, а не при каждом переключении между вкладками одного пространства.

**В75.** MCP закрепляет пространство по умолчанию при первом вызове без параметра `space` и держит его до конца своего процесса; ответы называют пространство. Сейчас MCP читает `vault_path` при каждом вызове: с вкладками щелчок по другой вкладке менял бы цель агента между его вызовами, и следующее удаление или слияние ушло бы в другое пространство. CLI работает один вызов и читает `vault_path` при каждом запуске, как сейчас. SPEC_AI_ACCESS.md обновляется вместе с этим.

**В76.** Проверка помощника клиппера при возврате в окно (SPEC_ONBOARDING.md, О5) срабатывает при фокусе любого окна вкладок, а не только `main`.

**В77.** Меню правого щелчка встроенного кадра (`frame_context_menu.rs`) знает все страницы вкладок, а не одну `MAIN_VIEW`, и шлёт событие той вкладке, где щёлкнули.

**В78.** Состояние делится так (РП5):

| Что | Где живёт | Почему |
|---|---|---|
| Тема, скругление карточек, `Spacing`, растворение краёв, нижняя панель действий, параметры графа, шрифты, сочетания клавиш | приложение, как сейчас (`localStorage` с `settings-changed`, `config.json`) | вид всего приложения |
| `Sort` и `Show` ленты | приложение, как сейчас | вид карточек, а не место |
| Ширина и свёрнутость бокового меню | окно (`SavedWindow.sidebar`, В56) | кнопка меню стоит в полосе окна (РП6), меню не прыгает при переключении вкладок |
| Место, Grid или Graph, открытая карточка и её режим связей, прокрутка, фильтр коллекций | вкладка (`TabView`) | это память вкладки |

**В79.** Ключи `mine.mainViewMode` и `mine:sidebar` уходят из `localStorage`: при первом запуске новой сборки их значения становятся начальными для первой вкладки и первого окна, затем ключи удаляются. Ключ `mine:recentTags` никто не читает, кроме записи в него: он удаляется вместе с записью.

## Ошибки

```rust
/// Failures of the tab and window layer.
#[derive(Debug, thiserror::Error)]
pub enum TabError {
    #[error("unknown tab {tab_id}")]
    UnknownTab { tab_id: TabId },
    #[error("unknown window {window_id}")]
    UnknownWindow { window_id: WindowId },
    #[error("the calling page {label} is not a tab")]
    NotATab { label: String },
    #[error("space {vault_id} is not in the registry")]
    UnknownSpace { vault_id: VaultId },
    #[error("failed to create the page for tab {tab_id}: {source}")]
    PageCreate { tab_id: TabId, source: tauri::Error },
    #[error("failed to move tab {tab_id} into window {window_id}: {source}")]
    Move { tab_id: TabId, window_id: WindowId, source: tauri::Error },
}

/// Failures of reading and writing windows.json.
#[derive(Debug, thiserror::Error)]
pub enum SavedWindowsError {
    #[error("failed to read the saved windows: {source}")]
    Read { source: std::io::Error },
    #[error("failed to write the saved windows: {source}")]
    Write { source: std::io::Error },
    #[error("saved windows version {found} is newer than {known}")]
    NewerVersion { found: u32, known: u32 },
    #[error("malformed saved windows: {source}")]
    Parse { source: serde_json::Error },
}
```

`tauri::Error` не сериализуется, поэтому `TabError` до интерфейса не доходит как есть: команды переводят его в новый вариант `CommandError::Tab` с текстом ошибки, а исходная ошибка пишется в журнал. Ошибка открытия пространства передаётся нынешним вариантом `CommandError` без изменений.

Вкладка, чья страница не создалась, остаётся в полосе с меткой ошибки; повторный выбор повторяет создание. Ошибка чтения сохранённых окон ведёт по В32. Ошибка записи пишется в журнал и повторяется при следующем изменении, интерфейс она не останавливает.

| `tab_painted()` | вкладка | сигнал кадра при переключении (В5) |
| `activate_tab(tab_id)` | полоса, меню | сделать вкладку видимой |

| `close_tab(tab_id)`, `close_other_tabs(tab_id)` | полоса, меню | В53 |

## Решения пользователя

Приняты 03.10.2026 по рекомендованным вариантам.

| | Вопрос | Решение | Отвергнутый вариант |
|---|---|---|---|
| РП1 | Где полоса вкладок | отдельный ряд над хромом, нынешний хром без изменений | вкладки вместо первого ряда: переключатель пространства становится вкладкой, фильтр и переключатель коллекций переезжают во второй ряд |
| РП2 | Полоса при одной вкладке | видна всегда: хром не прыгает при открытии второй вкладки | скрыта при одной вкладке |
| РП3 | Что открывают новая вкладка и новое окно | пространство видимой вкладки на Everything | экран выбора пространства |
| РП4 | Подпись вкладки | В47: пространство, внутри коллекции коллекция и пространство | всегда только пространство |
| РП5 | Что помнит вкладка | таблица В78 | всё, включая `Sort`, `Show` и боковое меню, помнит вкладка |
| РП6 | Кнопка бокового меню | в полосе справа от светофоров, где она стоит сейчас; действует на окно | в первом ряду страницы вкладки, действует на вкладку |
| РП7 | Сколько вкладок живут одновременно | 6, сверх предела выгружаются давно не выбранные | без предела |

## Не делаем

- Возврат закрытой вкладки (⇧⌘T), закреплённые вкладки, группы вкладок, две вкладки рядом в одном окне.
- Историю назад и вперёд между запусками.
- Системные вкладки macOS и пункт Window → Merge All Windows.
- Перетаскивание карточек и файлов на вкладку, перенос вкладок в другие приложения.
- Второй экземпляр приложения.

## Проверки

Rust:

- `domain/windows.rs`: каждое правило В32 со списком экранов как параметром; сериализация туда и обратно; TypeScript-типы без расхождений (`bun run bindings:check`).
- `SpaceHost`: две вкладки одного пространства получают одно `OpenSpace`; последняя аренда закрывает его через `SPACE_RELEASE_GRACE_MS`; аренда в этот промежуток получает прежнее и продолжает сессию ожиданий; идущая работа держит пространство после закрытия вкладок; недоступность одного пространства не трогает другое (П25); выбор во вкладке A не отменяет выбор во вкладке B; наблюдение за корнем живёт, пока живо `OpenSpace`.
- Вкладки одного пространства: каждая команда изменения шлёт `vault-changed` остальным вкладкам пространства и не шлёт вызвавшей; перечень `commands/effects.rs` покрывает все команды; переименования доходят в `renames`.
- Адресация: команда из вкладки A не читает и не пишет пространство B; получатели каждой группы В21 (чистая функция от `TabRegistry`); `app.emit` только для событий без пространства.
- Ведущая вкладка: одна на пространство, только видимая, смена роли при переключении вкладок и окон, работа ждёт без ведущей, закрытое уведомление не возвращается.
- Модель векторов: два пространства ищут одновременно; поиск обгоняет фоновый прогрев; ожидание дольше `EMBEDDING_MODEL_WAIT_MS` даёт ответ без смыслового слоя.
- `WindowStore`: атомарная запись, `windows.corrupt.json`, `windows.v<версия>.json`, задержка записи, состояние выхода, закрытие последнего окна, отмена перетаскивания при выходе.
- Перенос: ошибка переноса пересоздаёт вкладку в исходном окне.
- Политика памяти: предел, выгрузка давно не выбранной, видимые не выгружаются, сигнал нехватки памяти.
- Раскладка окна: рамки полосы и вкладок по размеру окна и в полноэкранном режиме.
- `vault_path` пишется только при смене пространства видимой вкладки последнего окна; MCP держит закреплённое пространство.

Интерфейс (Vitest):

- Полоса: ширины вкладок, прокрутка к видимой, ширины после закрытия под указателем, клавиатура, порог перетаскивания, порядок после перестановки, Escape.
- Вкладка: восстановление по `TabView` с проверками В18, отчёт с задержкой, раскладка бокового меню окна, пауза медиа при скрытии, нет сверки при показе вкладки.
- `TAB_BAR_HEIGHT_PX` совпадает с токенами хрома в `global.css`.
- `RESERVED` содержит сочетания вкладок; переназначения на них снимаются.
- Линтер: общий `listen`, `getCurrentWindow` и `getCurrentWebviewWindow` в коде вкладок и полосы.

Нативная проверка (`bun run test:native-shell`, отдельная папка данных по В34):

- Две вкладки с разными пространствами: каждая видит только свои карточки и события.
- Две вкладки одного пространства: удаление коллекции в одной переводит другую на Everything.
- Память: значение в памяти вкладки A не видно вкладке B и переживает перенос вкладки в другое окно без перезагрузки.
- Права после переноса: команды из перенесённой вкладки проходят.
- Ввод в дочерней странице: стрелки в поле не вставляют символы с U+001C по U+001F (tauri #10194), символ не удваивается (tauri #8705).
- Скрытая вкладка: `visibilityState = hidden`, медиа на паузе.
- Перезапуск возвращает окна, их порядок, видимые вкладки и `TabView`.

Живая приёмка Т1 по Т6 за пользователем в установленном приложении.

## Риски

- Дочерние страницы Tauri помечены `unstable`: их API может меняться между версиями, поэтому каждое обновление Tauri повторяет пробу Э0.
- На macOS открыты ошибки ввода в дочерних страницах (tauri #10194, #8705). Если Э0 их подтвердит, защита в странице нужна до Э2.
- При живом изменении размера окна содержимое вкладки отстаёт от рамки: WebKit рисует асинхронно (WebKit PR 72971 не влит).
- Создание дочерней страницы активирует приложение (исправление wry #1866 ещё не выпущено): окна, восстановленные после запуска, могут вывести Mine вперёд, если пользователь уже переключился в другое приложение.
- На macOS 26.3 открыто падение при закрытии второго окна (wry #1730).
