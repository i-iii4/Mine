## Цель

Довести человека от «скачал» до «вижу в ленте свои карточки», не требуя ни
терминала, ни чтения инструкций. Каждое требование ниже описывает наблюдаемое
поведение, а не реализацию.

Язык интерфейса — английский, включая все новые тексты онбординга.

## Точка входа — расширение, а не приложение

Целевая публикация в Chrome Web Store — **открытая**, доступная поиском;
сейчас такой публикации нет, используется unpacked development-сборка.
Человек может поставить расширение раньше приложения, поэтому расширение
обязано быть самостоятельным.

**О1.** Расширение сохраняет карточки в папку на диске **без установленного
приложения**.

Кнопка `Choose folder…` в оверлее отправляет `openStandaloneSetup` в background,
который открывает `dist/index.html?mode=setup` на origin расширения. Оверлей
остаётся смонтированным с открытым клипом; страница настройки не извлекается
как новый клип. После выбора и проверки разрешения background уведомляет
открытые интерфейсы, а `Return to clip` закрывает окно настройки.

Хэндл и непрозрачная привязка папки хранятся в IndexedDB. Права запрашиваются
по пользовательскому жесту и проверяются перед записью. `Allow access`
восстанавливает разрешение; для незавершённой операции открывается
`?mode=setup&binding_id=…` с исходным хэндлом, без замены папки.
Документы, имена и раскладку определяет Rust/WASM `mine-core`, а браузерный
исполнитель делает файловый ввод-вывод. Отсутствие File System Access
no-clobber/OS-flush гарантий не скрывается и не исправляется компиляцией в WASM;
барьер реальной файловой проверки описан в [SPEC_SAVE_CORE.md](SPEC_SAVE_CORE.md).

**О2.** Расширение определяет доступность совместимого связующего компонента
и отдельно состояние выбранной папки. Факт скачивания приложения оно не
определяет; отсутствие ответа не означает «Mine не установлен».

`get_status` отвечает `ok:true, connected:true`, даже когда папки нет.
Отдельные поля `vaultConfigured`, `folder_state`, `binding_id` и `error`
отличают отсутствие выбора, исчезнувшую папку и отказ доступа. UI требует
`save_operation_v1` и `operation_lookup_v1`; несовместимый компонент получает
сообщение об обновлении, не новую команду сохранения неизвестного формата.

Экран настройки предлагает `Choose folder…`, а при утрате разрешения —
`Allow access`; `Get the Mine app (optional)` остаётся необязательной ссылкой.
Диагностика подключения и `Retry connection` видимы здесь же. Требование
17.08.2026 сделать загрузку приложения primary заменено этим потоком
восстановления; отсутствие ответа не используется как диагноз установки.

**О3.** Меню отражает проверенные возможности. `Open app` доступно, когда
связующий компонент поддерживает открытие приложения; при проблеме связи
доступны диагностика и повтор проверки. Если компонент ещё не зарегистрирован,
инструкция предлагает один раз открыть Mine. `Download app` — предложение
установки, не диагноз и не замена восстановлению доступа к папке.

`Open app` появляется только после объявления `open_app_v1` в успешном
handshake. Ошибка открытия остаётся видимой в меню. В браузерном режиме
надпись `browser` обозначает исполнителя, а не делает вывод «приложения нет».

**О4.** Формат и сценарий сохранения едины. Перед новой операцией выбираются
конкретное пространство и доступный исполнитель; совместимый native можно
использовать только для подтверждённой привязки к той же папке. Без Mine
пишет браузерный исполнитель. Само появление компонента не меняет папку.

Выбранный исполнитель сохраняется в `mineSaveDestination`. Появление Mine
не заменяет браузерную папку, а отказ ранее выбранного native-пути не включает
скрытый fallback. `Choose folder with Mine…` — явный системный выбор, не
сопоставление по отображаемому имени. Browser binding проверяется
`isSameEntry`, native binding — canonical path; одинаковый `vault-id` у копий
или одинаковое имя не доказывают идентичность папки. Запоздалый ответ о старой
папке не отменяет новый выбор: UI проверяет поколение запроса.

До отправки Save UI сохраняет `operation_id`, `sourceUrl`, payload,
исполнителя и исходную привязку в `chrome.storage.local`. После потери ответа
кнопка `Check save outcome` проверяет ту же операцию. `unknown`, конфликт
привязки или содержимого не разрешают другой ID/папку. Повторное исполнение
допустимо только после `not_committed, resumable:true`; разморозить клип
после отказа можно только по сохранённому `terminal_rejected:true`, который
доказывает отсутствие побочных записей.

Другой клип с тем же URL не подхватывает чужой результат: показывается
отдельная карточка исходного клипа с `Check previous save`. Проверка старой
операции не отмечает новый клип сохранённым; `This is a different clip`
явно разрешает новую операцию. Повреждённый payload при сохранившихся
идентификаторе и привязке остаётся доступным для проверки исхода.
SQLite и превью обновляются после исходников и не являются условием commit.

Работа при закрытом Mine уже поддерживается; это не новая возможность.
Осознанные ограничения автономного режима сохраняются: inline-картинки могут
остаться удалёнными, защищённое видео без нативной утилиты — без скачанного
файла. UI не выдаёт такую ссылку за локально сохранённое медиа. Одинаковый
формат не означает одинаковую атомарность файловых API — см. барьер SC0.

**О5.** Первый запуск Mine настраивает поставляемый связующий компонент для
поддерживаемых браузеров без терминала и ручного extension ID. Стабильные
production/dev ID и точные разрешённые origin задаются поставкой. Скачивание
или копирование приложения без первого запуска этого ещё не делает.

После первого интерактивного кадра startup maintenance устанавливает
отсутствующий host и восстанавливает точные manifests обнаруженных
Chromium-браузеров. Текущий синхронный вызов `refresh_installed_host` в Tauri
`.setup` должен быть перенесён по `SPEC_STARTUP_PERFORMANCE.md`; до реализации
это известное несоответствие принятому startup-контракту.
Ключ `extension/manifest.json` фиксирует development ID
`eioalidaccoahofcggkbinalibpajokh`; только его origin входит в allowlist.
Та же поставка атомарно обновляет runtime расширения в стабильном каталоге
`~/Library/Application Support/com.mine.app/clipper/extension`. Браузер один
раз подключает через `Load unpacked` этот каталог, а не checkout и не build
output. Обновление приложения или developer installer заменяет содержимое
каталога целиком, сохраняя путь и ID; перенос или удаление репозитория больше
не влияет на регистрацию браузера. Исходники, тесты и старые runtime-файлы в
установленную копию не попадают.
Помощник и копию расширения Mine держит в актуальном виде сам всё время
работы, а не только при запуске (решение пользователя 30.09.2026). После
первого интерактивного кадра, затем раз в 5 минут и при возврате в окно Mine
(не чаще раза в 30 секунд) он сверяет установленный помощник и копию
расширения с поставкой байт в байт, а регистрацию помощника с каждым
найденным браузером. При расхождении ставит всё заново тем же путём, что и
первый запуск; после неудачи повторяет через минуту. Так новый браузер,
подменённый или повреждённый помощник и сорвавшаяся установка чинятся без
действий человека. Кнопок починки и проверки в интерфейсе нет. Сборка без
помощника в поставке проверку не запускает: чинить нечем.
Production ID пока не назначен. Диагностический `MINE_NATIVE_SMOKE` не
регистрирует браузеры и не заменяет пользовательский host.

Если для пространства уже есть локальный derived-индекс, первый экран
читает его сразу, а freshness-reconcile идёт в фоне. Ожидание полного
обхода файлов до первой отрисовки допустимо только когда готового
снимка нет: первая индексация нового пространства или незавершённая
миграция. Переключение между уже индексированными папками не может
показывать пустой экран из-за фоновой сверки.

**О6.** Приложение сверяет версию установленного связующего звена со своей.

Приложение сравнивает SHA-256 байтов поставленного и установленного host,
проверяет исполняемый файл и заменяет его через подготовленный временный
inode с правами `0755`, `fsync` и atomic rename. Отметка версии сама по себе
не подтверждает актуальность. Совместимость протокола проверяет расширение
по capabilities; установка host не удаляет журналы сохранений.

**О7.** Статус связи в настройках снят 30.09.2026 решением пользователя:
человеку не нужен экран о помощнике, если помощник чинится сам (О5), а о
сбое связи говорит клиппер в момент сохранения ([SPEC_CLIPPER.md](SPEC_CLIPPER.md),
таблица ошибок). Запись последней подтверждённой проверки остаётся на диске
для разбора сбоев. После успешного `get_status` расширение
при capability `connection_check_v1` отдельно отправляет
`confirm_connection_check`; сам `get_status` остаётся read-only. Native host
проверяет точный extension origin из аргумента запуска и сохраняет одну
последнюю подтверждённую проверку в app-local
`clipper/last-connection-check.json`, вне пользовательской папки.
Время задаёт host (ISO в записи), версия и API берутся из работающего host,
не из запроса. Ошибка этой необязательной диагностики не меняет результат
handshake или Save.

Разрешения расширения остаются в текущем виде: переход на внедрение по клику
не делаем.

### Переход со старого unpacked ID

Новый ключ меняет origin старой установки без закреплённого ID. Данные
`chrome.storage.local`, IndexedDB-привязки папок и browser receipts не
переносятся между этими origin автоматически. До выяснения исхода старых
pending-операций нельзя удалять старую установку или сбрасывать её storage;
удаление расширения очищает `storage.local`. Проверка старых pending нужна
**до первого запуска новой `.app`, Repair registration или developer installer**:
они заменяют allowlist новым ID. При unknown нельзя менять прежние расширение,
host и регистрацию; открытый native port не гарантирует новое подключение.
Это контролируемый dev-переход, не автоматическая миграция. Новая установка
снова запрашивает доступ к папке; это не повод заново создавать старые клипы.
Основание: [manifest key](https://developer.chrome.com/docs/extensions/reference/manifest/key),
[extension storage](https://developer.chrome.com/docs/extensions/reference/api/storage),
[origin-scoped IndexedDB](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies).

## Утилита для видео

**О8.** `yt-dlp` поставляется внутри приложения.

Сделано 15.08.2026. Бинарник скачивается при сборке (закреплённая версия) и
попадает в бандл ресурсом; при установке связующего звена копируется рядом с
ним, потому что браузер запускает звено из каталога пользователя. Поиск
утилиты начинается с собственного каталога и только потом идёт по системным
путям, так что явная установка через менеджер пакетов по-прежнему побеждает.

## Первый запуск приложения

**О9.** Первый экран говорит одну строку и даёт одну кнопку.

Сделано 15.08.2026 тремя тезисами о модели продукта; пересмотрено 01.10.2026
по решению пользователя: тезисы не помогали сделать шаг, а три размера
шрифта и выравнивание по центру выбивались из интерфейса. Теперь одна строка
`Mine keeps your cards as files in a folder.` размера `text-sm` и кнопка
`Choose folder`, всё по левому краю в колонке шириной 320 px по центру окна.

**О10.** Два явных действия вместо одного: `Create new space` создаёт папку
сама, предлагая расположение по умолчанию; `Open existing folder` открывает
системный выбор. Человек, который просто хочет попробовать, не должен
придумывать и создавать папку сам.

**О11.** При отказе в доступе к папке показывается экран «нет доступа к папке»
со ссылкой в системные настройки, а не пустая лента. Строку перед системным
запросом о том, что спросит macOS, сняли 01.10.2026 вместе с тезисами О9:
системный запрос объясняет себя сам и бывает не для каждой папки.

Сделано полностью 17.08.2026. Привязанное пространство проверяется чтением
каталога — той самой операцией, которую приложение собирается выполнить:
папка читается — открываемся; папки нет — `Folder unavailable` с поиском
папки; папка есть, но чтение запрещено — отдельный экран «No access to the
folder» с кнопкой в System Settings (Privacy & Security, Files and Folders) и
повтором. «Найдите папку» — бесполезный совет, когда папка на месте и
заблокирована.

**О12.** Выбранная папка открывается сразу, без подтверждения.

Подтверждение непустой папки (сделано 15.08.2026) снято 01.10.2026 по
решению пользователя: выбор в системном окне уже и есть решение, а для
готового пространства Mine шаг был пустым. Защиту от случайной папки даёт
уведомление о первой индексации (О13): оно показывает, сколько в папке
заметок, и, пока лента пуста, предлагает `Choose another folder`. Команда
подсчёта папки `preview_vault_folder` удалена.

**О13.** Первичная индексация показывает прогресс с числами обработанного, а
не бесконечный индикатор.

Сделано 16.08.2026. Индексатор сообщает `(обработано, всего)` по инвентарю
markdown-файлов; событие `vault-sync-progress` уходит на первый файл, каждый
25-й и последний. С 01.10.2026 его шлёт и первое построение индекса, которого
ждёт лента при открытии новой папки (раньше оно молчало, и лента стояла
пустой с одной надписью `Syncing…`).

С 01.10.2026 по решению пользователя числа показываются уведомлением в правом
нижнем углу (`NotificationCard`): заголовок `Indexing “<папка>”`, полоса и счёт
`обработано / всего`, кнопка закрытия скрывает его до конца прохода. Оно
появляется, только если проход идёт дольше 1 с, иначе мигало бы после каждого
сохранённого файла. Пока лента пуста, в нём есть `Choose another folder` (О12).
Счётчик посреди ленты и надпись `Syncing…` в нижней панели сняты. Пока идёт
индексация, онбординг пустого пространства не показывается: «пространство
пусто» было бы неправдой. Полоса не рисует дальше конца и не делит на ноль.

С 03.10.2026 пространство может быть открыто в нескольких вкладках, а
уведомление принадлежит пространству ([SPEC_TABS.md](SPEC_TABS.md), В19, В20).
Его показывает только ведущая вкладка пространства: видимая вкладка этого
пространства, а если таких несколько, та, чьё окно было в фокусе позже
других. Скрытая вкладка ведущей не бывает; пока видимой вкладки пространства
нет, уведомление не показывается. Смену роли бэкенд сообщает вкладке событием
`space-lead-changed`. Закрытие уведомления запоминается для этого открытия
пространства: вкладка зовёт `dismiss_space_notice("indexing")`, а `OpenSpace`
хранит отметку, пока пространство открыто. Вкладка, ставшая ведущей,
спрашивает `space_notice_dismissed("indexing")` и закрытое уведомление снова
не показывает. Ошибки индексации и чтения ленты остаются ошибками своей
вкладки и показываются там, где случились.

С 01.10.2026 то же уведомление ведёт и вторую фазу открытия, подготовку превью.
Полный проход превью шлёт `derived-preview-progress {path, processed, total}`,
где `total` равно числу карточек, которые он проверяет: при старте, на первой
карточке, затем каждые 10 карточек или 250 мс (что раньше) и на последней.
Карточка, чьё медиа только в iCloud, засчитывается после загрузки. Постановку
полного прохода в очередь сообщает `derived-preview-queued` (раньше
`vault-sync-finished`, поэтому между фазами нет промежутка), конец всех полных
проходов, в том числе отменённого сменой пространства, сообщает
`derived-preview-finished`. Проходы по отдельным карточкам после сохранения
файла молчат. Карточка в углу одна: сначала `Indexing “<папка>”`, затем
`Preparing previews` со своим счётом (пока проход считает карточки, полоса без
чисел). Задержка в 1 с и скрытие относятся ко всему открытию: появившееся
уведомление не пропадает между фазами, скрытое не возвращается до конца обеих.

## Пустая лента

**О14.** Пустое пространство никогда не выглядит просто пустым.

Сделано 15.08.2026, уточнено 16.08.2026. Два пути наполнения: установка

## Момент ценности

**О19.** После первой в пространстве сохранённой карточки — одноразовая
пометка о том, что карточка лежит файлом в выбранной папке, с действием
`Reveal in Finder`.

Сделано 17.08.2026. Показывается, когда карточка добавилась в пустую ленту и
пометка в этом пространстве ещё не показывалась; отметка о показе — сайдкар в
derived-хранилище, как у рекомендации Keep Downloaded. В тексте — имя файла,
чтобы «файл» был конкретным; Reveal in Finder открывает именно его.

С 03.10.2026 пометку ставит и показывает только ведущая вкладка пространства
(видимая, а из нескольких видимых та, чьё окно было в фокусе последним;
[SPEC_TABS.md](SPEC_TABS.md), В19): одна пометка на пространство, а не по
одной на каждую вкладку с пустой лентой. Вкладка, которая не ведёт
пространство, новую карточку получает как обычное изменение.
