## Цель

Довести человека от «скачал» до «вижу в ленте свои карточки», не требуя ни
терминала, ни чтения инструкций. Каждое требование ниже описывает наблюдаемое
поведение, а не реализацию.

Язык интерфейса — английский, включая все новые тексты онбординга.

## Точка входа — расширение, а не приложение

Расширение публикуется в Chrome Web Store **открыто**, доступно поиском.
Это меняет порядок знакомства: человек чаще ставит расширение первым и только
потом узнаёт про приложение. Расширение обязано быть самостоятельным.

**О1.** Расширение сохраняет карточки в папку на диске **без установленного
приложения**.

Первичная реализация существует с 16.08.2026: фоновой worker пишет через
File System Access, хэндл папки хранится в IndexedDB. Выбор из оверлея
сознательно запрещён, чтобы разрешение не принадлежало домену страницы.
Подтверждён дефект: совет нажать иконку на обычной странице возвращает в тот
же оверлей. Также JS-формат разошёлся с Rust; копии тестов этого не обнаружили.

Цель SC3–SC4: доступное действие открывает отдельную страницу/окно расширения,
сохраняет черновик и возвращает к нему после выбора папки. Разрешение
запрашивается по пользовательскому жесту и проверяется повторно; его нельзя
считать бессрочным. Файлы формирует общее ядро, браузерный исполнитель
сохраняет их по контракту SC0. Автономная приёмка — Chrome и Dia; Safari
по-прежнему не входит в первую раскатку.

**О2.** Расширение определяет доступность совместимого связующего компонента
и отдельно состояние выбранной папки. Факт скачивания приложения оно не
определяет; отсутствие ответа не означает «Mine не установлен».

Целевой контракт SC4: соединение, совместимость протокола и разрешение на
папку — независимые состояния. Ответ работающего компонента без настроенного
пространства ведёт к выбору папки. Ошибка запуска/регистрации/версии ведёт к
соответствующему восстановлению, а не к обязательной загрузке приложения.

В текущей реализации эти состояния смешаны: неуспешный `get_status` без
доступной автономной папки показывает экран установки. Это дефект, не
сохраняемое продуктовое правило.

Уточнение 17.08.2026: на экране настройки primary — `Download app`, потому что
первая ценность продукта (лента с превью) живёт в приложении и активация идёт
через него; `Choose folder…` — полноценный второй путь рядом (secondary).
Исключение — потерянный доступ к уже выбранной папке: там человек уже
сохраняет автономно, и primary — `Allow access`, восстановление его потока.

**О3.** Меню отражает проверенные возможности. `Open app` доступно, когда
связующий компонент поддерживает открытие приложения; при проблеме связи
доступны диагностика и повтор проверки. Если компонент ещё не зарегистрирован,
инструкция предлагает один раз открыть Mine. `Download app` — предложение
установки, не диагноз и не замена восстановлению доступа к папке.

Действие `open_app` и ссылка на релизы существуют с 16.08.2026. Целевая
маршрутизация меню ещё не реализована: SC4 заменит нынешнюю догадку
«установлено/не установлено» на подтверждённое состояние соединения.

**О4.** Формат и сценарий сохранения едины. Перед новой операцией выбираются
конкретное пространство и доступный исполнитель; совместимый native можно
использовать только для подтверждённой привязки к той же папке. Без Mine
пишет браузерный исполнитель. Само появление компонента не меняет папку.

Установка Mine после автономных сохранений предлагает подключить уже
используемую папку. Совпадение отображаемых имён не доказывает совпадения
папок; если его нельзя установить, требуется явный выбор пользователем.
Таймаут не запускает альтернативное сохранение: сначала проверяется исход
той же операции. SQLite и превью обновляются после исходников и не являются
условием успешного commit. Целевой переход — SC1–SC4.

Работа при закрытом Mine уже поддерживается; это не новая возможность.
Осознанные ограничения автономного режима сохраняются: inline-картинки могут
остаться удалёнными, защищённое видео без нативной утилиты — без скачанного
файла. UI не выдаёт такую ссылку за локально сохранённое медиа. Одинаковый
формат не означает одинаковую атомарность файловых API — см. барьер SC0.

**О5.** Первый запуск Mine настраивает поставляемый связующий компонент для
поддерживаемых браузеров без терминала и ручного extension ID. Стабильные
production/dev ID и точные разрешённые origin задаются поставкой. Скачивание
или копирование приложения без первого запуска этого ещё не делает.

Текущее поведение: установка кнопкой в настройках и ввод ID вручную;
при запуске приложения обновляется только ранее установленный бинарник.
Первичная регистрация и её восстановление — запланированная работа SC4,
а не уже работающая автоматизация.

**О6.** Приложение сверяет версию установленного связующего звена со своей.

Текущая проверка использует отметку версии рядом с бинарником. Цель SC4:
проверять также совместимость протокола и требуемых возможностей; версия
приложения, версия протокола и наличие файла — не один и тот же факт.
Обновление не теряет незавершённые операции и не отправляет новому/старому
компоненту неподдерживаемые команды.

**О7.** В настройках виден статус связи.

Целевой статус SC4 различает установленный бинарник, регистрацию браузера и
подтверждённый обмен с компонентом. Для результата обмена видна актуальность;
без него можно показывать «зарегистрировано», но не «соединение работает».
Существование файла манифеста сейчас используется как признак подключения —
это недостаточная проверка и подлежит замене.

Разрешения расширения остаются в текущем виде: переход на внедрение по клику
не делаем.

## Утилита для видео

**О8.** `yt-dlp` поставляется внутри приложения.

Сделано 15.08.2026. Бинарник скачивается при сборке (закреплённая версия) и
попадает в бандл ресурсом; при установке связующего звена копируется рядом с
ним, потому что браузер запускает звено из каталога пользователя. Поиск
утилиты начинается с собственного каталога и только потом идёт по системным
путям, так что явная установка через менеджер пакетов по-прежнему побеждает.

## Первый запуск приложения

**О9.** Первый экран объясняет модель продукта тремя короткими тезисами.

Сделано 15.08.2026.

**О10.** Два явных действия вместо одного: `Create new space` создаёт папку
сама, предлагая расположение по умолчанию; `Open existing folder` открывает
системный выбор. Человек, который просто хочет попробовать, не должен
придумывать и создавать папку сам.

**О11.** Перед системным запросом доступа к папке — одна строка о том, что
сейчас спросит macOS и зачем. При отказе — экран «нет доступа к папке» со
ссылкой в системные настройки, а не пустая лента.

Сделано полностью 17.08.2026. Привязанное пространство проверяется чтением
каталога — той самой операцией, которую приложение собирается выполнить:
папка читается — открываемся; папки нет — `Folder unavailable` с поиском
папки; папка есть, но чтение запрещено — отдельный экран «No access to the
folder» с кнопкой в System Settings (Privacy & Security, Files and Folders) и
повтором. «Найдите папку» — бесполезный совет, когда папка на месте и
заблокирована.

**О12.** Если выбранная папка не пуста, показывается подтверждение с фактами
до начала работы.

Сделано 15.08.2026. Подсчёт идёт без изменения файлов и ограничен по глубине,
чтобы само подтверждение не тормозило. Пустая папка открывается сразу.

**О13.** Первичная индексация показывает прогресс с числами обработанного, а
не бесконечный индикатор.

Сделано 16.08.2026. Индексатор сообщает `(обработано, всего)` по инвентарю
markdown-файлов; поток синхронизации шлёт событие каждый 25-й файл и последний.
Числа с тонкой полосой показываются в области ленты вместо онбординга пустого
пространства — «пространство пусто» было бы неправдой о пространстве, которое
ещё читается. Полоса не рисует дальше конца и не делит на ноль.

## Пустая лента

**О14.** Пустое пространство никогда не выглядит просто пустым.

Сделано 15.08.2026, уточнено 16.08.2026. Два пути наполнения: установка
расширения (ведёт в настройки) и перетаскивание файлов; третий путь — импорт из
Are.na — отменён вместе с импортом. Состояние показывается только на маршруте
Everything: пустая коллекция — это фильтр, который ничего не нашёл, и у неё
свой текст.

**О15.** Состояние исчезает с появлением первой карточки и больше не
возвращается.

**О16.** Точка входа для установки остаётся в настройках постоянно — раздел
`Extension` с шагами установки и статусом связи, для второго браузера или
второй машины.

## Импорт из Are.na

**О17.** Отменено 16.08.2026: импорт Are.na не входит в эту версию, без
обещаний на будущее. Вход из онбординга убран, код диалога спит без точки
входа — ровно так он жил до 15.08.2026.

**О18.** Снято 16.08.2026 вместе с отменой импорта (О17).
## Момент ценности

**О19.** После первой в пространстве сохранённой карточки — одноразовая
пометка о том, что карточка лежит файлом в выбранной папке, с действием
`Reveal in Finder`.

Сделано 17.08.2026. Показывается, когда карточка добавилась в пустую ленту и
пометка в этом пространстве ещё не показывалась; отметка о показе — сайдкар в
derived-хранилище, как у рекомендации Keep Downloaded. В тексте — имя файла,
чтобы «файл» был конкретным; Reveal in Finder открывает именно его.

## Чего не делаем

- Не переводим интерфейс на русский.
- Не переходим на внедрение скриптов по клику.
- Не включаем Safari в первую раскатку.
