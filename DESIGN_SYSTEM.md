# Дизайн-система Mine

Токены определены в `src/styles/global.css` → `@theme inline`.
Tailwind v4 генерирует утилиты автоматически из `--radius-*`, `--spacing-*`, `--text-*`.

## Словарь сущностей (UI-нейминг)

Три уровня иерархии, сквозные термины во **всех** пользовательских строках —
меню, кнопки, плейсхолдеры, диалоги, тултипы, нативное меню macOS, расширение браузера:

| Уровень | Термин в UI | Что это (внутреннее имя в коде) |
|---|---|---|
| 1 | **Space** | vault — корневая папка пользователя |
| 2 | **Collection** | channel/tag — Obsidian-страница коллекции |
| 3 | **Element** | block/card — карточка контента |

Старые UI-термины `card(s)`, `channel(s)`, `vault` запрещены в видимых
строках. Внутренние имена кода (типы, команды, маршруты `/channel/:tag`,
frontmatter `type: channel`, `Mine Collections`) **не** переименовываются —
словарь касается только слоя, который читает пользователь. Примеры:
`Search elements`, `New Collection`, `Find Elements` (нативное меню),
`Connected elements`, `Delete element?`, `Save to 1 collection` (расширение),
`Select Space`.

Развод имён поиска: поле над списком коллекций называется `Find or create`
(подсказка `Find or create...`, подпись для диктора `Find or create
collection`): оно фильтрует строки, а Enter открывает коллекцию с набранным
именем или создаёт её (решение пользователя 05.10.2026, раньше `Filter
collections`); `Search
collections` зарезервировано за поиском в выпадающем переключателе коллекций;
`Search elements` — глобальный поиск элементов (`Cmd+F`).

## Скругления

| Токен | Значение | Утилита | Где |
|---|---|---|---|
| `--radius-0` | 0 | `rounded-0` | Карточки контента, изображения, текстовые блоки |
| `--radius-1` | 3px | `rounded-1` | Основные элементы интерфейса: кнопки, инпуты, попапы, меню, тултипы, диалоги |
| — | 2px | `rounded-[2px]` | Чекбоксы (16px, компенсация масштаба) |
| `--radius-pill` | 9999px | `rounded-pill` | Переключатели, тоглы, прогресс-бар |
| `--radius-round` | 50% | `rounded-round` | Аватары, индикаторы статуса |

**Правило:** содержимое без скругления (`rounded-0`), интерфейс 3px (`rounded-1`), бейджи и pill-контролы капсулами (`rounded-pill`), чекбоксы 2px.

### Скругление карточек — настройка

Appearance → `Card corners`: `Square` (по умолчанию) или `4` пикселя (решение пользователя 06.10.2026, до этого `3`, как у интерфейса). Сохранённое прежнее значение `3` читается как `4`.

Область действия выбрана намеренно:

| Поверхность | Скругление |
|---|---|
| Рамка карточки | по настройке |
| Медиа сверху в карточке с рамкой (SPEC_FEED_DISPLAY.md, Д20) | видимые углы медиа это внутренние углы линии над ним: сверху линии рамки, снизу обводки, низ зеркалит верх; обрезка медиа по середине линии (`--card-frame-line-radius`); стыки сетки прямые; медиа с текстом под ним закрыто обводкой, отражением линии рамки |
| Изображение в развёрнутой карточке | по настройке |
| Карточка метаданных в просмотре статьи | по настройке |

Внутри карточки с контентом одиночное медиа или вся сетка имеют один общий
контур: скругление и обрезку держит общий слот `GraphicSurface`, а не
отдельные плитки. Внутренние стыки сетки остаются прямыми при любом числе
плиток, шов между плитками 1px (`gap-px`) цвета фона карточки. Это относится и
к видео и постерам. Одиночное открытое изображение берёт тот же угол, что и
рамка карточки.

Технически настройка переопределяет только `--radius-card`. Общий слот медиа
читает этот токен; отдельные плитки используют нулевой `--radius-media`. Изображения развёрнутой карточки читают
`--radius-card` через правило по `[data-detail-article-column]`.
Карточка с датой, источником и автором также читает `--radius-card`.

`Square` не выставляет `0px`, а снимает переопределение — значение по умолчанию
остаётся за таблицей токенов.

## Верхние ряды

С 03.10.2026 по решению пользователя интерфейс один: прежняя версия 2 стала
единственной, версия 1 и переключатель версий в меню логотипа удалены вместе с
`src/lib/uiVersion.ts` и атрибутом `data-ui-version`.

- **Третьего ряда нет.** Его половина над лентой (`Grid / Graph`, `Display`,
  при открытой карточке её название, меню и закрытие) стоит во втором ряду
  после переключателя коллекции (`MainSecondaryTopBar part="content"`), лента
  начинается сразу под вторым рядом. Над таблицей третьего ряда тоже нет:
  числа коллекций нет, индикаторы загрузки и индексации и `+` новой коллекции
  стоят справа в ряду поля `Find collections` (`data-sidebar-top-search-actions`).
  В раскладке с рядом метаданных внизу окна всё это остаётся в нём.
- **Вид справа, без счётчика.** Числа элементов и подписи `View:` нет.
  `Grid / Graph` стоит у правого края рядом с `Display`, пилюлей на
  постоянной подложке («Пилюля»).
- **Путь.** `Mine › Everything › карточка`: внешнее поле `8px` у подсветки
  стоит только со стороны границы (край окна, линия колонки), между соседними
  подсветками его нет (`joinsNext`, `joinsPrevious`). От стрелки до следующего
  имени около `16px` на глаз. Название открытой карточки идёт по общему
  правилу видимого заголовка (`getNavigationLabel`), без папки и расширения, и
  подсвечивается при наведении, как соседние звенья.
- **Свёрнутое боковое меню.** Линии между `Mine` и `Everything` нет, они
  соседи по правилу пути.
- **Высота хрома у каждого окна своя** (SPEC_TABS.md, В83): меню логотипа
  предлагает `Chrome Height 30` и `Chrome Height 40`, полоса вкладок и верхние
  ряды страницы ходят вместе. По умолчанию 40 (решение пользователя
  07.10.2026); окно с записанными высотами сохраняет свои. Вариант с полосой
  30 над страницей 40 убран 07.10.2026, сохранённое с ним окно читается как
  высокое. Высокий ряд вместе с линией шагает как строка таблицы бокового
  меню (`--sidebar-row-height`, 40 px), высота стоит с первого кадра. Нижняя
  панель свою высоту не меняет.
- **Полноэкранный режим.** Резерва светофоров в полосе вкладок нет.
- **Нижняя панель моноширинная.** Названия команд и сочетания клавиш набраны
  системным моноширинным шрифтом (SF Mono) того же размера, `12px`, поэтому
  высота панели прежняя. При шрифте интерфейса Departure Mono панель остаётся
  на нём.

## Варианты оформления

Действующий вариант только Alt 1. При запуске старые значения `Default` и
`Alt 2` приводятся к Alt 1. Шрифт интерфейса и шрифт статьи только системные
(решение пользователя 06.10.2026). Доступные отступы: 32, 24 и 16 пикселей. Сохранённое
значение 2 пикселя читается как 16. Нижняя панель использует только стандартные
кнопки. Переключатели этих вариантов удалены из настроек.

Следующее описание нескольких вариантов сохранено как история проектирования.

Appearance → `Design`: `Default` / `Alt 1` / `Alt 2`. Ось ортогональна теме:
любой вариант сочетается с любой темой, значения хранятся раздельно
(`mine.design` и `theme`). Основной вариант не несёт атрибута вовсе,
альтернативные ставят на корень `data-design="alt"` / `data-design="alt2"` —
таблицы стилей отвечают на атрибут, а раскладка, считаемая в JS (masonry,
ширины колонки боковой панели), читает то же значение через `useDesignMode`.
Неизвестное сохранённое значение сводится к основному варианту: атрибут, на
который не отвечает ни одно правило, — это поломанный интерфейс, а не вариант.

**Что вариант имеет право менять.** Метрики раскладки. Цвета следуют системной
схеме и остаются общими — вариант, который переопределяет палитру, перестаёт
быть раскладкой и становится второй темой, а тема у нас уже есть.

### Alt 1 — таблица заподлицо

Боковая панель отдаёт внешние отступы таблицы (`--sidebar-nav-pad-x`,
`--sidebar-nav-pad-top` → `0`) и переносит отступ внутрь строки
(`--sidebar-row-pad-x: 16px`). Зона строки растёт с `100` до `104`, минимальная
ширина панели — с `366` до `314` (см. «Строка боковой панели: три зоны»).

Из-за фиксированных `16` внутри строки центральная настройка плотности
перестаёт управлять этой колонкой: край хрома описан отдельным именем
`--chrome-edge-pad`. С 07.10.2026 оно равно `8px` во всех вариантах (решение
пользователя: прежние `16px` остались от хрома высотой 32 и для текущего не
нужны; эталон это отступ кнопок карточки `Card actions` и `Connect` от её
края) и отвязано от ритма ленты целиком: от границы (край окна, линия колонки,
линия вкладки, край панели) до подсветки первой кнопки или до текста, если в
ряду нет кнопки. На него опираются верхние ряды, полоса вкладок, нижняя
панель, ряд выделения и верхняя панель развёрнутой карточки. Причина отвязки
та же: шаг ленты `2px`, оболочка не должна схлопываться вместе с плотностью
карточек.

### Строка боковой панели: три зоны (26.08.2026)

Строка читается как три части: имя, превью, счётчик. **Единица модели — зона,
а не бокс колонки.** Зона — расстояние между двумя разделителями или между
разделителем и краем панели: именно его сравнивает глаз. Отступ строки
принадлежит зоне имени, пиксели разделителей и зазоры вокруг миниатюр —
соседним зонам, поэтому равные боксы дают неравные зоны.

**Ширина зоны** = `max(отступ строки + краеугольные 88, поле кнопки действия)`
(`appLayout.ts` → `sidebarZoneWidth`). Краеугольные `88` — это 2,5 превью
(32 + 4 + 32 + 4 + 16), минимум, при котором полоса миниатюр ещё читается.
Поле кнопки — `8 + минимальная ширина 84 + 8`. Основной вариант: `100`;
Alt 1 и Alt 2: `104`.

Connect / Connected / Disconnect занимают одну плашку: ширина зоны минус
16px, высота 24px внутри строки 40px. Поля со всех четырёх сторон 8px.
Плашка объёмная, как залитые кнопки; наведение затемняет её лицевую сторону («Объём кнопки»).
Состояние меняет только текст и оформление. Отступ текста счётчика не влияет
на положение плашки; оптическое выравнивание надписи со счётчиком не применяется.

Из зоны выводится остальное — ни одно из этих чисел не задаётся отдельно:

| Величина | Формула |
|---|---|
| Пол колонки имени | зона − отступ строки |
| Резерв строки | зона + 2 пикселя разделителей + отступ строки |
| Минимальная ширина панели | 3 зоны + 2 разделителя + внешние отступы навигации |

Минимум: `366` в основном варианте, `314` в Alt. **Это число обязано совпадать
в CSS (`--sidebar-min-width`) и в JS (`sidebarMinWidth()`)**: JS ограничивает
перетаскивание и поднимает сохранённую ширину, CSS замораживает навигацию под
шторой. Сдвиг одной стороны оставляет навигацию шире панели, и штора навсегда
срезает колонку счётчика. Контракт закреплён тестами `sidebarColumns.test.ts`.

**Выше минимума** лишняя ширина делится поровну между именем и превью, пока имя
не упрётся в `150`; дальше весь остаток забирают превью.

**Правый разделитель стоит на границе зоны**, а не на краю кнопочного поля.
Ячейка миниатюр кончается на нём сама (07.10.2026): ячейка счётчика стоит в
строке отдельно, и маске миниатюр её ширина не нужна.

### Alt 2 — одна полоса внизу

Наследует всю геометрию Alt 1 и меняет компоновку оболочки:

| Что | Default / Alt 1 | Alt 2 |
|---|---|---|
| Строка метаданных (число коллекций, счётчик элементов, Grid/Graph) | под верхним меню | под контентом, поверхность `--accent`, граница сверху |
| Нижняя панель с кнопками | есть | нет |
| Разворот карточки: название, меню карточки, крестик | в строке метаданных | в верхнем меню |
| Разворот карточки: переключатель `All/Connected` | в строке метаданных | там же, внизу |
| Разворот карточки: правая половина строки | статистика пространства | метаданные заметки: тип, дата, размеры, число медиа, автор |

Строка метаданных не исчезает при открытой карточке, как в компактном режиме
разворота, — внизу она и есть носитель коллекций и сведений о заметке. Отсюда
правило: переключатель коллекций рисует либо верхнее меню, либо строка, но
никогда оба сразу.

Размещение строки — параметр компонента (`placement="top" | "bottom"`), а не
проверка варианта внутри него: шов всегда обращён к контенту (граница снизу
наверху, сверху внизу), и то же размещение можно включить в любом другом
варианте.

## Слои композиции

**Собственный слой — плата, а не ускорение.** `transform-gpu` и `will-change`
дают элементу отдельный буфер в видеопамяти. Один элемент — мелочь; тот же
приём на каждой карточке ленты стоил вчетверо больше памяти и втрое больше
нагрузки на отрисовку при неподвижном окне (замер 20.08.2026: 1,3 ГБ и треть
ядра против 320 МБ и пяти процентов).

**Просить слой можно только под конкретный дефект.** У нас он один: WKWebView
поднимает `<video>` в собственный слой, и обычный сосед проигрывает ему в
порядке отрисовки несмотря на `z-index` — кнопки проваливались под ролик.
Поэтому слой запрашивают только hover-контролы карточки, под которой играет
видео (`videoUnderneath`), и никто больше.

**Проверять замером, а не ощущением.** Нагрузка от слоёв не видна в коде и не
ловится профилировщиком JavaScript: и JS, и Rust в этот момент спят. Смотреть
надо процесс отрисовки — `ps` по нему и сборка-проба со снятыми слоями.

## Разделители и габарит

**Линия входит в габарит, а не поверх отступа.** Разделитель принадлежит тому
элементу, чью границу обозначает, и никогда не выносится на уровень выше:
строка списка закрывается своей линией, панель хрома — своей. Габарит при этом
остаётся на модульной шкале — 32 у хрома, 40 у строки, — потому что размеры
компонентов образуют ритм интерфейса, а волосяная линия толщиной в пиксель не
имеет права этот ритм сдвигать. Строки в 41 не бывает.

**Пиксель линии резервируется, содержимое центрируется в остатке.** Иначе
линия садится на нижний отступ и съедает его: при отступе 4 это четверть, и
просвет над содержимым оказывается на пиксель больше, чем под ним. Верхний
хром так работает с самого начала — `box-sizing: border-box` вычитает границу
до центрирования; строка боковой панели приведена к тому же правилу
`padding-bottom: 1px` (`SIDEBAR_ROW_BOX_CLASS`). Просветы выходят по 3,5 — на
Retina это ровно 7 физических пикселей с каждой стороны.

**Отступ отсчитывается от края линии, не от колонки, которую она закрывает.**
То же правило по горизонтали: между направляющей и первой миниатюрой
положено 4 чистых пикселя, поэтому полоса начинается на пятом.

Замер, зафиксировавший правило: просвет над содержимым и под ним равен во всех
строках, включая первую, где сверху стоит граница хрома.

## Отступы

### Плотность интерфейса — настройка

Панель `Display` ленты → `Spacing`: `32` / `24` / `16` (до 30.09.2026 жила в
Settings → Appearance; [SPEC_FEED_DISPLAY.md](SPEC_FEED_DISPLAY.md), Д17).

Одно значение стоит за расстояниями внутри контента: боковой и верхний отступы
ленты, зазор между карточками, колонки и верхний отступ развёрнутой карточки,
таблица боковой панели. Отдельной настройки для карточек нет намеренно: разная
плотность на разных поверхностях читается как небрежность, а не как замысел.

Шаги: `32 / 24 / 16 / 2`. Крайний шаг `2px` существует ради ленты вплотную;
чтобы он не съедал оболочку, введены две границы. **Хром отвязан от ритма
полностью** и держит `--chrome-edge-pad: 8px`. **Поверхности чтения имеют
пол**: `--card-content-pad` и отступы таблицы боковой панели равны
`max(ритм, 16px)` — на шагах `32/24/16` ничего не меняется, на `2` они
останавливаются на `16`.

Значение публикуется CSS-переменной `--edge-rhythm` на корне: таблицы стилей и
произвольные значения Tailwind читают её напрямую, лента получает число через
`useDensity`, потому что геометрия masonry считается в JS.

Производные переменные выводятся из источника, а не задаются числами:
`--sidebar-nav-pad-x`, `--sidebar-nav-pad-top` равны `max(ритм, 16px)`,
`--main-secondary-pad-x` равен краю хрома, `--top-collection-pad-x` равен краю
хрома минус `8px` — у переключателя коллекций есть собственный внутренний
отступ пилюли, и текст должен встать вровень с краем оболочки, а не сам
триггер.

Правило распространяется и на код: выпадающее меню переключателя коллекций
равняется по тексту триггера, поэтому его смещение **измеряется** с самой
кнопки, а не повторяется числом. Повторённое число (`24`) молча разошлось с
отступом в тот день, когда хром отвязали от ритма.

Раньше эти величины были вшиты в дизайн-вариант `alt` набором констант. Теперь
`alt` отвечает только за раскладку.

| Токен | Значение | Утилита | Где |
|---|---|---|---|
| `--spacing-s1` | 4px | `p-s1`, `gap-s1` | Внутренний отступ мелких элементов (теги, бейджи) |
| `--spacing-s2` | 8px | `p-s2`, `gap-s2` | Отступ внутри кнопки, инпута |
| `--spacing-s3` | 16px | `p-s3`, `gap-s3` | Отступ между элементами внутри карточки |
| `--spacing-s4` | 24px | `p-s4`, `gap-s4` | Padding внутри карточки от края |
| `--spacing-s5` | 32px | `p-s5`, `gap-s5` | Расстояние между карточками (gap сетки) |
| `--spacing-s6` | 48px | `p-s6`, `gap-s6` | Отступ между секциями |
| `--spacing-s7` | 64px | `p-s7`, `gap-s7` | Верхний/нижний отступ страницы |

**Примечание:** токены spacing определяют разрешённую шкалу. Числовые утилиты Tailwind (`p-2`, `gap-8`) допустимы, если их значение совпадает со шкалой. Недопустимые значения: 20px (`p-5`), 28px (`gap-7`), 40px — их нет в шкале.

Grid gap (32px) задан JS-константой `GAP` в `Grid.tsx`, потому что участвует в расчёте колонок. Соответствует `--spacing-s5`.

### Текст интерфейса 13 px

13 px это размер, которым macOS набирает заголовки окон, меню и боковые
панели. Замер из AppKit 02.10.2026: заголовок окна 13 pt жирный, пункты меню
13 pt, системный текст 13 pt; 1 pt в macOS равен 1 px вёрстки. Этим размером
Mine набирает:

- оба ряда верхней панели: название пространства, текущую коллекцию, поле
  фильтра коллекций, число коллекций, `651 elements`, `View:` и переключатели;
- все выпадающие меню и меню правого клика вместе с подменю и тем, что в них
  лежит: выбор коллекций, список пространств;
- названия коллекций в боковом меню и поле их переименования.

Реализация: одно правило в `src/styles/global.css` с переменной
`--text-interface: 13px` поверх утилит этих мест (`text-sm` в рядах панели,
`text-base` в меню и списке коллекций). Меняется только кегль: высота строки
остаётся той, что даёт утилита, поэтому ни ряд, ни строка меню не меняют
высоту. Переменная объявлена в `:root`, а не в `@theme`: размеры темы
подставляются в утилиты при сборке и в работающем приложении как переменные
недоступны.

Остаются 12 px: числа в строках бокового меню, текст карточек ленты и нижняя
панель с подсказками клавиш.

### Иконки 13 px

Все иконки lucide во всём интерфейсе набраны 13 px (`size-[13px]`), как текст
интерфейса 13 px и как значки в меню macOS: там значок пункта меню это символ
SF Symbols того же кегля, 13 pt (замер AppKit 02.10.2026). Размер один для
всех мест: кнопки всех размеров (`default`, `sm`, `xs`, `icon`, `icon-xs`,
`chrome-icon`), пункты выпадающих меню и меню правого клика, слот иконки меню
`MenuIconSlot` (13×13px, чтобы колонка текста оставалась ровной), бейдж,
диалог, кнопки на карточке, верхняя панель.

Линия ровно 1 px. Lucide рисует на сетке 24 единицы с обводкой 2, и при 13 px
линия вышла бы 1,08 px, с размытым краем на любом экране. Одно правило в
`src/styles/global.css`: `svg.lucide { stroke-width: 1.8462 }`, это 24/13
единицы сетки, ровно 1 px при 13 px. Собственных обводок у иконок нет.

Исключения:

- логотип Mine в меню настроек и значок «плей» на видео не из lucide и
  сохраняют свой рисунок; кнопка `chrome-icon` держит не-lucide SVG в 16×16px;
- крупная иконка в шапке `AlertDialog` 32px.

Решение пользователя 02.10.2026 после проб: 16 px в меню и на кнопках карточки
отвергнуто (иконке тесно в плашке 24 px, плюс тяжелее текста рядом), 12 px
везде отвергнуто (иконки верхней панели резко мельчают), принято 13 px с
линией 1 px.

## Цветовой принцип

Все серые — чисто нейтральные (R=G=B), chroma 0, hue 0. Никаких тёплых или холодных оттенков. Цвет допустим только в акцентах: ссылки, ошибки (destructive), разъединение (detach), поисковый маркер (search-mark), графики (chart-*).

### Два уровня «опасных» действий

Сквозное правило для всех меню, кнопок и подтверждений:

| Токен | Цвет | Семантика | Примеры |
|---|---|---|---|
| `--destructive` | красный | действие **безвозвратно удаляет контент** | `Delete`, `Delete Media`, `Delete Text`, удаление коллекции |
| `--detach` | оранжевый | действие **разрывает связь, контент сохраняется** | `Disconnect`, `Remove from Element` |

**Принцип выбора значений (теория, не вкус).** Тон и насыщенность смысловых
цветов берутся у macOS (постоянная К12 в
[SPEC_COLOR_RULES.md](</Users/i_iii/Проекты/Личные проекты/local-arena/.claude/worktrees/youtube-referer/SPEC_COLOR_RULES.md>)):
приложение живёт среди системных поверхностей, и культурные коды «опасности»
у пользователя уже откалиброваны ОС:

- `--destructive` от `systemRed` (`oklch(0.654 0.232 28.7)`), код «потеря
  данных»;
- `--detach` от `systemOrange` (`oklch(0.765 0.175 62.6)`), код
  «предупреждение без потери».

Светлота выводится по роли: оба цвета это текст и значок, поэтому в светлой
теме у обоих ровно порог текста 4.5:1 на холсте (К5), а тёмная выводится по
закону сигнала линейной формы; насыщенность уменьшается до охвата sRGB.
Поэтому светлота у них почти равна, и различие держит тон: красный против
оранжевого, Δhue около 34°.

| Тема | `--destructive` | `--detach` | Контраст на холсте |
|---|---|---|---|
| Светлая | `oklch(0.596 0.232 28.7)` | `oklch(0.577 0.132 62.6)` | 4.50:1 и 4.50:1 |
| Тёмная | `oklch(0.717 0.177 28.7)` | `oklch(0.744 0.17 62.6)` | 7.36:1 и 8.40:1 |

Пункты меню используют `variant="detach"` (`DropdownMenuItem` /
`ContextMenuItem`) — оранжевый текст, стандартный hover/focus-фон, как у
destructive; в иконочном слоте — `Unlink` (разрыв цепи), у destructive-пунктов
удаления — `Trash2` (корзина). Действие, которое выглядит «удаляющим», но не
трогает файлы, обязано быть оранжевым, а не красным — иначе пользователь не
отличает потерю данных от рассоединения.

**Правило:** при добавлении нового серого — `oklch(L 0 0)`. Не вводить hue.

## Архитектура цвета: три роли

Любой цвет интерфейса выводится из закона, а не подбирается на глаз
(решение пользователя 05.10.2026). Свод законов и постоянных с выводом
каждого токена в обеих темах лежит в
[SPEC_COLOR_RULES.md](</Users/i_iii/Проекты/Личные проекты/local-arena/.claude/worktrees/youtube-referer/SPEC_COLOR_RULES.md>)
(принят пользователем 05.10.2026); палитра в коде одна, её токены стоят в
тематических блоках `global.css`. Принципы:

1. **У каждого окрашенного элемента одна роль, у роли один закон.** Ролей
   три: зона, высота и сигнал.
2. **Элемент с двумя ролями складывается слоями.** Выбранная клавиша нижней
   панели, кнопка в подсвеченной строке: лицевая сторона следует закону
   высоты, слой состояния поверх неё следует закону сигнала.
3. **Значение вне закона записывается вместе с причиной.** «Выверено на
   экране» причиной не считается. Таких значений в палитре нет.
4. **Основной цвет текста `--foreground` абсолютен** (К2) и законами не
   меняется.
5. **Токен без потребителя удаляется**, два токена с одинаковым выводом
   сводятся к одному.

| Роль | Что входит | Закон |
|---|---|---|
| Зона | уровни окна: страница `--background`, боковое меню `--sidebar`, карточки и хром `--card`, `--chrome`, нижняя панель и полоса вкладок `--accent` (с ними `--secondary`, `--muted`) | целое число шагов зоны ярче страницы (раздел «Поверхности») |
| Высота | лицевая сторона объёмной кнопки и выбранного сегмента, плавающие слои на `--popover` (меню, подменю, подсказки, всплывающие панели, уведомления) | светлая тема: лицевая сторона строится как подложка наведения; тёмная тема: яркостью (лицевая сторона на 3 шага зоны ярче того, что под ней); плавающий слой в обеих темах на уровне 2, цвете нижней панели, держится линией и тенью (решение пользователя 07.10.2026) |
| Сигнал | линии и рамка поля (`--border`, `--sidebar-border`, `--input`), рамка того, что нажать нельзя (`--inert-frame`), слой состояния (`--active`), плоские заливки контролов (`--component-fill*`), фокус и выделение (`--ring`, `--sidebar-ring`, `--border-accent`, `--feed-selection-frame`, `--graphic-card-focus-overlay`), ступени текста и значков (`--muted-alpha`, `--tertiary-alpha`), смысловые цвета | одинаково заметная разница с тем, на чём стоит, в обеих темах: тёмная ΔL = светлая ΔL / коэффициент формы |

### Сигнал: одинаковая заметность в обеих темах

Сигнал отличается от того, на чём стоит: линия от поверхности, подложка
наведения от строки, вторичный текст от фона. Закон держит постоянной не
светлоту сигнала (она меняет знак между темами), а **разницу с фоном ΔL**
(светлота OKLab, перцептивно равномерная): сигнал обязан одинаково бросаться в
глаз в обеих темах.

**Коэффициент формы.** При равном ΔL тёмное на белом читается резче, чем
светлое на тёмном (иррадиация). Поэтому тёмной теме нужна разница больше
светлой: **тёмная ΔL = светлая ΔL / коэффициент**, и коэффициент зависит от
формы сигнала (решение пользователя 05.10.2026). Эталон светлая тема: она
задаёт величину, тёмная выводится.

| Форма | Что | Коэффициент |
|---|---|---|
| Линейная | линии, рамки, рамка того, что нажать нельзя, рамка поля, обводки фокуса, текст и значки | К4 = 0.7 |
| Площадная | слои состояния, плоские заливки, заливка фокуса на изображении | К4ₐ = 0.51 |

**Тихий шаг.** Тихие сигналы стоят на лестнице из целых тихих шагов s (К7,
ΔL 0.03 в светлой теме): линия, рамка того, что нажать нельзя, и слой
состояния это 1 s, плоская заливка контрола 2 s, заливка под слоем состояния
и заливка фокуса на изображении 3 s. Сильные индикаторы своих чисел не имеют
и берут ступени текста.

**Где мерить.** Каждый сигнал меряется на своей опорной поверхности:

| Сигнал | Опорная поверхность | Светлая | Тёмная |
|---|---|---|---|
| Слой состояния `--active-alpha` | страница | `4.1%`, ΔL 0.030 (1 s) | `5.25%`, ΔL 0.059 |
| Вторичная ступень `--muted-alpha` | страница | `55.66%`: ровно 4.5:1 (К5), ΔL 0.432 | `69.28%`, ΔL 0.617 |
| Третичная ступень `--tertiary-alpha` | страница | `26%` (К8), ΔL 0.194 | `27.92%`, ΔL 0.278 |
| Рамка того, что нажать нельзя `--inert-frame-elevation` | любая (сдвиг от неё) | `−0.03` (1 s) | `+0.0429` |
| Линия и рамка поля `--border`, `--sidebar-border`, `--input` | самая яркая зона, которую линия разделяет (`--accent`) | `0.9394`, ΔL 0.03 (1 s) | `0.243` |
| Плоская заливка `--elevation-rest`, под слоем состояния `--elevation-hover` | поверхность под ней | `−0.06` и `−0.09` (2 s и 3 s) | `+0.1176` и `+0.1765` |
| Фокус кнопок и полей `--ring`, `--sidebar-ring` | страница | `0.568`: вторичная ступень, непрозрачная | `0.757` |
| Фокус карточки и шов строки бокового меню `--border-accent` | страница | `0.669`: 3:1 (К6) | `0.612` |
| Рамка выбранной карточки `--feed-selection-frame` | страница | основной цвет `0.145` | основной цвет `0.985` |
| Заливка фокуса на изображении `--graphic-card-focus-overlay` | холст | основной цвет `12.21%` (3 s) | основной цвет `16.93%` |

Числа охраняет тест `src/styles/colorLaw.test.ts`: он выводит каждый токен
тематических блоков `global.css` из постоянных свода через
`src/lib/colorLaw.ts` и падает, если значение подобрано мимо закона.
Прозрачности выводятся так, чтобы наложенный цвет дал нужную ΔL на опорной
поверхности; на других поверхностях наложение даёт близкую разницу (раздел
«Цвет от того, что под элементом»).

С 28.09.2026 (SPEC_CARD_STATES.md) выделение не рисует кольцо снаружи
карточки: `--feed-selection-frame` красит собственную границу карточки `1px`,
как `--border-accent` при клавиатурном фокусе и подсветке от коллекции.
Наведение мышью обводку не красит. Выделение главнее всех состояний: на
выделенной карточке фокус, подсветка и наведение ничего не добавляют.

`--border-accent` это единый токен индикатора навигации: шов строки бокового
меню (наведение и фокус) и рамка фокуса карточки в сетке. `--ring` отдельно:
обводка фокуса кнопок и полей, у неё другая роль и больший контраст.

### Зона и высота

**Зона** это уровень окна. Уровень зоны это целое число шагов зоны (К3), на
которое она ярче страницы: в тёмной теме шаг 0.03 L, в светлой он
переносится площадным коэффициентом, 0.03 × 0.51 = 0.0153. Боковое меню стоит
на трети шага (К9): отличимо и от страницы, и от хрома. Значения в разделе
«Поверхности». Значение зоны **абсолютно** (по уровню): иерархия глубины, а не
контраста.

**Высота** показывает, что лежит над окном: лицевая сторона объёмной кнопки и
выбранного сегмента, плавающие слои. Плавающий слой с 07.10.2026 стоит в обеих
темах на уровне 1, цвете хрома, то есть ряда страницы под полосой вкладок
(`--popover` = `--chrome`: светлая 0.9847, серый 250; тёмная 0.17, серый 15;
решение пользователя), и держится линией `--border` и тенью (шкала К11); над
самим хромом и карточкой заливки совпадают, и слой держат только линия и
тень. В светлой теме лицевая сторона кнопки строится как подложка наведения:
зона под кнопкой со слоем состояния `--active` (на странице 245, на карточке,
хроме и плавающем слое 240, на нижней панели 235). На тёмном фоне тень не
читается, и высоту кнопки несёт яркость: лицевая сторона на 3 шага зоны (0.09)
ярче того, что под ней (на странице 29, на плавающем слое 36, на нижней панели
43). Лицевую сторону задают токены
`--button-face-step`, `--button-face-layer` и `--button-face-share` в
тематических блоках `global.css`, правило лица и рецепты объёма живут в
`buttons.css` (раздел «Объём кнопки»).

**Плоские заливки контролов** (значок-пилюля, клавиша в подсказке, строка
ссылки, клавиша в поиске) это не высота, а сигнал площадной формы, как
`systemFill` у macOS: заливка поднимается над тем, что под ней, на постоянную
величину, а не берёт абсолютный цвет, поэтому одинаково заметна на любом фоне.
`--component-fill` на два тихих шага ярче того, что под ним,
`--component-fill-hover` на три (заливка и слой состояния поверх).

| Токен | Сдвиг (светлая) | Сдвиг (тёмная) |
|---|---|---|
| `--component-fill` (и его алиас `--component-fill-inner`) | `−0.06` (2 s) | `+0.1176` |
| `--component-fill-hover` | `−0.09` (3 s) | `+0.1765` |

Слой состояния (`state-active`) тоже сигнал: прозрачный основной цвет поверх
того, что под ним (раздел «Цвет от того, что под элементом» ниже). Заливки
внутри подсветки поднимаются от неё, а не от зоны.

**Механизм.** `--surface` это цвет, на котором стоит содержимое. Каждая зона
объявляет в нём свой фон (карта в `global.css` после тематических блоков),
подсветка передаёт в нём себя тому, что держит (раздел ниже). Заливки
считаются от `--surface` относительным цветом OKLCH:
`oklch(from var(--surface) calc(l + var(--elevation-rest)) 0 0)`, один набор
на все места (`surface-fills`). Зона ссылается прямо на свой токен
поверхности, второго числа, способного разойтись с цветом, нет. Работает
благодаря `@theme inline`: утилита `bg-component-fill` подставляет
`var(--component-fill)` и вычисляется на элементе кнопки, наследуя
`--surface` от ближайшей зоны или подсветки.

### Цвет от того, что под элементом

Закон обеих тем (решение пользователя 04.10.2026): элемент берёт цвет от
того, что фактически лежит под ним, а не от ближайшей объявленной зоны. Любой
элемент, который красит фон, в том числе переходная подсветка (наведённая или
выбранная строка, вкладка под указателем, открытый пункт меню или триггер,
выбранная клавиша нижней панели), является поверхностью для того, что внутри
него. Ничто не совпадает с подложкой и не теряет контраст ни в одном
состоянии и ни в одной теме. Прежнее правило «переходные состояния не
становятся зонами» и исключение `data-surface-zone` отменены.

Механизм один, по образцу macOS: непрозрачные поверхности и заливки,
прозрачные слои состояния и ступени текста.

1. **Поверхности и заливки непрозрачны.** Зоны (раздел «Поверхности»),
   лицевые стороны объёмных кнопок и плоские заливки контролов
   (`--component-fill*`) остаются непрозрачными: кнопка может стоять поверх
   изображения, и прозрачная заливка показала бы картинку.
2. **Подсветка это слой состояния.** Наведение, выбор, открытое меню,
   клавиатурный фокус пункта красит утилита `state-active`: поверх
   собственной заливки элемента ложится основной цвет текста
   `--foreground` с прозрачностью `--active-alpha`, `4.1%` в светлой теме и
   `5.25%` в тёмной (токен `--active`). Сила слоя это сигнал площадной формы,
   один тихий шаг: на странице ΔL 0.030 и 0.059 (раздел «Архитектура цвета:
   три роли»). Слой смешивается с тем, что под ним, сам: в светлой теме
   255 → 245 на странице, 253 → 243 на боковом меню, 250 → 240 на карточке и
   хроме, 245 → 235 на нижней панели; в тёмной 9 → 22, 11 → 24, 15 → 28,
   22 → 34, на плавающем слое, как на хроме, 15 → 28. На заливке клавиши, на изображении и
   на другой подсветке так же. Совпасть с подложкой он не может по
   построению.
3. **Подсветка передаёт себя как поверхность.** Элемент со слоем сохраняет
   поверхность, на которой стоит (`--under`), и его собственная заливка
   поднимается от неё: выбранная клавиша это её обычная лицевая сторона со
   слоем сверху. Его дети получают `--surface` = эта поверхность со слоем
   (`color-mix(in srgb, var(--under), var(--foreground) var(--active-alpha))`)
   и пересчитанные от неё заливки: кнопка Connect в подсвеченной строке,
   подложка крестика на наведённой вкладке, внутренняя пуля на подсвеченном
   триггере поднимаются от подсветки. Когда плашка подсветки стоит рядом с
   содержимым, а не вокруг него (дорожка пилюли, `TabsList variant="chrome"`),
   их общий родитель несёт `state-surface`: та же передача без краски.
4. **Текст и значки это основной цвет с прозрачностью** (раздел «Цвет текста
   и значков»): вторичная и третичная ступени складываются с тем, что под
   ними, как слой состояния.

Точность: слой внутри слоя (подложка крестика на наведённой вкладке)
складывается точно и в краске, и в переданной поверхности. Ребёнок зоны
остаётся на своей зоне. Приближение одно: если у элемента со слоем есть своя
заливка (выбранная клавиша), дети получают поверхность без этой заливки; в
интерфейсе там только текст, а он складывается сам.

Совпадений подсветки с тем, что внутри, нет по построению: слой всегда на
тихий шаг ярче того, на чём стоит, и всё внутри подсветки поднимается от неё.
Как тёмная тема складывает сигналы, видно на странице `/__text-ladder`
(сервер разработки): лестница сигналов в тёмной теме с замерами.

Линии в этот механизм не входят: одна непрозрачная краска на окно (раздел
«Границы»).

## Цвет текста и значков

Лестница из трёх ступеней, как метки macOS (`labelColor`,
`secondaryLabelColor`, `tertiaryLabelColor`; решение пользователя
04.10.2026): основная ступень абсолютная, вторая и третья это основной цвет с
прозрачностью. Поэтому ступень отстоит от того, что под ней, одинаково на
любой поверхности и подсветке.

| Ступень | Токен | Светлая | Тёмная | Утилита |
|---|---|---|---|---|
| Основная | `--foreground` | `oklch(0.145 0 0)` | `oklch(0.985 0 0)` | `text-foreground` |
| Вторичная | `--muted-foreground` | основной, прозрачность `0.5566` | основной, `0.6928` | `text-muted-foreground` |
| Третичная | `--tertiary-foreground` | основной, `0.26` | основной, `0.2792` | `text-tertiary-foreground` |

Вторичная и третичная ступени это сигналы линейной формы (раздел
«Архитектура цвета: три роли»). Светлая вторичная это доля, дающая на холсте
ровно порог текста 4.5:1 (К5, WCAG 1.4.3), светлая третичная это доля
`tertiaryLabelColor` macOS (К8, 26%); тёмные выведены законом сигнала:
разница с фоном на странице равна светлой, делённой на 0.7 (ΔL 0.432 → 0.617
у вторичной, 0.194 → 0.278 у третичной). На странице вторичная ступень даёт
серый 119 в светлой теме и 176 в тёмной, третичная 191 и 76.
`--secondary-foreground`, `--accent-foreground`,
`--sidebar-accent-foreground`, `--card-foreground`, `--popover-foreground`,
`--sidebar-foreground` и `--primary` равны основной ступени. Непрозрачная
вторичная ступень для тех, кто не умеет складывать цвета (холст графа), это
`--muted-foreground-opaque`: вторичная ступень, уже сложенная с `--surface`.

Контраст на холсте (WCAG): вторичная ступень 4.50:1 в светлой теме и 9.17:1 в
тёмной, третичная 1.83:1 и 2.33:1. Третичная ступень поэтому принадлежит
только недоступному (WCAG его освобождает, решение Р1 а в своде).
Подсказки в полях, плейсхолдеры, мета-строка над лентой, индикаторы
активности и «No collections» берут вторичную ступень: правило в
`global.css` переводит `text-tertiary-foreground` и
`placeholder:text-tertiary-foreground` на вторичную ступень у всего, что не
выключено, и это делается на самом элементе, поэтому класс наведения на нём
же по-прежнему поднимает ступень.

**Значки на той же лестнице.** Значок берёт цвет текста (`currentColor`) и
отдельных серых не имеет. Значок lucide из нескольких линий рисуется одним
слоем: линии получают непрозрачный цвет, а прозрачность ложится маской на весь
значок (`svg.lucide` в `global.css`). Иначе на пересечении линий (крестик,
плюс) прозрачность складывалась бы в тёмную точку.

**Наведение поднимает на одну ступень.** Наведение, открытое меню и
клавиатурный фокус, где элемент ярчает, переводят текст или значок ровно на
ступень вверх: третичная → вторичная, вторичная → основная. Шаг это доля
расстояния от фона до основного цвета (вторичная → основная: `0.4434` в
светлой теме, `0.3072` в тёмной), поэтому прибавка одинаково сильна на любом
фоне. У основной ступени шага вверх нет: на наведении она не меняется. Носители:
кнопки хрома (`hover`, открытое меню, клавиатурный фокус хрома), `ghost` и
`link`, `raised` (тусклый значок, основной только при открытом меню: наведение
у объёмной кнопки меняет лишь лицевую сторону), клавиши нижней панели
(`group-hover`), строки бокового меню, пункты меню (значок пункта и подпункта
вторичный в покое и основной, как текст, у пункта под указателем или фокусом
клавиатуры и у подпункта с открытым подменю; у `destructive` и недоступного
пункта цвет значка свой и не меняется). Других серых для
текста нет: `--hover-foreground`, `text-accent-foreground` на фокусе пунктов
меню и приглушение через `opacity` убраны.

**Недоступное** берёт третичную ступень (раздел «Недоступно»).

**Правило:** иерархия через яркость, не через размер или цвет. Плейсхолдеры,
подсказки и мета-информация берут вторичную ступень, третичная только у
недоступного.

## Фоны

Две независимые группы токенов: **поверхности** (фоновое наслоение) и **заливки компонентов** (кнопки, интерактивные элементы). Разные требования к контрасту — поверхности тонкие, кнопки считываемые.

### Поверхности

| Уровень | Токен | Светлая, L (серый) | Тёмная, L (серый) | Назначение |
|---|---|---|---|---|
| 0 | `--background` | 1.0 (255) | 0.14 (9) | Фон страницы |
| ⅓ | `--sidebar` | 0.9949 (253) | 0.15 (11) | Заливка боковой панели целиком |
| 1 | `--card`, `--chrome` | 0.9847 (250) | 0.17 (15) | Карточки ленты, hover previews, App/top chrome |
| 2 | `--accent`, `--secondary`, `--muted` | 0.9694 (245) | 0.20 (22) | Нижняя панель, полоса вкладок, фон карточки-статьи в тёмной теме |
| высота | `--popover` | 0.9847 (250) | 0.17 (15) | Плавающие слои: меню и подменю, подсказки, всплывающие панели, уведомления |

Уровень зоны это целое число шагов зоны ярче страницы (раздел «Архитектура
цвета: три роли»): шаг 0.03 в тёмной теме и 0.0153 в светлой (0.03 × К4ₐ).
`--popover` не зона, а высота, но с 07.10.2026 стоит на уровне 1, цвете хрома
(ряд страницы под полосой вкладок), в обеих темах (решение пользователя) и
держится линией и тенью.
Родной фон окна macOS следует за полосой вкладок (`--accent`): 245 в светлой
теме, 22 в тёмной.

Линия `--border` (0.9394 и 0.243) не поверхность, а сигнал (раздел
«Границы»). Наведение и выбор рисует слой состояния `state-active`, а не
поверхность `--accent` (раздел «Цвет от того, что под элементом»).

**Уровень ⅓, шаг сайдбара** (К9). Боковая панель собирается собственной
заливкой: треть шага зоны от фона страницы в сторону хрома. Полный шаг ставил
бы панель на один уровень с хромом, а треть оставляет до хрома две трети шага,
и обе оболочки различимы. `bg-sidebar` одновременно перебазирует `--surface`
зоны, так что все заливки и подсветки внутри панели поднимаются от её
поверхности, контракт: `src/lib/sidebarSurface.test.ts`.

**Примечание:** `--card` и `--chrome` делят один уровень, но роли разные:
`--card` это контентные карточки и hover previews, `--chrome` это оболочка
приложения. Токены `--muted`, `--secondary` имеют то же значение, что и
`--accent` (для совместимости с shadcn). Для нижней панели и активных search
surfaces используем `bg-accent`, для верхнего хрома `bg-chrome`. Меню, подменю
и подсказки стоят на `--popover`, какой бы класс зоны ни нёс их компонент:
правило в `global.css` ставит им и фон, и `--surface`, поэтому всё внутри
поднимается от плавающего слоя. Слой состояния `--active` не принадлежит этой
абсолютной шкале: это прозрачный основной цвет поверх того, что под ним
(«Цвет от того, что под элементом»).

### Заливки компонентов (component fills)

Плоские заливки контролов **производные**, не абсолютные: считаются от того,
что под ними (`--surface`), и это сигнал площадной формы (раздел «Зона и
высота»). Конкретный L зависит от поверхности, на которой лежит контрол;
ниже результат на странице и на нижней панели (серый 0..255).

| Токен | Сдвиг, светлая | Сдвиг, тёмная | Светлая: страница, нижняя панель | Тёмная: страница, нижняя панель |
|---|---|---|---|---|
| `--component-fill` (= `-inner`) | −0.06 (2 s) | +0.1176 | 235, 225 | 35, 50 |
| `--component-fill-hover` | −0.09 (3 s) | +0.1765 | 225, 215 | 50, 65 |

`--component-fill-inner` это алиас `--component-fill`; выбранный сегмент
переключателя, который носит класс `bg-component-fill-inner`, рисуется лицевой
стороной объёмной кнопки (раздел «Объём кнопки»), а не этой заливкой.
Источник чисел: `--elevation-rest` и `--elevation-hover` в тематических блоках
плюс карта `--surface` после них. Фиксированными числами `--component-fill*`
не задавать.

## Границы

Линия одна непрозрачная краска на всё окно в каждой теме, без прозрачности
(решение пользователя 04.10.2026): разделители, рамки карточек, рамки меню и
линии бокового меню (`--border`, `--sidebar-border`). Линия это сигнал
линейной формы (раздел «Архитектура цвета: три роли»): самая яркая зона,
которую она разделяет (`--accent`, уровень 2), плюс один тихий шаг. Светлая
`0.9694 − 0.03 = 0.9394` (серый 235), тёмная `0.20 + 0.03 / 0.7 = 0.243`
(серый 32). Рамка поля `--input` равна линии: поле узнаётся по месту и
подсказке, поэтому WCAG 1.4.11 рамки 3:1 от него не требует.

| Тема | `--border`, `--sidebar-border` | `--input` | Толщина |
|---|---|---|---|
| Светлая | oklch(0.9394 0 0) | oklch(0.9394 0 0) | 1px |
| Тёмная | oklch(0.243 0 0) | oklch(0.243 0 0) | 1px |

Непрозрачная линия отстоит от разных подложек по-разному; это принятая цена
одной краски на окно. Светлая линия 235: −20 на странице, −18 на боковом
меню, −15 на карточке и хроме, −10 на нижней панели и полосе вкладок. Тёмная
линия 32: +23 на странице, +21 на боковом меню, +17 на карточке и хроме, +10
на нижней панели и полосе вкладок. На подсветке (строка под указателем или
выбранная) линия почти сливается: на подсветке поверх страницы −10 и +10, на
подсветке поверх нижней панели 0 и −2.

Сильные индикаторы для hover/focus state в sidebar и feed берут ступени
текста, своих чисел у них нет:

| Токен | Светлая | Тёмная | Где |
|---|---|---|---|
| `--border-accent` | oklch(0.669 0 0): 3:1 на холсте (К6) | oklch(0.612 0 0), выведена законом | Hover/focus color для sidebar row separator и focused feed card frame |

разрешён только для состояния hover/focus у sidebar row separator и keyboard

но не спорить с контентом. В sidebar реализация идёт через один и тот же
separator system: каждая строка владеет только своей нижней seam line, а
hover/focus перекрашивает seam текущей и предыдущей строки. В feed меняется

толщины.

### Нижняя панель команд

**Показывается только то, что сейчас можно нажать.** Команда, которой в текущем
состоянии нет применения, из панели убирается, а не гасится: серый пункт учит
сочетанию, которое ничего не делает, и заставляет проверять его вручную.
`Navigate` появляется, когда есть что перебирать **и есть где перебирать**: при
открытом элементе стрелки не делают ничего — лента их не слушает, а элемент не
обрабатывает, — поэтому запись уходит. `Switch collection` требует, чтобы список
коллекций был на экране: при свёрнутой боковой панели сочетание отключено, и
записи нет. `Focus` — когда есть сфокусированный объект, который откроет Enter;
`Close` — только при открытом элементе. При выделении панель сужается до команд
выделения: навигация и `Focus` уходят, приходит нажимаемая `Clear selection esc`.

**Имена и сочетания записей приходят из реестра** (`src/lib/commandRegistry.ts`,
[SPEC_KEYBOARD.md](SPEC_KEYBOARD.md)) — панель не владеет ни одним текстом
команды.

**Панель нажимаема, кроме двух справочных записей.** `Command ⌘K` кликом
открывает меню сфокусированного элемента, `Close` и `Clear selection` выполняют
свой esc, `Focus` открывает. Справочными остаются `Switch collection` и
`Navigate`: у перебора есть направление, одного действия для клика нет
(решение 23.08.2026).

**Контекстные записи только дописываются в конец группы** — то, что пользователь
уже видел, не сдвигается.

**Порядок**: слева постоянные `Hide Sidebar`, `New Collection`; середина —
контекстные; справа `Find elements`, `Commands ⌘/`, `Settings` крайняя — самая
редкая команда не занимает лучшее место панели.

**Сужение окна** ([SPEC_KEYBOARD.md](SPEC_KEYBOARD.md),
`src/lib/bottomBarOverflow.ts`): записи скрываются целиком, усечение запрещено.
Нужно ли что-то убирать, решает сама раскладка — `scrollWidth > clientWidth` на
панели, — а не арифметика по ширинам: модель отступов, зазоров и фиксированных
детей ошиблась ровно так, что записи уезжали под край окна и обрезались.

Порядок ухода — по ценности записи для читающего (24.08.2026):

1. **Справочные записи** — `Navigate`, `Switch collection`. Нажать нечего,
   поэтому теряется не действие, а напоминание.
2. **Esc-записи** — `Close`, `Clear selection`. Escape знают во всех
   интерфейсах; запись здесь — любезность, а не спасательный круг.
3. **Заученные команды** — `Settings`, `Hide Sidebar`, `New Collection`,
   `Find elements`, `Commands`. Доступны всегда, их сочетания есть и в нативном
   меню.
4. **Ситуативные команды** — `Command`, `Focus`. Существуют только в том
   состоянии, которое их предлагает, и панель — единственное место, где их
   вообще видно.



**Признак доступности сообщает тот, кто владеет состоянием.** Лента и граф
сами говорят панели, что у них есть, — и обязаны отозвать сказанное, когда
исчезают с экрана или когда поверх них открывается карточка. Без отзыва
последнее «фокус есть» остаётся навсегда, и панель предлагает `Focus` и `⌘K`
там, где ни того, ни другого нет.

**Имя записи — действие, а не предмет.** `Collections` рядом с `New Collection`
читалось как список, а не как переход между коллекциями; `Switch collection`
отличается от создания глаголом. Пункт панели называет то, что произойдёт.

**Справочная запись — не кнопка.** `Switch collection` и `Navigate` называют
то, что пользователь делает на клавиатуре: у перебора есть направление, и
одного действия, которое мог бы выполнить клик, у них нет. `Focus` — наоборот,
обычная кнопка: он открывает то, что сейчас в фокусе, и это одно определённое
действие.

`Command` (`⌘K`) остаётся справочной по другой причине: меню открывается
там, где стоит карточка, и у нажатия в панели нет позиции, которую можно было
бы использовать. Запись появляется при открытом элементе и в ленте — только при
клавиатурном фокусе: это единственное условие, при котором лента отвечает на
`⌘K`. Выделение мышью меню не открывает, поэтому и записи при нём нет. С
23.08.2026 запись нажимаема: лента передаёт панели само действие открытия меню,
а не признак доступности. У
таких записей `ActionButton` получает `readOnly`: снимаются роль кнопки,
остановка при табуляции **и отклик на наведение**. Отклик снимается не только с
надстроенных `group-hover`-классов, но и в самом варианте кнопки: `readOnly`
переключает её на вариант `reference`. Пока вариант оставался `default`,
обводка приходила из него и появлялась при наведении прямо на пилюлю.

**Справочная запись показывается без тела, но не видом недоступного**
(решение 24.08.2026, уточнено пользователем 04.10.2026): вариант `reference`
это прозрачный фон, рамка `--inert-frame` от поверхности под записью (та же,
что у недоступного) и второстепенная ступень у клавиши и названия, без единого
`hover`-правила. Тело это то, что читается как «нажимаемо»; запись без тела
отличима от команды с первого взгляда, без наведения. Ответ на курсор обещает
нажатие, а нажимать здесь нечего. Третичную ступень запись не берёт: сочетание
работает, а тусклый текст говорил бы, что сейчас оно не сработает.

### Курсор

Mine — десктопное приложение, а не страница в браузере, поэтому курсор следует
правилам macOS, а не веба.

| Курсор | Когда | Примеры |
|---|---|---|
| Стрелка (по умолчанию) | Любое действие внутри приложения | Кнопки, пункты меню, карточки в ленте, строки сайдбара, результаты поиска, изображения |
| Указывающая рука `cursor-pointer` | Только переход вовне приложения | `Source`, домен в метаданных, ссылки в теле статьи |
| `grabbing` | Только пока идёт перетаскивание | Карточка, изображение |
| `text`, `col-resize`, `e-resize`, `w-resize` и прочие | По смыслу действия | Текстовые поля; линия бокового меню: `col-resize` между пределами ширины, `e-resize` на минимуме, `w-resize` на максимуме, `col-resize` всё перетаскивание |

Обоснование. В macOS указывающая рука по HIG означает ровно одно — «здесь URL,
клик уведёт по адресу»; все контролы системы живут под обычной стрелкой. Веб
пришёл к обратному, потому что плоские кнопки потеряли объём и курсор занял
место утраченного признака нажимаемости. У Mine эту работу делают другие
сигналы: контур кнопки при наведении, hover-действия на карточке, подсветка
строки. Курсор освобождается под единственную задачу, которую больше некому
выполнить, — предупредить, что клик выбросит из приложения в браузер.

Сторонние компоненты приносят веб-конвенцию с собой, и её приходится снимать
явно. Граф — единственный такой случай: его библиотека помечает узлы классами
`.clickable` (указывающая рука) и `.grabbable` (раскрытая ладонь до начала
перетаскивания). Оба сняты в `global.css`.

`grabbing` при этом положен обеим разновидностям перетаскивания — и узла, и
самого вида: панорамирование это перетаскивание, просто двигают не объект, а
камеру, и macOS показывает там закрытую руку (Просмотр, Карты). Библиотека
помечает только перетаскивание узла, поэтому случай фона размечен отдельно —
атрибутом `data-graph-panning`, который ставится **при движении с зажатой
кнопкой**, а не при нажатии: иначе курсор мигал бы на каждом клике.

Следствие для новых элементов: прежде чем ставить `cursor-pointer`, проверить,
уводит ли элемент из Mine. Если нет — курсор не трогать. Если элемент
нажимается, но при наведении никак не отзывается, чинить надо отклик, а не
курсор.

Отдельный случай — ссылки. Маршрутизация внутри Mine построена на настоящих
`<a>` (строки сайдбара — `NavLink`), а браузер выдаёт руку любому `<a href>`
даром: в разметке курсор не упомянут, поэтому по классам его не найти. Забрать
руку может только таблица стилей, и правило живёт в `global.css`: якорям
назначается стрелка, а рука возвращается тем, у кого `target="_blank"` или
внешний `http(s)`-адрес.

### Active (нажатие)

Только у объёмных кнопок, раздел «Нажатие».

### Native selection

Mine chrome is non-selectable by default: toolbar, sidebar, feed cards,
metadata rail, hover previews, buttons, images, and videos must not show the
blue WebKit selection overlay during pointer drags. The only non-editable
surface that opts back into native text selection is Detail article prose
(`[data-article-body]`), because text-selection extraction and `Cmd+C` depend
on the system selection.

### Selected (активный пункт сайдбара)

Sidebar navigation rows do not render a selected background. The active route
lives in router state; the table-like sidebar keeps one visual row model for
default, hover and active route states.

Default row text and right counts use `text-muted-foreground`. The selected
route row (`Everything` or the current channel) always stays
`text-foreground`. On row hover/focus the sidebar only brightens the focused
row text to `text-foreground`; all other row labels/counts stay
`text-muted-foreground`. The selected route also remains `text-foreground` if
another row is currently focused. Thumbnail strips do not participate in this
state and stay visually unchanged. The row separator is a single owned seam per
row. The experimental flag `SIDEBAR_ROW_HOVER_SEAM_ENABLED` controls whether
hover/focus also changes the hovered row seam and the previous row seam to
`border-accent`. Current test setting is `false`: hover/focus only brightens
text, while the seam stays `sidebar-border`. The previous seam highlight remains
available behind the flag and, when enabled, never changes line thickness.
Enter/exit uses `180ms cubic-bezier(0.22, 1, 0.36, 1)`; switching directly
between rows inside focus mode disables transition for that switch frame.

## Компоненты (shadcn/ui + CVA)

Компоненты Mine хранятся в проекте как source-owned shadcn/ui код. Текущая
headless-основа — Radix UI (`shadcn info`: `base = radix`); смена
base является отдельной миграцией, а не обновлением CLI. Стили задаются
через CVA (Class Variance Authority), а радиусы, цвета и размеры — токенами выше.

### Обновление shadcn-инфраструктуры

- `shadcn` CLI зафиксирован в `devDependencies`; его версию и `bun.lock`
  обновляет отдельный еженедельный Dependabot PR.
- Официальный global skill обновляется независимо от Mine из upstream
  `shadcn/ui`.
- Файлы `src/components/ui/` никогда не перезаписываются автоматически:
  это source-owned код с продуктовыми кастомизациями Mine.
- Upstream-расхождение проверяется read-only командой
  `bunx shadcn add <component> --diff`; каждое изменение принимается отдельно с
  прогоном компонентных и browser-тестов.
- `init`, `apply`, `migrate` и смена base не являются maintenance-командами; это
  отдельные архитектурные миграции.

### Button

Базовые свойства всех кнопок: `rounded-1` (3px), обычное начертание `font-normal`, `select-none`.
Курсор кнопка не меняет — см. «Интерактивные состояния → Курсор»; исключение
только для кнопок, уводящих в браузер.

Залитые кнопки (`default`, `destructive`, `raised`) стоят на лицевой стороне
объёмной кнопки: она считается от того, что под кнопкой (`--surface`), поэтому
кнопка одинаково отделена от любого фона (раздел «Объём кнопки»). Класс
`bg-depth-fill` это крючок, который красит правило лица в `buttons.css`;
своего токена у него нет. Внутренняя пуля составных controls
(`bg-component-fill-inner`) стоит на той же лицевой стороне, поэтому она и
обычная `Button` на одной структурной поверхности имеют строго одинаковый
вычисленный цвет; различаться могут только геометрия и hover-контракт.

Варианты (`variant`):

| Вариант | Фон | Hover | Отличие |
|---|---|---|---|
| `default` | `bg-depth-fill` и `.button-depth` | слой состояния поверх лицевой стороны | Primary, одна на группу действий |
| `secondary` | `bg-transparent` + обводка 1px inset `--border` | обводка `--component-fill-hover` | Все остальные текстовые действия |
| `destructive` | `bg-depth-fill` и `.button-depth` | слой состояния поверх лицевой стороны | `text-destructive` (красный текст) |
| `ghost` | `bg-transparent` | `text-foreground` (на ступень вверх) | Только иконные контролы |
| `link` | `bg-transparent` | `text-foreground` (на ступень вверх) | `underline`, инлайн-ссылки |

**Размер контрола задаётся, а не выводится из текста.** Ширина кнопки — число
в пикселях, а не `10ch` и не «по содержимому». Единица `ch` привязывает размер
к гарнитуре и кеглю: смена шрифта двигает контрол, а колонка вокруг него,
посчитанная в пикселях, остаётся на месте — так у кнопки `Connect` получились
поля 8 и 6 вместо равных. Ширина берётся по самому длинному состоянию
(`SIDEBAR_ROW_ACTION_BUTTON_PX` = минимальные 84 для `Connect` / `Connected` /
`Disconnect`). В ячейке sidebar ширина равна зоне минус два поля по 8px;
в collection picker остаётся 84px. `ch`
остаётся уместной для внутренних отступов (`px-[1ch]`), которые обязаны расти
вместе с текстом.

**Закон текстовой кнопки.** Текстовая кнопка действия всегда имеет тело:
заливку (`default`/`destructive`) или обводку (`secondary`). Текстовых кнопок
без обводки не бывает — голый текст не читается как кнопка. `ghost` разрешён
только иконным контролам (крестики, триггеры меню, инструменты оверлея), где
рамка вокруг каждой иконки была бы шумом. В группе действий ровно одна
primary; остальные — `secondary`; группа помещается в одну строку — перенос
кнопок на вторую строку означает, что действий слишком много или контейнер
слишком узок.

**Положение primary.** Два жанра, два правила. В левовыровненном потоке
(полноэкранные состояния, экраны настройки) кнопки идут потоком слева, и
primary — первая: её встречает порядок чтения. В диалоге кнопки прижаты к
правому нижнему углу (`DialogFooter`, `sm:justify-end`), и primary — крайняя
правая, Cancel слева от неё: конвенция macOS для окон-диалогов. Смешивать
жанры нельзя: правый низ в потоке и «primary первая» в диалоге одинаково
ломают ожидание.

**Деструктивность — по данным, не по драме.** `destructive` получают действия,
которые теряют содержимое (удаление карточки, отбрасывание незавершённой
загрузки). Действия, отменяющие только привязку или настройку и обратимые
повторным выбором — `Forget this space`, аналог системного «Forget This
Network» — остаются `secondary`: красный цвет, применённый к обратимому,
обесценивает его там, где терять действительно есть что.

Размеры (`size`):

| Размер | Высота | Паддинги | Шрифт | Иконка |
|---|---|---|---|---|
| `default` | `h-8` (32px) | `px-3` | `text-base` (14px) | 13px |
| `clipper` | `h-10` (40px) | `px-3` | `text-base` (14px) | 13px |
| `sm` | `h-7` (28px) | `px-2.5` | `text-base` (14px) | 13px |
| `xs` | `h-6` (24px) | `px-2` | `text-sm` (12px) | 13px |
| `icon` | `size-8` (32px) | нет | нет | 13px |
| `icon-xs` | `size-6` (24px) | нет | нет | 13px |
| `chrome-icon` | плашка 24×24px, область 24×30px | нет | нет | 13px, не-lucide SVG 16px |

Иконка во всех размерах одна, 13px с линией 1px (раздел «Иконки 13 px»).

Input и Command по умолчанию — 32px (`h-8`). Clipper использует
`Input controlSize="clipper"` (`h-10`) только внутри popup/overlay строк.

**Скругление основных элементов интерфейса: 3px (`rounded-1`).** Button,
ActionButton (обе пули), DropdownMenu, Tooltip, Input используют этот радиус.
`Badge` является отдельным pill-примитивом и использует `rounded-pill`.

**Семантические токены скругления** (управляются из `global.css`):
- `--radius-card` → скругление карточек и нижних углов медиа сверху (по умолчанию `var(--radius-0)` = 0px; меняется настройкой)
- `--radius-media` → скругление медиа внутри карточек (по умолчанию `var(--radius-0)` = 0px)

Карточки: `rounded-[var(--radius-card)]` на обёртке `[data-block-slug]`.
Плитки медиа: глобальное CSS-правило `[data-block-slug] img, [data-block-slug] video { border-radius: var(--radius-media) }`.
Общий контур медиа сверху: слот `GraphicSurface` с
`overflow-hidden rounded-b-[var(--radius-card)]`. Это сохраняет прямые стыки сетки.

### ActionButton: действующее представление

Нижняя панель использует только стандартное представление. Следующее описание
варианта Pill сохранено как история проектирования.

- **Pill** (по умолчанию) — сочетание клавиш и подпись в одной рамке,
  собственная геометрия компонента. Заливка `bg-component-fill-inner` лежит на
  сочетании клавиш: это фиксированная, знаковая половина пары, и в рамке она
  читается как клавиша. Название действия — текст, оно остаётся открытым.
- **Standard** — стандартный `Button` дизайн-системы размера `xs` несёт
  сочетание клавиш, название действия стоит справа обычным текстом. Поведение —
  hover, focus, активация — целиком принадлежит `Button` и здесь не
  переопределяется.

  Высота рамки — `h-5`, как у внутренней пули варианта Pill: оба представления
  стоят на одной базовой линии панели.

  Интерактивная область — вся пара, включая подпись. Рамка внутри неё это
  `span`, а не вложенный `button`: подпись входит в цель, и делать кликабельной
  только рамку значило бы оставить половину контрола мёртвой для указателя.

  Сочетание клавиш и подпись в покое вторичные (`text-muted-foreground`).
  Сочетание выходит на `foreground`, когда указатель на любой части пары
  (`group-hover`) — оно справочное, пока к нему не тянутся. Подпись при этом не
  меняется: подсветка обеих половин сразу читается как мигающий блок, а не как
  один контрол.

  Пара несёт собственный правый отступ `mr-2`. Без него подпись упирается в
  следующую кнопку и перестаёт читаться как часть своей группы: `gap` панели
  равен `gap` внутри пары.

Кнопка без сочетания клавиш в варианте Standard не оставляет пустую рамку:
подпись переезжает внутрь, и пара схлопывается в обычную кнопку с текстом.

В настройках сочетаний клавиш редактор использует тот же `Button` с
`variant="default"`, `size="xs"` и высотой `h-5`. Название команды уже стоит в
строке, поэтому внутри кнопки показано только сочетание. В покое кнопка имеет
`bg-depth-fill`, при наведении меняются лицевая сторона и цвет текста. Слой
состояния `state-active` поверх лицевой стороны обозначает только активную
запись нового сочетания.

Кнопки строки образуют одну группу у правого края: слева появляется `Reset`
только для изменённого сочетания, справа всегда остаётся кнопка сочетания.
Обе кнопки имеют высоту `h-5`. Появление `Reset` не сдвигает кнопку сочетания.

Вариант читается из корневого атрибута `data-action-button-style` через
`useActionButtonStyle`, а не передаётся пропом — места вызова у обоих
представлений одинаковые, и ни одно не может оказаться не в том виде.

### Surface Search

Surface Search описан в [SPEC_SEARCH.md](SPEC_SEARCH.md). Это inline state
существующих поверхностей, не modal и не command palette.

Main/Grid search (`Cmd+F`) сохраняет backend/query механизм, но visual search
component сейчас временно не rendered. Top chrome всё равно делится тем же
`--sidebar-width`, что и body: левая часть держит space selector, sidebar
channel search и `border-r border-sidebar-border`, поэтому разделитель
Sidebar/Main продолжается до верхнего края страницы вкладки. Правая часть top
chrome начинается с current collection switcher, а оставшаяся область остаётся
drag region до нового search surface. Поиск не участвует в layout Grid, не
анимирует страницу и не меняет scroll viewport.
Bottom app bar справа содержит `ActionButton` `Search elements` с `hotkey="⌘F"`.
Это command trigger, а не selected/toggle visual state: кнопка не получает
`isSelected` и не остаётся зажатой, даже когда search state активен. Button и
повторный shortcut переключают App-owned main search state без показа input.
При входе в Grid group selection пустой search state перестаёт быть active,
непустой query/filter остаётся активным.

Settings содержит persisted переключатель `Hide bottom menu`
(`localStorage` key `mine.bottomActionBarHidden`). Он скрывает весь bottom app
bar без placeholder-строки и без изменения высоты top chrome/body. Чтобы не
создавать тупик в UI, постоянная кнопка логотипа Mine открывает меню разделов
настроек независимо от видимости bottom bar. С 03.10.2026 она стоит справа в
полосе вкладок (раздел «Полоса вкладок»), а не в top chrome страницы.
Shortcut `Cmd+,` продолжает открывать то же окно настроек.

Кнопка логотипа: подсветка в `8px` от края окна (`--chrome-edge-pad`, с
03.10.2026 общее правило иконочных кнопок хрома), SVG-область ещё на `4px`
внутри.
Штатный `Button variant="chrome" size="chrome-icon"` имеет область нажатия 24×30px
и отдельную центрированную видимую плашку 24×24px;
логотип рисуется по своей сетке 8×5 пикселей знака: один пиксель знака
`1.5px`, это три физических пикселя при 2x, поэтому все края знака лежат на
целых пикселях экрана и не размываются. Знак 12×7,5px в коробке 12×8px
(`viewBox="0 0 800 500"`, `preserveAspectRatio="xMidYMin meet"`): коробка
целая, плашка ставит её на целый пиксель, знак прижат к её верху, на полпикселя
выше середины плашки. Размер задан на самом SVG: правила кнопки для значков
(13px для любого SVG без класса размера, 16px для не-lucide) перевели бы
сетку мимо физических пикселей.

Размер выбран замером в WebKit при 2x на настоящей кнопке (07.10.2026, жалоба
пользователя: логотип выглядел меньше соседних значков). До правки базовое
правило кнопки сжимало SVG логотипа до 13px вместо задуманных 16px: знак
выходил 10,4×6,5px с размытыми краями (клетка 2,6 физического пикселя).
Соседние значки (`Settings2`, `Columns2`, `Plus`, `X`, `Search`,
`ChevronLeft`) занимают рамки от 5×8 до 11×11px, медиана среднего
геометрического сторон 9,5px, закраска от 40 до 185 физических пикселей
(у `Settings2` рядом 121). Новый знак: рамка 12×7,5px (среднее
геометрическое 9,5px, ровно медиана), закраска 153, ни одного частично
закрашенного пикселя. Соседний шаг сетки, 2px на пиксель знака (16×10px),
дал бы закраску 272, больше любого значка хрома в полтора раза; 1,75px
размывает края. При экране 1x пиксель знака 1,5px неизбежно сглаживается.
`currentColor` наследуется от общего Button: muted в покое, foreground при
hover/open/focus; собственного цветового класса у SVG нет. Белой подложки нет.
Hover/open/keyboard focus используют
`state-active`, как остальные меню chrome. Dropdown выровнен вправо и использует
штатную ширину `command`; список разделов общий с окном Settings. Кнопка
остаётся последней справа при открытой карточке и скрытом bottom bar.

Иконки действий chrome используют тот же вариант Button: область 24×30px,
плашка 24×24px, иконка lucide 13×13px с линией 1px. Кнопка `Display` ленты
([SPEC_FEED_DISPLAY.md](SPEC_FEED_DISPLAY.md), Д1) стоит во втором уровне под
логотипом в собственной `ChromeActions`: правая половина строки держит только
левый отступ `--main-secondary-pad-x`, правый край отдан `ChromeActions`, и ось
кнопки совпадает с осью логотипа.
`ChromeActions` задаёт промежуток 4px и общий правый отступ
`--chrome-edge-pad` (8px). Ось Close второго уровня совпадает с осью
логотипа сверху. В компактном режиме группа действий перед логотипом не
дублирует краевой отступ. Classic detail header также использует `ChromeRow`
и отдельный Separator; локальные размеры кнопок и компенсации запрещены.

Sidebar search (`Shift+Cmd+F`) живёт в левом сегменте top chrome. Порядок:
space selector, separator `w-px bg-border`, search input, затем штатный
`border-r border-sidebar-border` между Sidebar и Main. Резерв светофоров и
кнопка бокового меню с 03.10.2026 стоят в полосе вкладок над этим рядом
(раздел «Полоса вкладок»).

Все chrome-строки используют один `ChromeRow`: permanent header (включая
загрузку пространства и Settings), secondary row сверху/снизу и bottom action
bar. Свободная область содержимого **30px** (`--chrome-row-content-height`),
hover-плашка **24px**, отступы **3px сверху и снизу**. Это выбранная геометрия
дизайн-системы, не компенсация размеров AppKit. Для элементов другой высоты
центрирование остаётся тем же. `Separator` 1px — отдельный соседний элемент
в потоке, снизу у верхних панелей и сверху у нижних; внутри 30px линий нет.
Кнопки и сегменты переключателей chrome используют `ChromeControl`: область нажатия
занимает 30px строки, независимо от размеров видимой плашки. `ChromePlate`
отделяет визуальную геометрию от hit target; существующие handlers/ref остаются
на одном интерактивном элементе, вложенных кнопок нет. Правило распространяется
на text triggers, логотип/More/Close/очистку поиска, облачное меню, действия
нижней панели в обоих оформлениях. Read-only подсказки клавиш не превращаются
в кнопки. Для переиспользуемого ActionButton режим задаётся явно через
`chrome`; вне chrome геометрия прежняя, включая клиппер. Сегменты пилюли
(`Grid / Graph`) это сами вкладки Radix высотой с пилюлю, без обёртки
(«Пилюля»).

Dropdown отступает на штатные 4px от полноразмерного trigger: после соседнего
разделителя 1px остаётся 3px. Отдельные поправки для меню логотипа запрещены.
При нехватке места Radix сохраняет штатные collision/flip ограничения.
Отступы ленты и поведение прокрутки этим правилом не затрагиваются.
Регрессия геометрии и взаимодействий: `bun run test:chrome` — изолированный
браузер, production-компоненты/CSS, светлая/тёмная темы, 1x/2x, верхний и нижний
варианты metadata. Проверяются зазоры меню, границы hit targets, сохранение
плашек/иконок, клики вне плашек, оба вида нижних действий и вызов drag IPC.
Одна граница рисуется один раз. `ChromeShell` владеет внешними верхней/нижней
границами 1px: системное оформление окна не отнимает место у содержимого
строк. Эти границы остаются и без native frame, в том числе в fullscreen.
Оформление нативного окна не меняется; индивидуальные translate/padding
поправки для строк и кнопок запрещены. При двух верхних строках нижняя линия
второго уровня поднимается на 1px; положение плашки первого уровня сохраняется.
Страница вкладки внешней верхней границы не рисует (`ChromeShell
topEdge={false}`, 03.10.2026): над ней стоит полоса вкладок, и нижний
разделитель полосы служит швом между полосой и первым рядом страницы; вторая
линия удвоила бы его. Окно настроек и страницы вне вкладок рисуют обе границы.

Permanent top chrome использует `bg-chrome`, промежуточный surface между
`bg-background` и `bg-accent`. Это оставляет активному search surface следующий
видимый уровень заливки: когда query непустой, search wrapper получает
`bg-accent`, а остальной header остаётся `bg-chrome`.
Traffic-light reserve (`80px`) не остаётся прозрачным spacer'ом: он получает
тот же surface class, что и хром вокруг него (`bg-chrome` в полосе вкладок и в
окне настроек). Цвет фона нативного окна задаёт бэкенд (03.10.2026,
SPEC_TABS.md, В25): страница сообщает цвет поверхности хрома `#rrggbb`,
вычисленный из её CSS-токена, командой `report_window_surface`
(`useNativeWindowChromeSurface`), бэкенд красит все окна вкладок
(`NSWindow.backgroundColor`) и хранит цвет в `windows.json`, чтобы следующий
запуск красил окно до загрузки страниц. Так AppKit titlebar area не
просвечивает чужим цветом поверх overlay titlebar. Собственный фон страниц
выключен (`drawsBackground = NO`, В26): до первого кадра страницы виден цвет
хрома, а не белый.
Сами native traffic lights не стилизуются CSS, не перекрашиваются через webview
и не получают custom alpha/state machine из Rust. На macOS desktop это всегда
настоящие AppKit standard window buttons, а inactive gray, hover color,
обводка, disabled/active state и click behavior полностью остаются системными.
Frontend только резервирует `80px` зоны и сообщает бэкенду цвет хрома, чтобы
системные кнопки лежали на корректной поверхности.
Fake traffic lights, outline/обводка кружков, ручная отрисовка кнопок и
programmatic hide/show настоящих кнопок запрещены.

Theme selector обязан синхронизировать не только web theme (`data-theme` +
`color-scheme`), но и native AppKit appearance через Tauri `setTheme()`:
`Light` → `setTheme("light")`, `Dark` → `setTheme("dark")`, `System` →
`setTheme(null)`. Это не перекрашивает traffic lights вручную, а переводит
системные кнопки, меню и native chrome в ту же light/dark appearance, что и
приложение. Произвольный цвет traffic lights по-прежнему запрещён.

Когда sidebar collapsed, top chrome не схлопывается до `0px` и не держит
пустой слот под исчезнувший поиск. Левый segment сжимается до реального
содержимого: intrinsic width space selector. Резерва светофоров и кнопки
бокового меню в ряду страницы вкладки нет с 03.10.2026: они в полосе вкладок.
Channel search скрывается, а правая часть top chrome с current collection
switcher начинается сразу после compact collapsed segment. Collapsed layout
строится только CSS intrinsic sizing: левый segment получает
`w-auto max-w-[240px]`, и `VaultSwitcher` в collapsed mode получает тот же
предел `max-w-[240px]`, потому что он единственное содержимое сегмента. JS
measurement, hidden probe и вычисление ширины по уже обрезанному visible
trigger запрещены.

#### Иконочные кнопки хрома

Одно правило для всех иконочных кнопок в рядах хрома, при высоте ряда 30 px и
40 px одинаковое (решение пользователя 03.10.2026, после разнобоя в 2, 4, 6, 8 и
12 px и неудачной пробы 12 px):

| Что | Значение |
|---|---|
| Кнопка | `Button variant="chrome" size="chrome-icon"`: подсветка 24×24, значок 13 px |
| По вертикали | подсветка по центру содержимого ряда |
| От границы до подсветки | `8px` (`--chrome-edge-pad`): край окна, линия колонки, линия вкладки; то же внешнее поле, что у подсветок текста (`Mine`, `Everything`), и то же, что у кнопок `Connect` в строках таблицы |
| Между соседними кнопками | `4px` (`gap-1`) |
| Подсветка | при наведении; в ряду фильтра над таблицей `+` новой коллекции объёмный (`Button plate="raised"`, «Объём кнопки»; решение пользователя 04.10.2026 вместо постоянной плоской подсветки); крестик очистки поля такая же кнопка хрома, с подсветкой при наведении (решение пользователя 05.10.2026; исключение «без подсветки, светлеет только значок» от 03.10.2026 снято) |

Так стоят: кнопка бокового меню, `Back` и `Forward`, крестик вкладки, `+` новой
вкладки и логотип в полосе вкладок; крестик очистки, индикаторы и `+` новой

#### Сжатие ряда фильтра

Ряд над таблицей бокового меню (имя пространства, поле `Find collections`,
индикаторы, `+`) при нехватке места уступает его (решение пользователя

строку при перетаскивании края меню): на стадии `name` имя пространства
сужается до `--row-fit-name-min` (`120px`). Поле и `+` не уходят никогда.

Ряд берёт `full`, пока полю остаётся не меньше `72px`, иначе `name`. Стадию
меряет вёрстка, а не расчёт (`useSidebarRowFit.ts`, как у нижней панели):
стадия пробуется через атрибут `data-row-fit` на самом ряду, стили отвечают
атрибуту.

Стадия, на которой поле сворачивалось в кнопку с лупой, удалена 07.10.2026
по решению пользователя: она не срабатывала никогда. Замер в WebKit на
минимальной ширине меню `314px`, с длинным именем пространства, обоими
индикаторами активности и запросом в поле (кнопка очистки видна), ряды 30 и
40, обе темы: на стадии `name` поле `94px`, без запроса на `full` `85.5px`.
Стадия со значками вместо подписей ушла раньше в тот же день вместе с
фильтром `All / Connected`.

Ряд меряется заново при смене содержимого и при каждой смене своей ширины.
Ширину сообщает `ResizeObserver`, подключённый к ряду в момент его появления
на странице (ref-обратный вызов хука), а не при первом рендере: ряд
приложения появляется позже, когда пространство откроется. Открываясь, верхний
сегмент бокового меню растёт от `0` до своей ширины за `200ms`, поэтому замер
в момент открытия видит ряд нулевой ширины и берёт `name`; наблюдатель ведёт
ряд кадр за кадром до конечной ширины. В скрытой вкладке и свёрнутом окне
переход ждёт показа страницы, и стадия догоняет ширину тогда же. До
04.10.2026 наблюдатель не подключался вовсе: после открытия меню ряд
оставался на стадии, взятой при нулевой ширине, до следующей смены содержимого и не отвечал на
перетаскивание края меню.

#### Объём кнопки

Залитые кнопки (`default`, `destructive`, `raised`) это высота: лицевая
сторона по закону высоты и края по рецепту стиля кнопок. Правила живут в
[buttons.css](</Users/i_iii/Проекты/Личные проекты/local-arena/.claude/worktrees/youtube-referer/src/styles/buttons.css>),
закон в своде
[SPEC_COLOR_RULES.md](</Users/i_iii/Проекты/Личные проекты/local-arena/.claude/worktrees/youtube-referer/SPEC_COLOR_RULES.md>)
(раздел 3.3, постоянная К10).

**Лицевая сторона, одна для всех стилей.** Считается на самом носителе от
того, что под ним (`--surface`). В светлой теме она строится как подложка
наведения: зона со слоем состояния `--active` поверх (на странице 245, на
карточке и хроме 240, на нижней панели 235). В тёмной теме она на 3 шага зоны
(0.09) ярче того, что под ней (на странице 29, на нижней панели 43, на
плавающем слое 36). Числа задают токены тематических блоков
`--button-face-step` (0 и 0.09), `--button-face-layer` (слой `--active` и
`none`) и `--button-face-share` (`--active-alpha` и `0%`, доля слоя, когда лицо
нужно одним цветом). Та же лицевая сторона у выбранного сегмента
переключателя (`bg-component-fill-inner`): macOS рисует выбранный сегмент
приподнятой кнопкой.

**Наведение это слой состояния поверх лица.** Наведение, открытое меню
кнопки и выбранная клавиша нижней панели (`data-selected`, `state-active`)
кладут `--active` поверх лицевой стороны: лицо остаётся, слой лежит над ним,
поэтому кнопка одинаково отвечает на любом фоне. Текст и значок, тусклые в
покое (кнопки карточки, значки кнопок хрома), при этом поднимаются на
основную ступень, как у любой кнопки при наведении (SPEC_COLOR_RULES.md,
3.6; решение пользователя 07.10.2026); текст, который и в покое на основной
ступени, не меняется. Кнопка не поднимается и не опускается, анимации нет. Выключенная кнопка и
подложка внутри неё наведения не получают. Одно правило для всех носителей
объёма: кнопки, подложка кнопки хрома `+`, плашки Connect и клавиши
нижней панели.

**Края: три стиля кнопок.** Стиль выбирается для каждого окна отдельно:
меню логотипа в полосе вкладок › Buttons (macOS, Retro, Linear) или ⌃⌥B
(команда `flip-buttons`, по кругу macOS, Retro, Linear). Полоса вкладок
хранит выбор по идентификатору окна, применяет его к себе и рассылает своим
вкладкам; вкладка, перенесённая в другое окно, берёт стиль этого окна; после
переключения видимая вкладка окна на миг показывает уведомление
«Buttons: Retro». Новое окно и окно настроек рисуют macOS. Стиль ставит на
корень атрибут `data-buttons="retro"` или `"linear"`; у macOS атрибута нет.
Модуль `src/lib/buttonStyle.ts`, уведомление
`src/components/ButtonStyleNotice.tsx`.

| macOS (по умолчанию) | обводка `0.5px` внутри кнопки на 1½ тихого шага линии ярче лица (в светлой теме ΔL 0.045 темнее, в тёмной 0.0643 светлее; полшага добавлены ради читаемости 07.10.2026), больше ничего: ни нижнего края, ни блика, ни тени, обводка ровная по всему контуру; при наведении она считается от лица со слоем состояния и поднимается вместе с ним | вспышка `--press`, без сдвига |

#### Нажатие

Стиль кнопок macOS (решение пользователя 05.10.2026): кнопка при нажатии не
опускается, а мигает. Пока её держат, лицо уходит дальше подложки наведения
ещё на половину слоя состояния (`--press`, половина `--active-alpha`), обводка
следует за лицом; отпускание возвращает вид наведения. Так же мигают плоские
подложки иконок и надписей в хроме (`[data-chrome-plate]` в
`[data-chrome-control]`) во всех стилях кнопок. Мгновенно, без перехода, как
наведение. Правило вспышки macOS живёт в `buttons.css`. Ниже правило сдвига
для стилей Retro и Linear (раздел «Объём кнопки»).

Переключатели пространства и коллекции с шевроном не мигают: нажатие
показывает только поворот шеврона, подложка горит, пока меню открыто, и не
гаснет при закрытии повторным нажатием, пока указатель над ней
(`useMenuTriggerPointerInside`, решение пользователя 06.10.2026).

В стилях Retro и Linear нажатие опускает на `1px` только объёмную кнопку, и
все объёмные без исключений (решение пользователя 04.10.2026, вместо прежнего
«любая кнопка, кроме открывающих меню и переключателей»). Объёмная значит носитель
`.button-depth`: варианты `default`, `destructive` и `raised`, в том числе
открывающие меню (⋯ на карточке, Connect), плашка Connect, подложка `+` и лупы
у кнопок хрома (опускается подложка, а не область нажатия), клавиша нижней
панели (опускается клавиша при нажатии на пару). Ничто другое не нажимается,
не вдавливается и не опускается: иконочные кнопки хрома с плоской подложкой,
`ghost`, `secondary`, `link`, вкладки, `Switch`, сегменты, пункты меню,
строки, карточки. Недоступная объёмная кнопка не движется. Одно правило в
`global.css` вне слоёв, рядом с объёмом; сдвиг сделан через `transform`,
поэтому плашка Connect, отцентрированная через `translate`, остаётся на месте
и опускается на `1px`. Замер в WebKit: `default`, `raised` с меню, подложка
`+` и клавиша нижней панели опускаются на `1px`; `secondary`, `ghost`,
кнопка хрома и вкладка хрома стоят на месте.

#### Недоступно

Один вид недоступного для всех контролов в обеих темах (решение пользователя
04.10.2026), и он берётся от того, что под контролом:

- заливки и объёма нет; контрол с телом (залитые `default`, `destructive`,
  `raised`, плашка Connect, клавиша нижней панели, `secondary`) показывает
  только рамку 1px внутри края, `--inert-frame`: поверхность под контролом,
  сдвинутая по L на один тихий шаг, `−0.03` в светлой теме и `+0.0429` в
  тёмной. Рамка это сигнал линейной формы: тёмный сдвиг выведен законом из
  светлого, `0.03 / 0.7`;
- текст и значок берут третичную ступень (`--tertiary-foreground`);
- наведения, подсветки и нажатия нет.

Рамка берётся от поверхности, а не от линии `--border`: одна краска линии на
разных подложках отстоит по-разному (в тёмной теме +21 на боковом меню и +10
на нижней панели), и одинаково выключенные контролы выглядели бы разными.

Справочные записи (вариант `reference`: `Switch collection`, `Navigate` в
нижней панели, неизменяемые сочетания в настройках, пилюля `Connected` в
боковом меню, SPEC_CARD_STATES.md, С4 и С5) недоступными не считаются (решение
пользователя 04.10.2026): то, что они называют, работает. С недоступным их
роднит только рамка `--inert-frame`, общая для всего, что нажать нельзя;
текст у них второстепенный, у недоступного третичный. Так третичная ступень
значит одно: «сейчас недоступно». Прозрачность всего контрола (`opacity-50`)
больше не применяется: она гасила по-разному то, что было разной яркости, и давала
несколько разных «выключенных» (основной текст кнопки, вторичный значок
хрома). Правило для объёмных носителей живёт в `global.css` вне слоёв, для
остальных в базовом классе `Button`, вариантах `reference` и `secondary`, в
пунктах меню, сегментах и вкладках хрома.

Расчёт по закону, пилюля `Connected` на боковом меню против записи
`Switch collection` на нижней панели: рамка 243 на 253 и 235 на 245 (−10 и
−10) в светлой теме, 20 на 11 и 32 на 22 (+9 и +10) в тёмной; текст у обеих
второстепенный, одна доля расстояния до основного цвета. Выключенные
`Button`, кнопка хрома и пункт меню дают тот же вид: третичная ступень 191 на

#### Подсказки

Кнопка без текста (`Button` размеров `icon`, `icon-xs`, `chrome-icon`)
называет себя подсказкой из `aria-label` через `500ms`, следующие открываются
сразу, пока указатель идёт по кнопкам. Подсказка это плавающий слой на
`--popover` (рамка, тень, радиус `3px`), без хвостика; если у действия есть
сочетание клавиш, оно стоит справа (`shortcut`), но только если оно
срабатывает именно на эту кнопку: у ⋯ на карточке в ленте ⌘K нет, он
открывает меню карточки с фокусом клавиатуры, а не той, что под указателем.
В полосе вкладок подсказок нет: её страница высотой в ряд, подсказку обрезало
бы. Подсказка стоит под контролом, как в macOS (решение пользователя
04.10.2026); у нижнего края окна Radix переворачивает её вверх. От краёв
окна она держит `8px`, как всякий всплывающий слой Radix (раздел «Всплывающие
элементы»).

Нажатая кнопка подсказки не показывает (решение пользователя 07.10.2026: «В
уже нажатом переключателе не должно быть подсказки»). Нажатая значит
переключатель во включённом положении (`aria-pressed="true"`,
`data-state="on"`) или кнопка, которая держит открытым своё меню, поповер или
выбор (`aria-expanded="true"`, `data-state="open"`): то, что подсказка назвала
бы, уже перед человеком. Подсказка, открытая в момент нажатия, закрывается и
после отпускания кнопки сама не возвращается, снова её приносят указатель или
фокус. Правило живёт в `Button` (`src/components/ui/button.tsx`), поэтому
касается каждой кнопки с подсказкой: `+` Connect и ⋯ Card actions на карточке
и в строке поиска, Display options, Mine settings, меню выбранных карточек,
Media actions в Detail. Управляемые подсказки-сообщения (отказ в имени при
переименовании) это не подсказки кнопки, правило их не касается.

#### Иконка рядом с текстом

Иконка lucide `13px` нарисована в середине своего квадрата: у уголка
`ChevronRight` примерно по `4px` пустого места слева и справа внутри квадрата.
Когда такая иконка стоит в подсветке после текста, её пустые поля заменяют
часть отступов, иначе промежуток и правый край на глаз вдвое шире задуманного
(замечание пользователя 03.10.2026: «Mine >» с пустым правым краем). Правило:
промежуток между текстом и иконкой `0`, правое поле подсветки `4px` вместо
`8px` (`pl-2 pr-1`). На глаз текст отстоит от левого края на `8px`, уголок от
текста на `4px` и от правого края на `8px`. Размер иконки не меняется.

Space selector — это top-chrome вариант `VaultSwitcher`: `h-full`,
`max-w-[50%]`, `flex-none`, `min-w-0`, `px-[var(--top-collection-pad-x)]`, `rounded-0`,
`font-mono text-sm text-muted-foreground`, `truncate`; без folder icon. С
03.10.2026 по решению пользователя у него есть dropdown chevron: lucide
`ChevronRight` `13px` внутри inner pill сразу после имени, цвет текста pill,
поэтому подсвечивается вместе с именем (`MenuTextTrigger showChevron`). Поля
pill со стрелкой `pl-2 pr-1` и промежуток `0` (раздел «Иконка рядом с
текстом»). В закрытом состоянии смотрит вправо, при
открытии меню поворачивается вниз за `150ms`, как в клиппере. Root trigger не заливается и не рисует отдельную обводку: он
только задаёт layout slot. Ширина
подстраивается под имя текущей папки, но не может занять больше половины
доступной search/space зоны. В collapsed sidebar state, когда search скрыт,
ограничение меняется на `max-w-[240px]`, а сам segment shrink-wrap'ится по
intrinsic width selector, чтобы справа не оставалось пустой ячейки. Короткое
имя (`Mine`, `Тест`) обязано отображаться полностью; ellipsis допустим только
для длинных названий, которые превышают collapsed selector cap.

Визуальный hover/open/keyboard-focus state принадлежит внутренней пуле вокруг
имени: `h-6 rounded-1 px-2 state-active text-foreground`. В покое текст пули
остаётся `text-muted-foreground`, как в Detail top bar; hover/open/keyboard
focus поднимает только эту интерактивную плашку до `text-foreground`. Это тот
же system hover/active token, что используется для row hover/focus в
`DropdownMenu`. Текст выровнен по левому краю через `justify-start` +
`text-left`. Space selector открывает первый ряд страницы вкладки (03.10.2026),
поэтому его левый inset равен краю хрома минус внутренний отступ пули
(`--top-collection-pad-x`, равен `--chrome-edge-pad`, 8px), как у
переключателя коллекций: пуля стоит на отступе хрома, текст ещё на её
внутренний `px-2` правее. Если имя папки не помещается, оно режется обычным end
ellipsis.
Pointer-click не должен оставлять trigger в focus-colored состоянии после
закрытия dropdown: top chrome triggers используют общий interaction hook,
который различает pointer и keyboard open. После pointer-close Radix
auto-focus на trigger отменяется и trigger blur'ится; после keyboard-close
focus возвращается на trigger и сохраняет keyboard-focus fill.
Pointer-drag не открывает dropdown: trigger defers Radix pointer-open до
обычного click. Если жест пересёк drag threshold, click подавляется и меню не
появляется.

Space dropdown не показывает текущий space повторно и не использует checkmark
или другие selected markers. Внутри есть `Search spaces` input, список только
destination spaces и два pinned action под разделителем: `Reveal in Finder`
(`FolderOpen`) и `Add space` (`FolderPlus`), именно в этом порядке. Оба несут
иконку в leading slot (`MenuIconSlot`, 13×13px) слева от текста; строки
destination spaces и placeholder `No other spaces` получают тот же слот пустым,
чтобы текстовая колонка меню была одна. `Reveal in Finder` действует на текущий
space, а не на строку, и закрывает меню — окно уходит в Finder, и оставленный
позади dropdown был бы забытым состоянием. Per-row reveal, наоборот, меню не
закрывает: оттуда пользователь может открыть несколько папок подряд. Порядок
стрелочной навигации повторяет визуальный: spaces, `Reveal in Finder`,
`Add space`. Rows ниже input — menu-styled buttons с `role="menuitem"`; hover
может менять active row, но не забирает DOM focus из input.

Icon actions строки пространства (`FolderOpen` — reveal, `X` — forget) обязаны
нести tooltip: иконка без подписи внутри списка не объясняет себя, а цена
ошибки здесь несимметрична. Тексты — `Reveal in Finder` и `Remove from the list
— files stay on disk`; второй называет последствие, а не действие, потому что
именно эту команду читают как «удалить папку». Ширина dropdown — floating width role `selector`
(`18rem` с available-width cap), а не ширина trigger и не content-fit.
Позиционирование dropdown привязано к видимой внутренней пуле selector, а не к
невидимому root slot: Radix `align="start"` использует `alignOffset=12`, равный
root inset `px-3`.

Search input не использует иконку. Search surface — wrapper `h-8 min-w-0
flex-1`, внутри прозрачный `Input ghost` (`rounded-0 px-3 py-0 border-none`)
и опциональный clear action справа. Текст permanent top-chrome search также
использует Detail top bar typography: `font-mono text-sm
text-muted-foreground`. Search занимает весь остаток ширины после selector. При
вводе длинного query используется нативное поведение `input`: caret остаётся
видимым, поэтому пользователь видит последние вводимые символы. Пустое поле
стоит на `bg-chrome`, как весь ряд хрома, и на наведение не отвечает: подсказка
`Find or create...` всегда приглушённая, `text-muted-foreground` (решение
пользователя 05.10.2026). Когда в поле есть текст, поле получает поверхность
таблицы коллекций, `bg-sidebar`; space selector и линии остаются на
`bg-chrome`.

Clear action появляется только когда value непустой: кнопка хрома
`Button variant="chrome" size="chrome-icon"` с иконкой `X` 13 px,
`aria-label="Clear collection search"`; при наведении и фокусе у неё подложка,
как у соседних кнопок хрома (решение пользователя 05.10.2026). Кнопка стоит в 8 px от правого края
колонки (`mr-2`), на одной вертикали с кнопкой `+` во втором ряду и с кнопкой
`Connected` строк коллекций; в Compact Detail top menu отступ `mr-1`. Click
очищает query, восстанавливает полный список каналов и возвращает focus в
input. `Escape` с непустым value очищает поле; `Escape` с пустым value снимает
focus.

`Enter` в `Find or create...`, когда стрелками не выбрана ни одна строка,
действует на набранное имя (trimmed). Коллекция с таким именем, без учёта
регистра, открывается. Иначе создаётся новая коллекция с этим именем по
правилам раздела «Создание коллекции», а фильтр очищается, чтобы список показал
её первой. Пустое поле `Enter` не обрабатывает.

Top-chrome search inputs use input-owned keyboard navigation. `ArrowUp` /
`ArrowDown` change `aria-activedescendant` and the visual active row; DOM focus
stays in the input so the user can keep typing. This applies to Sidebar channel
search, `Search spaces` and `Search collections`. `Enter` activates the active
row. Строка создания коллекции в навигацию поиска не входит: это не результат
фильтра. Pointer hover can update the active row but must not blur the input. Все
search inputs отключают нативные подсказки ввода через общий
`SEARCH_INPUT_SUPPRESSION_PROPS`: `autoComplete="off"`, `autoCorrect="off"`,
`autoCapitalize="none"`, `spellCheck={false}`. Это относится к top chrome,
space/collection dropdowns и channel connect pickers; обычные поля ввода вроде
rename/create остаются самостоятельными.

Right collection switcher живёт в правом top chrome segment и показывает
текущую Grid route collection: `Everything` или имя текущего канала. Геометрия
повторяет space selector: root slot `h-full min-w-0 max-w-[50%] flex-none
rounded-0 bg-transparent font-mono text-sm text-muted-foreground`, с тем же
dropdown chevron внутри pill, что у space selector; root padding
`px-[var(--top-collection-pad-x)]` (8px) при открытом и свёрнутом боковом
меню. Отдельный узкий режим `px-3` убран 03.10.2026 по замечанию пользователя:
он остался со времён, когда space selector имел поля по 12px, и при свёрнутом
меню давал 20px до имени вместо 16px.
Hover/open/keyboard-focus рисует только inner pill
`h-6 rounded-1 px-2 state-active text-foreground` вокруг имени. При клике
открывается обычный `DropdownMenu` со search field `Input ghost` и пунктами
коллекций в том же порядке, что Sidebar. Текущая коллекция не дублируется в
списке вообще: нет checkbox/radio/check icon, нет selected row, нет disabled
current item. Search input остаётся единственным focus owner внутри dropdown:
hover по destination rows не переводит фокус с input на строку. Строки ниже
input — menu-styled action buttons с `role="menuitem"`, а не roving-focus
`DropdownMenuItem`. Внизу всегда закреплена строка `Create collection`; она не
является search result и не меняет текст на `Create "{query}"`. Нажатие
закрывает dropdown и открывает отдельный create-channel dialog; dialog может
prefill'иться текущим query, валидирует пустые/дублирующиеся имена, вызывает
штатный channel create command, обновляет taxonomy/grid snapshots и переводит
route в новый канал. Ширина dropdown — floating width role `selector` (`18rem`),
такая же как у Space dropdown.
Позиционирование dropdown привязано к видимой внутренней пуле collection
trigger. Radix `alignOffset` равен левому полю root, измеренному при открытии
(`getComputedStyle(...).paddingLeft`), а не записанному числом. Dropdown не
может выпадать от невидимого layout slot, даже если slot шире видимой пули.

Compact Detail top menu — экспериментальная настройка Settings
`Compact Detail top menu`. Настройка заранее переводит right top chrome в
compact geometry: collection switcher использует `px-3` уже на главной
странице, поэтому `Everything`/название текущего канала не меняет X-position
при открытии и закрытии Detail. Permanent top chrome всегда остаётся
`bg-chrome`; открытие Detail не меняет его surface. Внутренний Detail top bar и sidebar
`Collections:` bar не рендерятся. Переключателя `All / Connected` нет
(убран 03.10.2026, удалён из кода 07.10.2026). Правая
часть top chrome начинается с того же кликабельного collection switcher, затем
показывает название карточки, overflow `…`, close `X`.

Открытая карточка в пути названа именем своего файла без папки и `.md`: это
имя меняет переименование (решение пользователя 05.10.2026). Название не
перетаскивается. Двойной клик превращает его в поле прямо в пути: подложка
наведения остаётся, пока это поле. Уход из поля сохраняет имя (Enter тоже),
Escape оставляет старое; кнопки сохранения нет. Пока набранное имя было бы
отклонено (символ из `\ : # ^ | [ ]`, точка в начале, имя занято), причина
стоит красным текстом в подсказке прямо под именем. Отклонённое сохранение
коротко трясёт поле из стороны в сторону (320 мс, `name-refused`). После
Enter поле остаётся с курсором и набранным именем, чтобы его можно было
поправить. После ухода из поля возвращается прежнее имя, а причина держится
под ним ещё 2,5 с. Принятое имя закрывает поле. Название не является
`data-tauri-drag-region`: окно таскается за пустые участки top chrome.

Переименование коллекции в боковом меню показывает кнопку `Save ↵` в правой
зоне строки, как строка создания показывает `Create ↵` (05.10.2026).

Название коллекции в боковом меню меняется и задаётся так же, как имя
открытой карточки в пути (решение пользователя 05.10.2026), и в строке
переименования, и в строке создания. Пока имя набирается, причина отказа
стоит красным текстом в подсказке прямо под строкой: пустое имя, символ из
`\ : # ^ | [ ]`, точка в начале, слишком длинное имя, папка в имени,
коллекция с таким именем (регистр букв не важен), файл с таким именем в папке
коллекции. Отклонённое сохранение коротко трясёт поле (320 мс,
`name-refused`). После Enter или кнопки `Save ↵` (`Create ↵`) поле остаётся с
курсором и набранным текстом. После ухода из поля возвращается прежнее имя
(строка создания закрывается), а причина держится на месте строки ещё 2,5 с.
Принятое имя закрывает поле.

Геометрия Compact Detail top menu:

- Height: `h-8`, как permanent top chrome.
- Surface: всегда `bg-chrome`. Это жёсткий permanent app chrome surface; он не
  переходит в `bg-accent` при открытии Detail. Активный search по-прежнему
  получает `bg-accent`, поэтому остаётся следующим уровнем заливки над ordinary
  chrome.
- Spacing: только compact axis `px-3`; правые `px-6`, `px-8` и любые 32px
  content-axis insets запрещены во всём режиме настройки, включая main/Grid
  state до открытия Detail.
- Segmented control: `h-6 p-[2px] rounded-1 font-mono text-sm`, segments
  `h-5 px-[1ch] rounded-[2px]`; active segment
  `bg-component-fill-inner text-foreground`, inactive
  `text-muted-foreground`. The outer pill stays transparent at rest and uses
  `state-active` on hover without changing inactive segment text. This is the same
  hover surface as dropdown rows and top-chrome menu triggers; the stronger
  `--component-fill-hover` is not used for the outer pill. Active segment fill
  is exactly the default `Button` face on the same structural surface: the
  face rule in `buttons.css` paints every `bg-component-fill-inner` carrier
  with the depth button face («Объём кнопки»).
- `Collections:` label в этом режиме запрещён.
- Текущая коллекция: штатный `TopCollectionSwitcher` в compact geometry
  (`px-3`, inner pill `h-6 px-2`). Это постоянный элемент right top chrome, а
  не часть условного Detail-блока: trigger остаётся тем же DOM/layout control
  до открытия Detail, во время Detail и после закрытия. Trigger остаётся
  кликабельным и открывает тот же dropdown коллекций; plain text label здесь
  запрещён.
- Название карточки: `font-mono text-sm text-muted-foreground`,
  `min-w-0 flex-1 truncate pl-0 pr-3`; это первый элемент, который отдаёт
  ширину. Левый padding запрещён: зазор между видимой collection pill и title
  задаёт только правый `px-3` slot самого `TopCollectionSwitcher`, иначе
  получается двойной неартикулированный отступ.
- Overflow и close: icon buttons `size-8 shrink-0`, всегда видимы. Правая
  сторона получает compact inset `pr-3`, чтобы close не упирался в край окна.

Responsive order: сначала режется название карточки, затем текущая коллекция,
затем сжимается Sidebar search в своём существующем flex slot. Overflow и
close не сжимаются. В collapsed Sidebar state channel search скрыт как
обычно.

Motion: Detail-only элементы в compact top chrome входят и выходят тем же
языком, что classic Detail chrome: `opacity + translateY` через
`detail-top-bar-enter`, а separator line — через `detail-top-bar-line-enter`.
Collection switcher, space selector, channel search и Sidebar divider не
анимируются при открытии Detail и не меняют позицию. Цвет permanent top chrome
никогда не анимируется и остаётся `bg-chrome`; Detail-only controls анимируются
через `220ms cubic-bezier(0.22, 1, 0.36, 1)`. Exit state выставляется синхронно в
close handler до очистки selected Detail state; выход должен идти тем же
motion path, что появление, без промежуточного скачка в normal top chrome.

Top chrome controls are dual-purpose. A short pointer gesture keeps the native
control action: click opens the space selector, click/focus enters channel
search. Movement beyond `4px` starts native window drag through
`useChromeDragGesture()`, which asks the backend to drag the page's window
(`start_window_drag`, SPEC_TABS.md, В23), and suppresses
the following click. This keeps the Zed-like behavior where even filled chrome
can be used to move the window without turning controls into dead drag-only
areas.

Dropdown triggers inside top chrome use `useTopChromeTriggerInteraction()`
instead of raw Radix pointer-open. Short pointer click opens the dropdown;
drag beyond `4px` starts native window drag and suppresses the trailing click,
so the menu does not flash open after the drag. Pointer-close blurs the trigger
to avoid sticky hover/focus fill, while keyboard-close restores focus for
keyboard accessibility. Reusable controls such as `CardMoreMenu` must opt into
this mode only when rendered inside top chrome; card-local menus keep their
normal card interaction contract.

  hover `bg-component-fill-hover text-foreground`) при непустом query.
- Список результатов: строки `rounded-1 px-2 py-1.5`, flex с миниатюрой слева —
  стандартный `MicroPreviewThumbnail` в слоте `size-8 shrink-0 overflow-hidden
  bg-component-fill` (text-миниатюры получают `dark:invert`). Строка это
  общий компонент `CardRow`, его же показывает Related notes открытой
  карточки (07.10.2026). Текст строки всегда в одну строку
  (с 06.10.2026, образец: поиск Notion): `span` `flex items-baseline gap-1
  font-sans text-base`, шрифт и размер строк коллекций бокового меню; все
  строки высотой 44 пикселя. Сначала имя файла `text-foreground truncate`,
  вес 400, следом на той же строке текст заметки `text-muted-foreground
  truncate flex-1` с многоточием у правого края. Знака между ними нет, только
  зазор 4 пикселя и цвет. При тексте имя берёт не больше 75% строки, текст
  получает остаток; без текста имя занимает всю строку. Начало текста,
  повторяющее имя, скрыто: текст идёт с первого нового слова, а при полном
  повторе строка показывает одно имя. Если обрезка имени прячет отметку
  совпадения, имя сохраняет начало и через многоточие показывает слова перед
  отметкой. Правила среза и окна: SPEC_SEARCH_OVERLAY.md, «Список
  результатов». Активная строка `state-active`; один источник
  active state (стрелки + реальный pointermove), фокус всегда в инпуте
  (`aria-activedescendant`).
- Команды строки (с 06.10.2026): строка под указателем показывает у правого
  края в ряд кнопки карточки ленты, слева направо `Connect` (`Plus`, выбор
  коллекций), `Source` (`ExternalLink`, только при безопасном адресе) и
  `More` (`MoreHorizontal`, меню карточки). Это те же компоненты, что в
  разделе «Кнопки карточки»: `Button variant="raised" size="icon-xs"`
  (24 пикселя), зазор 4 пикселя, правый край кнопок совпадает с концом
  текста строки, по центру высоты. Кнопки лежат поверх строки, место под них
  заранее не держится; пока они видны, текст обрезается многоточием за 8
  пикселей до первой кнопки, имя при тексте не сдвигается, имя без текста
  обрезается перед кнопками. Проявление 150 мс, исчезание 100 мс
  (`--hover-intent-fade-in`, `--hover-intent-fade-out`), без подъёма.
  Стрелки, колесо и уход указателя из списка прячут кнопки. `⌘K` открывает
  меню `More` активной строки. Фон активной строки лежит на обёртке, общей
  для строки и кнопок, поэтому лицевая сторона кнопок считается от него.
  Подробности: SPEC_SEARCH_OVERLAY.md, «Команды строки».
- Подсветка — системный search mark (жёлтый текстовыделитель, см. «Search match
  mark»): различим на любом фоне строки, включая активную.
- Превью справа (`w-80 border-l border-border p-4`, `flex flex-col gap-4`) —
  две выделенные зоны. Зона карточки: `ReadOnlyCardPreview` шириной 288 px
  без тени, та же карточка, что в ленте, в итоговом виде наведения и без
  активных элементов (с 06.10.2026, «Hover Preview Surfaces» ниже,
  SPEC_CARD_STATES.md, С10); при поиске она подсвечивает совпадение так же,
  как карточка ленты. Поверх превью ничего не лежит: команды карточки живут
  в строках списка. Зона метаданных: язык metadata-card Detail
  (`rounded-1 border border-border bg-accent`, строки — общий `MetadataRow`):
  Date, Type, Source (домен, кликабельный `MetadataLinkValue`), Author,
  Collections (lazy, оптимистичное обновление при Connect); пустые строки
  скрываются.
- Пустые состояния: пустой query → пустые панели; нет результатов —
  центрированная `No results` (`text-sm text-muted-foreground`). Спиннеров нет.

Search match mark (карточки и список Search Overlay):

- element: `mark` или inline `span`;
- typography наследуется от родительского title/excerpt;
- background: `bg-search-mark` — настоящий текстовыделитель (жёлтый), один из
  немногих хроматических акцентов системы (как destructive). Серые токены для
  маркера запрещены: индикатор совпадения обязан контрастировать с любым фоном
  строки, включая `state-active` активной строки списка;
- text: `text-search-mark-foreground` — фиксированные тёмные чернила в обеих
  темах (на жёлтом текст всегда тёмный);
- значения: `rgb(255 255 0)` в обеих темах, маркер macOS
  `findHighlightColor` целиком (К12 в своде цвета); чернила `oklch(0.145 0 0)`
  (основной цвет светлой темы, на жёлтом 18.4:1);
- radius: none;
- horizontal padding: `p-0`;
- no border, no underline.

Prefix search подсвечивает только введённый префикс: `memo` в слове `memory`
даёт mark вокруг `memo`, а не вокруг всего токена. Чтобы после mark не
появлялся ложный визуальный пробел, frontend режет excerpt по Unicode-символам
и не вставляет дополнительных separator nodes, padding или rounded caps вокруг
подсветки. Search mark не должен менять метрики текста.

Article/social-card body match excerpt uses normal card preview typography and
clamps to the same 2-3 line footprint as the regular article/social preview.
Search mode may replace preview text only while the query is active; clearing search restores
normal preview rendering.

Semantic-only search excerpts use the same preview typography but do not use
`mark`: highlight is reserved for real lexical/alias/fuzzy text ranges.
Author and URL matches are searchable metadata only: they can return a card
from search, but they do not replace card preview text, do not reveal hidden
URL text and never render `mark`.

### GraphLink

Graph использует геометрию линии как семантический маркер, не вводя новые
цветовые токены:

- membership коллекции — прямая сплошная линия текущего `linkDefault`;
- wikilink и related note — изогнутая пунктирная линия того же цвета и толщины;
- пунктир сохраняет экранный ритм `4px / 4px` при любом zoom;
- wikilink использует curvature `0.14`, related note — `0.20`;
- направление изгиба стабильно для пары нодов, а directed arrow остаётся
  частью semantic reference.

Hover не меняет цвет, толщину, пунктир или кривизну. Стиль связи не влияет на
physics и не является отдельным интерактивным состоянием.

### Диалог удаления — описание только по делу

Описание в `Delete element?` объясняет судьбу медиафайлов: какие удалятся вместе
с карточкой, какие останутся, потому что их используют другие карточки.

Если медиа нет, описание не выводится вовсе. Прежняя формулировка сообщала, что
удалится «только элемент» — она отвечала на вопрос, которого никто не задавал, и
порождала новый: а что ещё могло удалиться. Для доступности остаётся скрытый
текст, потому что диалог обязан иметь описание.

### DropdownMenu

`DropdownMenuTrigger > DropdownMenuContent > DropdownMenuItem`.

Content: `rounded-1 border bg-card p-1 text-card-foreground` в разметке, но стоит на `--popover`: правило в `global.css` ставит меню и подменю фон и `--surface` плавающего слоя (раздел «Поверхности»); тень единая для всплывающих элементов (см. «Всплывающие элементы»).

Width follows one rule for every menu, submenu and context menu
(`[data-floating-menu]`, «Всплывающие элементы»; 07.10.2026): the longest
row, from 128px to 300px; a list with a search field holds its opening width
while the query narrows it. The former width roles (`command`, `selector`,
`picker`, `widthRole`) are gone. Raw `w-64` / `w-72` in feature components is
invalid.

Выбор из нескольких значений (`DropdownMenuRadioItem`, `ContextMenuRadioItem`)
не сдвигает текст на `pl-8` и не рисует кружок: текущий пункт несёт галочку
`Check` 13px в обычном `MenuIconSlot`, у остальных слот пустой, как в меню
macOS. Текстовая колонка совпадает с остальными строками меню. Подпись группы
выбора повторяет заголовок меню выделения: `px-2 py-1.5 font-mono text-sm
text-muted-foreground`; группы разделены `DropdownMenuSeparator`. Меню, где
выбор применяется сразу, остаётся открытым (`onSelect` с `preventDefault`).
Первое такое меню: `Display` ленты.

Trigger ignores modified opening keys: `Cmd`/`Ctrl`/`Alt` +
`ArrowDown`/`ArrowUp`/`Enter`/`Space` must not open a dropdown. Those
combinations remain app/global shortcut candidates even when DOM focus is on a
hidden or hover-only trigger.

### Card Hover Menu

При hover на карточку появляются кнопки сверху и ряд коллекций снизу
(итоговый вид выбран пользователем 02.10.2026, SPEC_CARD_STATES.md, С8.8 и
С8.9). Карточка при этом не затеняется и не меняет рамку. Слой
`[data-card-hover-overlay]` остаётся носителем кнопок, его фон
`--card-hover-overlay` прозрачен в обеих темах.

**Кнопки:** стандартные `Button variant="default" size="icon-xs"` (24px,
`bg-component-fill`, `rounded-1`), иконка 13px с линией 1px. Адаптируются к
теме автоматически.

**Расположение:**
- **Сверху справа** (`absolute right-2 top-2`, `gap-1`): **Source**
  (`ExternalLink`, только если у карточки есть безопасный адрес) и **More**
  (`MoreHorizontal`) с меню карточки.
- **Снизу** (`absolute left-2 right-2 bottom-2`): слева коллекции карточки,
  справа **Connect** плюсом (`Plus`) с `CollectionPicker`.
- Коллекции в ряду обычный текст интерфейса, не кнопки с плашкой:
  `font-mono text-sm text-muted-foreground`, при наведении `text-foreground`,
  без фона и обводки; нажатие открывает коллекцию. Порядок как в ручном
  порядке бокового меню, открытая сейчас коллекция тоже показывается.
  Переполнение растворяется у плюса (`createRightFadeMaskStyle`). Пустой ряд:
  `No collections` цветом `text-tertiary-foreground`.
- Плашки коллекций в теле карточки выключены (`CARD_COLLECTION_PILLS_ENABLED`).

**Появление:** `opacity-0 group-hover:opacity-100`, только когда текущий
interaction owner pointer. Нижний ряд не ложится поверх текста: карточка
поднимает содержимое так, чтобы от последней строки до букв ряда было 14px,
а ряд выезжает следом из-под края; картинка смещается на 8px
(SPEC_CARD_STATES.md, С8.1; правила в `global.css`, `[data-card-lift]`).
Кнопки и подъём отвечают только на карточке, куда курсор пришёл не быстрее
0,5 px/мс: в ленте рамка становится `group` только у такой карточки (С8.6).
Правый клик опускает карточку на время контекстного меню. В Grid keyboard
mode карточка получает `hoverEnabled=false`: `group-hover:opacity-100`
снимается с overlay, верхних кнопок и нижнего ряда, карточка не поднимается,
но программное открытие `Cmd+K` всё равно может показать верхний
`More`/overflow menu.

**Поведение:**
- Parent card открывается по keyboard только когда `keydown` пришёл с самой
  card surface (`event.target === event.currentTarget`); вложенные action
  buttons не должны keyboard-bubble в open Detail.
- `stopPropagation` на контейнере — клик по кнопкам не открывает Detail
- Source: `openUrl(url)` в браузере. Без безопасного `block.url` кнопки нет
- Connect: `DropdownMenu` со списком каналов (`CollectionPicker`)
- More / right-click menu: `DropdownMenu` / `ContextMenu` — Connect
  (подменю), Source, Reveal in Finder, Copy Path, Rename…, Disconnect from
  current collection, Delete. Иконки используются у `Connect` (`Plus`),
  `Source` (`ExternalLink`), `Disconnect` (`Unlink` — разрыв цепи) и `Delete`
  (`Trash2` — корзина); остальные строки получают пустой leading-slot той же
  ширины, чтобы текстовая колонка была выровнена по одному уровню. Термин
  `Remove from collection` запрещён для card membership actions — в UI
  используется только `Disconnect`.

### Selection Context Menu

Правый клик по карточке, входящей в текущее выделение, открывает selection-scoped

один URL. Правый клик по карточке вне выделения открывает обычное single-card
меню и не меняет выделение. Подробности — в
[SPEC_GROUP_SELECTION.md](SPEC_GROUP_SELECTION.md).

### Media Asset Hover Menu

Media Asset Hover Menu — отдельный contract от Card Hover Menu. Он появляется
на конкретном локальном media asset (frontmatter `file` или body embed), а не
на карточке.

**Кнопка:** стандартный `Button variant="default" size="icon"` с
`MoreHorizontal` 13px. Фон непрозрачный `bg-component-fill`; hover-состояние
идёт из базового Button: inset outline `hover:outline-component-fill-hover`.

**Расположение:** `absolute right-2 top-2` относительно прямоугольника самого
media asset.

**Меню:** одно overflow-меню под многоточием. Команды: `Create Element`, `Reveal
in Finder`, `Copy Path`, `Copy Media`, `Rename Media...`, `Remove from Element`,
`Delete`.

Icon economy mirrors card menus: `Create Element` (`Plus`), `Remove from
Element` (`Unlink`) and `Delete` (`Trash2`) show real icons. Every other media
command keeps the same leading slot empty (no folder/copy/pencil icons).

`Create Element` открывает searchable submenu для `Everything` и каналов. Этот
submenu не имеет собственного ограничения высоты: список обязан использовать
общий `QuantizedMenuScrollArea` с `default` row token, как обычный Connect
picker.

**Граница ответственности:** все команды target'ят media file. В этом меню нет
card-level `Source`, card rename, card delete или collection `Disconnect`.

**Видео:** кнопка занимает только top-right corner и не создаёт full-surface
overlay, чтобы не блокировать native video controls.

Article media-only paragraphs:
- A paragraph whose meaningful children are only image/video embeds renders as
  `data-article-media-stack`.
- Stack children are direct `data-detail-media-action-frame` blocks with
  `display: flex`, `width: fit-content` and `1rem` vertical spacing except the
  last item.
- This prevents several Obsidian embeds on one physical markdown line from
  behaving as inline media and wrapping into accidental rows.
- Inline `<video>` carries `h-auto max-w-full`, exactly like inline `<img>`.
  Without it the element keeps its intrinsic height while the flex frame
  shrinks its width, and `object-fit: contain` letterboxes the frame — dark
  bars that read as extra space under the video, not as a video border.
- The article body zeroes the trailing margin of its last block
  (`[&>:last-child]:mb-0`). The distance from the end of the body to whatever
  follows it belongs to the surrounding layout token, not to the last
  paragraph's own rhythm.

CollectionPicker membership rows:
- Search uses the shared `SearchMenuInput` contract: `border-b border-border
  p-1` wrapper plus `Input variant="ghost"` with `rounded-0 px-2 py-0`.
  It is a menu header, not a standalone input pill. This matches
  `Search spaces` and `Search collections`.
- Checkbox не используется.
- Название канала слева остаётся обычным UI-шрифтом.
- Правый slot имеет `w-[10ch]`; connected row всегда показывает кнопку
  `Connected`, а на active row текст замещается на `Disconnect`.
- Вся строка кликабельна и выполняет то же действие, что правая кнопка
  (toggle membership) — в кнопку не нужно целиться; кнопка останавливает
  всплытие, двойного срабатывания нет.
- Порядок коллекций во всех списках (пикеры, переключатели, расширение) —
  канонический ручной порядок сайдбара (channel positions, затем
  positionless-теги по алфавиту). Локальные пересортировки запрещены;
  допустимое исключение — поднятие текущей коллекции наверх стабильным
  сортом.
- Правый внутренний отступ строки равен вертикальному зазору кнопки:
  `pr-[calc((var(--menu-row-height)-1.5rem)/2)]` — 4px в menu-рядах (32px),
  8px в clipper-рядах (40px). Кнопка сидит в строке с равным воздухом со всех
  сторон на обоих row-токенах.
- Unconnected row показывает count по умолчанию; на active row count скрывается
  и появляется `Connect`.
- Active row имеет один source of truth: общий `activeIndex`, который обновляют
  pointer move и ArrowUp/ArrowDown. CSS `:hover` не должен создавать
  второй независимый selected state.
- `Create collection`, когда он показан в Connect picker, считается таким же
  navigable item: `ArrowDown`/`ArrowUp` могут поставить на него active state, а
  `Enter` запускает create-and-assign.
- Pointer enter не меняет `activeIndex`: после keyboard navigation список может
  прокручиваться под неподвижной мышью, и такой synthetic hover не должен
  отбирать выделение у стрелок. Pointer ownership включается только после
  реального `pointermove` с новыми координатами.
- Action button: `h-6 w-[10ch] rounded-1 bg-component-fill px-[1ch]
  font-semibold`, hover/focus outline `outline-1 -outline-offset-1
  outline-component-fill-hover`. Count/action visibility переключается без
  opacity transition, чтобы keyboard navigation не оставляла fade-tail на
  предыдущей строке.
- Видимое состояние `Disconnect` использует detach-семантику (разъединение,
  не удаление): `text-detach` при той же серой заливке и той же hover/focus
  outline.
- Клик по action button не должен всплывать в parent row/menu surface.

### Text Selection Action Bar

Detail article prose is the only non-editable surface that supports native text
selection. A valid selection shows one compact horizontal floating action bar
near the first selected rendered Markdown block.

- Left grip: `GripVertical`, 32px hit area, `Button variant="ghost" size="icon"`
  like the close button: no own border, no own fill, muted icon by default,
  foreground only on hover/active. It carries the `dnd-kit` draggable payload
  `type: "text_selection"`. The native highlighted text itself is never a Mine
  drag source.
- `Create Element`: standard `Button size="xs"` with a 13px `Plus` inside the bar;
  opens the same searchable channel picker contract as media asset `Create Element`
  (`Everything`, channels, shared `SearchMenuInput`, `QuantizedMenuScrollArea`,
  optional create channel).
- `Delete Text`: destructive `Button size="xs"` with a 13px `Trash2`; removes
  the selected text fragment from the source article, not the source card.
- `Clear text selection`: ghost icon button with `X`, same close affordance
  family as the main grid group-selection bar.
- The bar uses `h-8 rounded-1 border border-border bg-popover px-1 shadow-sm`.
  It is rendered as a `document.body` portal and measured with its real DOM
  size; fixed width constants are fallback only, never the source of truth.
  Its position is centered over the first valid selection rect. If the centered
  position would leave the article safe area, it is clamped by that safe area;
  if there is not enough top room, it flips below the selection.
  It must not appear as a left gutter tab, a vertical rail, or a native
  selection-toolbar clone.

### Feed Card Surfaces

Ordinary feed cards use `bg-card`, not direct `bg-background`. In light theme
`--card = --chrome = oklch(0.9847 0 0)`: zone level 1, one light zone step
(0.0153) below the white page, matching the top chrome level. In dark theme
`--card = --chrome = oklch(0.17 0 0)`, one zone step above the page.
This makes card previews visibly filled without becoming a strong component
fill; floating UI stands on `--popover` instead. Do not hardcode one-off card background classes; change
the semantic token if the surface level changes.
Every card, a post or not, in either theme, stands on `--card` (06.10.2026),
so a read-only hover preview has the same fill as the feed card by
construction.

Feed graphic cards use the same generated thumbnail/poster source as the
sidebar preview strip before falling back to the original media file. This keeps
grid cards visually aligned with sidebar thumbnails and avoids source-image
letterboxing, transparent gutters, or oversized originals becoming the default
feed surface.

### Hover Preview Surfaces

**Превью карточки это карточка ленты, развёрнутая без подъёма и без активных
элементов** (решения пользователя 06.10.2026 и 07.10.2026, SPEC_CARD_STATES.md,
С10).
Так показываются превью в поиске, превью мини-карточки бокового меню, превью
узла графа и превью связанной заметки. Отдельного шаблона нет: один путь
`StaticCard` в `src/components/Card.tsx` рисует карточку ленты в текущем виде

радиусом `--radius-card`.

- Вид: у превью нет следующего наведения, поэтому оно показывает всё, что
  приносит подъём ленты, не поднимая и не обрезая содержимое: текст с первой
  строки без затухания сверху, в `Media` подпись карточки с текстом под
  медиа, внизу ряд коллекций (`font-mono text-sm text-muted-foreground`, без
  коллекций `No collections` цветом `--tertiary-foreground`) в ручном порядке
  бокового меню. Карточка выше ленточной на место ряда, то есть на высоту

  или на подпись.
- Ничего не нажимается: нет `Source`, `More` и плюса `Connect`, имена
  коллекций не отвечают на наведение, превью `pointer-events-none`.
- Без движения: внутри `[data-card-preview]` у слоёв подъёма нет переходов,
  поэтому превью появляется и меняет карточку сразу, при любой настройке
  движения.
- Ширина места: 240 px у бокового меню, графа и связанных заметок, 288 px в
  поиске. Превью над окном несёт `shadow-lg`, превью в панели поиска стоит без

- Призрак перетаскивания рисуется тем же путём, но в покое (карточка под
  перетаскиванием не поднимается, С8.5).

**Один владелец размера.** В media drag-превью (DragOverlay) геометрию задаёт
только `<img>` (пара `max-h`/`max-w` даёт бокс точно по аспекту; `object-fit`
не нужен). Рамка — чистый декоратор: обтягивает контент (`inline-flex`), несёт
border/radius/shadow и **не имеет собственных size-ограничений**. Дублирование
`max-*` на рамке двойственно ограничивает геометрию: border съедает клампнутый
бокс, и вокруг изображения проступают полосы фона; блочная рамка растягивается
на ширину overlay и оставляет фоновое поле сбоку от вертикальных изображений.
`bg-background` на рамке — осознанная подложка для изображений с прозрачностью.

Related notes preview:
- Строка заметки это строка поиска (`CardRow`, решение пользователя

- Preview открывается справа от строки, если в области хватает места; иначе

  связь со строкой.
- В мобильном виде строка занимает всю колонку, места сбоку нет: preview
  встаёт под строкой, а без места снизу над ней, от левого края строки.
- Hover-поля между строкой и preview нет: preview закрывается, как только

- Preview не принимает указатель и не несёт кнопок карточки: это карточка

Article inline image hover preview:
- Это отдельный функциональный блок, не часть текущего Related notes preview.
- Hover/focus outline применяется к wrapper изображения, не к самому `<img>`:

- Preview можно показывать только если frontend может сопоставить image

### Progress

`h-2 rounded-pill bg-primary/20`. Индикатор: `h-full bg-primary rounded-pill`.
Скругление пилюлей у дорожки и у заливки обязательно: прямой край заливки внутри
скруглённой дорожки читается как обрубленный (исправлено 27.09.2026, до этого
компонент скруглял дорожку на `rounded-1`, а заливку не скруглял вовсе).

Два режима одного компонента [progress.tsx](src/components/ui/progress.tsx):

- **С процентом** (`value` от 0 до 100): заливка растёт от левого края,
  `transition-transform 300ms ease-out`. Процент только из реальных данных.
- **Без процента** (`value={null}`) для шагов, длительность которых неизвестна
  (подготовка, склейка, сохранение клиппера): сегмент-пилюля шириной в треть
  дорожки проходит её слева направо от края до края, `1.4s ease-in-out`,
  бесконечно (`mine-progress-indeterminate` в `global.css`). При
  `prefers-reduced-motion` сегмент не движется: он занимает всю дорожку и
  мягко меняет прозрачность от 0.35 до 1 за 2s.

Переход без процента → с процентом идёт от нуля без скачка назад. Атрибут
`data-progress-mode` называет режим. Кнопка Save клиппера использует тот же
режим без процента, сохраняя тело кнопки (`h-10 rounded-1 bg-component-fill`,
сегмент `bg-component-fill-hover`), чтобы полоса стояла ровно на месте кнопки.

Спиннеры (иконка `RefreshCw` индексации, кольцо в попапе клиппера,
`LoaderCircle` аудио статьи) пока не сведены к одному виду; задача в PLAN.md.

## Растворение кромок (edge fade)

Mine гасит контент у кромки маской прозрачности, а не тенью и не тёмной
накладкой. Одна кривая обслуживает все кромки: `src/lib/edgeFade.ts`.

Правая кромка боковой панели гасит переполнение текста: ширина `24px`, уход в
полную прозрачность, ручная таблица из девяти пар `alpha/progress`. Правило
относится ко всему тексту у этой кромки — именам коллекций в строках и полю
`Find or create...` в верхнем хроме (26.08.2026): узкая панель раньше срезала его
подсказку по середине буквы. Маску несёт само поле ввода, а не вся поверхность
поиска, поэтому кнопка очистки `X` справа от поля остаётся целой.

Миниатюры в строках коллекций (07.10.2026) в тёмной теме кончаются той же
кривой в своей ячейке, растворяясь в прозрачность; в светлой никакого эффекта
нет, ячейка просто обрезает их у направляющей (решение пользователя 07.10.2026,
раздел о боковой панели, «Превью-карточки»). Растворение фотографии в белом
читается как туман, по той же причине, по которой верхняя накладка в светлой
теме выключена.

Полоса вкладок (03.10.2026) растворяет оба горизонтальных края, за которыми
спрятаны вкладки: правый той же маской, что строки боковой панели
(`createRightFadeMaskStyle` без прозрачного хвоста), левый её зеркалом
(`createLeftFadeMaskStyle`), ширина `24px`. Когда вкладки спрятаны с обеих
сторон, две маски пересекаются. Здесь маска, а не накладка: вкладки лежат на
хроме, исчезать им есть куда только в тот же цвет, поэтому растворение работает
в обеих темах и не зависит от настройки `Fade content under the chrome`.

Верхняя кромка прокручиваемых поверхностей использует не маску, а накладку: цвет
поверхности кладётся поверх контента и растворяется вниз. Контент сохраняет
собственную непрозрачность и проезжает под полосой целым.

**Только тёмная тема.** Накрытие почти чёрным цветом затемняет контент — он
читается как уходящий вглубь. Накрытие почти белым осветляет его, и фотография
читается как испорченная, а не удалённая, поэтому в светлой теме эффект
выключен.

Высота `24px`, общая для всех поверхностей: полоса всюду означает одно и то же и
обязана помещаться в 32-пиксельную строку боковой панели. Кривая
`alpha(t) = 0.08 + 0.92 · smootherstep(t)`; `smootherstep` даёт нулевые
производные на концах, иначе на стыках видна полоса Маха. Гамма-коррекции нет:
она нужна маске, а не накладке.

Цвет — фон той поверхности, на которой лежит полоса: `--background` для ленты и
развёрнутой карточки, `--sidebar` для боковой панели, `--card` для поиска.
Красить её `--chrome` нельзя: это отдельный токен, и полоса выглядит
прямоугольником чужого оттенка.

Полоса появляется при `scrollTop >= 1px`, живёт вне прокручиваемого контейнера и
меняет только `opacity`. Полный контракт:
[SPEC_SCROLL_EDGE_FADE.md](SPEC_SCROLL_EDGE_FADE.md).

### Контейнер (Content)

`rounded-1 border border-border bg-card text-card-foreground p-1` в разметке;

### Ширина

Одно правило ширины для каждого меню, подменю, контекстного меню и списка с
поиском (решение пользователя 07.10.2026 «стандартизировать ширину»; прежние
роли `command`, `selector`, `picker` с минимумом `192px` и фиксированными
`288px` и `320px` убраны): **меню шириной по самой длинной строке, от `128px`
до `300px`** (`[data-floating-menu]` в `global.css`, ставят обёртки
`DropdownMenuContent`, `DropdownMenuSubContent`, `ContextMenuContent`,
`ContextMenuSubContent`; места вызова ширину не задают).

- Нижний предел `128px` это наименьшая ширина реестра shadcn. Естественная
  ширина коротких меню по замеру 07.10.2026: правый клик по коллекции `96px`,
  Display `120px`, меню карточки `143px`; при прежних `192px` они были
  заметно шире своих строк.
- Верхний предел `300px`: в списке коллекций с поиском и действием `Connect`
  справа (`84px`) остаётся около `188px` под имя, и из реальных имён
  пространства (32 коллекции, медиана 11 знаков, 90% не длиннее 23) целиком
  видны девять из десяти; длиннее режется многоточием.
- Список с полем поиска не сужается, пока его фильтруют: ширина, с которой
  меню открылось, становится его минимумом (`useHeldMenuWidth` в
  `src/lib/floatingLayer.ts`, `min-width` на слое). Строка, пришедшая позже,
  может расширить меню до предела, запрос сузить не может.

Замер после правки: Display `128px` (было `192px`), меню карточки и
контекстное меню карточки `143px` (было `192px`), правый клик по коллекции
`128px` (было `192px`), выбор пространства и коллекции `300px` (было `288px`,
естественная ширина `425px` и `340px` из-за длинных имён), выбор коллекций
`Connect` `300px` (было `320px`).

`available-width` берётся из Radix collision variables
(`--radix-dropdown-menu-content-available-width` /
`--radix-context-menu-content-available-width`) с viewport fallback
`calc(100vw - 1rem)`. `available-height` берётся из тех же Radix collision
variables и пробрасывается как `--floating-menu-available-height`.

### Высота Scrollable Menu

Scrollable dropdown/search lists не используют произвольный `max-height`
вроде `max-h-72`, `max-h-80` или `20rem`. Высота scroll-зоны должна быть
квантована по строкам:

```
fixed header/footer + list padding + N × rowHeight
```

Скролл живёт внутри списка, а не на всём menu content: search header, pinned
footer/create action и save action остаются fixed siblings. Список рендерится
через `QuantizedMenuScrollArea`, который читает
`--floating-menu-available-height`, вычитает fixed siblings и выставляет
`max-height` как целое число строк. Это запрещает полувидимые/обрезанные rows
в `CollectionPicker`, top-chrome space/collection dropdowns и Clipper menus.

Row tokens:

| Token | Value | Surface |
|---|---:|---|
| `default` | 32px | app dropdown/search rows, `SearchMenuAction`, `CollectionPicker` menu layout |
| `clipper` | 40px | Clipper header/list rows and clipper-sized menu actions |

Визуальная строка и расчёт высоты обязаны брать один и тот же token. При смене
row-height токена нельзя менять только CSS-класс строки или только расчёт
scroll area.

Ширина кнопки, которая открыла меню, шириной меню не служит: маленькая кнопка
не диктует ширину списка.

### Выравнивание

Меню стоит заподлицо с видимой подсветкой своей кнопки: край меню на краю
подсветки (`align="start"` по левому, `align="end"` по правому). У кнопки
хрома коробка шире подсветки, поэтому сдвиг меню (`alignOffset`) меряется от
подсветки при каждом открытии (`useMenuAlignToPlate`), а не пишется числом:
выбор пространства держал скопированные `12` при отступе `8` и открывался на
`4px` правее кнопки (замечание пользователя 07.10.2026). Замер после правки:
край меню пространства и меню коллекции совпадает с краем подсветки, `0px`;
меню кнопок с `align="end"` (Display, меню карточки, `Connect`) совпадают
правым краем, `0px`.

### Shadow DOM portal contract

`DropdownMenu` поддерживает `DropdownMenuPortalContainerProvider`. В обычном
приложении content порталится в `document.body`; в browser clipper overlay
provider обязан передавать shadow-local floating root. Это не отдельная
реализация меню для расширения, а тот же Radix/shadcn primitive с другим portal
container. Запрещено писать shadow-local самодельные dropdown'ы ради
избежания portal issue.

### Пункты (Item)

`rounded-1 px-2 py-1.5 text-base`. `DropdownMenu` использует
`focus:state-active`; `DropdownMenuSubTrigger[data-state=open]` использует тот же
`state-active`. `ContextMenu` использует тот же relative `state-active` для item,
checkbox, radio и open submenu states. Все menu hover/focus surfaces выводятся
от поверхности меню (`--popover`) или локального `bg-accent`, а не получают
абсолютный цвет.

Значок пункта и подпункта стоит на вторичной ступени
(`[&_svg:not([class*='text-'])]:text-muted-foreground`) и поднимается до
основной вместе с текстом: `focus:` у пункта и подпункта, `data-[state=open]:`
у подпункта (раздел «Цвет текста и значков»). Недоступный пункт держит
третичную ступень, `destructive` и `detach` держат свой цвет значка.

### Деструктивные и detach-пункты

`variant="destructive"`: текст красный (`text-destructive`) — действие
безвозвратно удаляет контент. `variant="detach"`: текст оранжевый
(`text-detach`) — действие разрывает связь, контент сохраняется (`Disconnect`,
`Remove from Element`). Оба используют единую relative
DropdownMenu/ContextMenu focus surface `focus:state-active`, без цветного фона при
наведении.

### Системные меню: отклонённый эксперимент

06.10.2026 меню карточки (`···`, правый клик, `⌘K`), выбор коллекций и
переключатель коллекции в пути попробовали как системные `NSMenu` с живым
полем поиска, с переключателем окна `Menus: Web / System`. Пользователь
проверил их вживую и отклонил («Нативные окна использовать мы не будем»):
меню остаются веб-меню Radix по правилам этого раздела, код эксперимента
удалён. Причины: системный шрифт и акцентная подсветка строки чужие
приложению, а цвет задаётся только заголовку и значку пункта; `Escape`
(сразу закрывает всё меню вместо очистки запроса) и поиск пункта по первой
букве после стрелок забирает AppKit; каждый выбор закрывает меню, поэтому
несколько коллекций подряд не переключить.

## Web Clipper UI parity

Web Clipper не имеет отдельной визуальной системы. Он использует те же app
primitives и те же состояния, что desktop UI:

- space selector: `MenuTextTrigger` with the top-chrome inner pill state —
  bright plain text trigger, no root button-frame border/fill beyond the row
  surface. In the clipper popup the row is `h-10 bg-accent px-2`; the actual
  Radix trigger is the inner `MenuTextTrigger surface="clipperHeader"` pill
  (`h-6 rounded-1 px-2`), so row padding plus pill padding places the `Mine`
  text at 16px. Chevron sits inside the pill immediately after the space name
  (padding `pl-2 pr-1`, no gap: section «Иконка рядом с текстом»),
  starts as right-facing, and rotates down on open. The dropdown uses
  the shared content width rule (128 to 300px), `align="start"`, and `bg-accent`. The same row owns
  the top-right close action through shared `ChromeCloseButton`, the same
  primitive used by expanded-card chrome;
- clip type switcher: the app's pill (`Tabs`, `TabsList variant="chrome"
  size="panel"`, раздел «Пилюля») inside a 40px Type row (`Type:` on the
  left, switcher on the right). The row uses `bg-chrome`; the pill is 32px
  (`--tabs-pill-height: 32px`, in px because the overlay lives in another
  site's page), the chosen segment's button flush with it, `text-base`, and
  shrink-to-content width, never stretched full-width;
- lower body: after the two top rows, the clipper keeps the legacy simple body:
  `.mine-clipper-body` owns the spacing tokens in `src/styles/global.css` so
  the app Design page and the extension render the same lower-body contract.
  `--mine-clipper-after-type-gap` is 16px only between Type row and the first
  preview card; `--mine-clipper-section-gap` is 8px for every lower separation:
  preview -> channel picker -> save/status stack and screenshot media ->
  screenshot actions. If Type row is hidden, the top body inset also falls back
  to the 8px section gap.
  Do not convert this lower body into edge-to-edge bars unless the full
  clipper contract is redesigned again;
- screenshot preview: legacy local card, `rounded-1 border border-border
  bg-accent`, image `max-h-[220px] w-auto max-w-full rounded-1 object-contain`;
- screenshot actions: `Button size="sm"` (28px), not `clipper`;
- channel picker: no clipper-only checkbox/search implementation. The clipper
  renders the same desktop `CollectionPicker` default menu layout inside an
  inline picker surface with the same visual tokens as floating picker content:
  `bg-card text-card-foreground flex max-h-80 flex-col overflow-hidden
  rounded-1 border p-0 shadow-md`. Use
  `COLLECTION_PICKER_CONTENT_CLASS` / `COLLECTION_PICKER_INLINE_SURFACE_CLASS`
  from `CollectionPicker`; do not restate picker geometry in clipper code.

Any clipper-only component that duplicates an app primitive visually is design
debt. The permitted form is a thin adapter over the app primitive when the
desktop component itself depends on Tauri-only APIs. Current shared primitives
that exist specifically to prevent drift: `MenuTextTrigger` and the pill
(`Tabs` chrome).

## Витрина состояний и краёв

Раздел дизайн-системы, открываемый в приложении, обязан показывать не только
компоненты в покое, но и **все состояния, которые трудно воспроизвести
вживую**. Правило приёмки: новое состояние интерфейса считается сделанным
только когда его видно в витрине без подготовки условий.

Витрина статична: состояния отрисованы, а не воспроизведены. Никаких реальных
хранилищ, сети и таймеров — только внешний вид и текст.

Раздел называется «Состояния и края» и живёт в
[EdgeStatesSection.tsx](src/components/EdgeStatesSection.tsx).

Состав раздела на 15.08.2026:

- карточка ленты в ожидании содержимого, с меткой облака и без неё;
- развёрнутая карточка с индикатором загрузки оригинала;
- недоступный оригинал: `Original is in iCloud, not available offline`;
- видео-постер вместо автовоспроизведения;
- иконка загрузки из облака в верхней панели и её пояснение;
- иконка индексации в верхней панели;
- карточка-дисклеймер в настройках, раздел `Spaces`, в обоих прочтениях:
  часть файлов в облаке и всё на диске;
- экран `Folder unavailable` с тремя действиями;
- подтверждение выбора непустой папки;
- онбординг-состояние пустой ленты с двумя путями наполнения;
- состояние отсутствующего медиафайла карточки;
- статус связи с расширением во всех вариантах: не установлен, установлен,
  версия расходится, ни одного браузера не найдено;
- прогресс первичной индексации с числами — **макет**, реализации нет;
- всплывающая карточка рекомендации с `Don't show again` — **макет**,
  реализации нет.

Три пометки различают происхождение состояния:

- без пометки — на странице настоящий production-компонент с фиксированными
  входными данными; расхождение с продуктом невозможно;
- «перерисовано» — оригинал живёт внутри приватной части карточки
  (`GraphicSurface`, `CardBody`), и здесь он воспроизведён; экспортировать
  внутренности карточки только ради витрины дороже, чем перерисовать;
- «нет в продукте» — состояние описано в требованиях, но не реализовано.
  Пометка снимается вместе с появлением реализации. Макет без пометки читался
  бы как готовая работа и хуже, чем отсутствие макета.

Раздел проверяется вживую: [edge-states-audit.mjs](scripts/edge-states-audit.mjs)
открывает его в браузере и падает, если экран не помещается в рамку, текст
совпал по цвету с фоном, какое-то состояние не отрисовалось или что-то бросило
исключение. Отдельная точка входа `edge-states.html` существует только в dev:
в продакшен-сборку входят лишь `index.html`, `settings.html` и `tabbar.html`.

общим жестом хрома с порогом `4px` (`useChromeDragGesture`). Жест просит
бэкенд начать перетаскивание (`start_window_drag`): страница не знает своего
окна после переноса вкладки (В22, В23). До первого состояния окна полоса
показывает `TabBarPending`: тот же ряд с резервом и зоной перетаскивания, без
вкладок.

**Ширина.** Все вкладки одной ширины: ширина ряда без слота `+` делится поровну
и округляется вниз до целого пикселя, в пределах от 72 до 200 px
(`TAB_MIN_WIDTH_PX`, `TAB_MAX_WIDTH_PX`). По умолчанию вкладка максимальной
ширины, сжимается только когда вкладок много. Блок вкладок занимает ровно их сумму,
поэтому `+` стоит вплотную к последней вкладке. После закрытия вкладки
указателем (крестик, средняя кнопка) ширины держатся, пока указатель над
полосой: под указателем оказывается крестик следующей вкладки. Удержание
снимают уход указателя с полосы и появление вкладок сверх числа на момент
закрытия.

**Вкладка.** Прямоугольник во всю высоту ряда, без скругления: узел
`role="tab"` с отступами `12px` слева и `4px` справа (`pl-3 pr-1`). Вкладки
очерчены линиями `1px` цветом `border`: справа у каждой, слева у первой.

| Состояние | Заливка | Подпись | Наведение |
|---|---|---|---|
| Видимая (`aria-selected`) | `bg-chrome`, хром страницы под полосой | `text-foreground` | нет |
| Остальные | без заливки, поверхность полосы | `text-muted-foreground` | `state-active` и `text-foreground` |

Видимая вкладка окрашена хромом уровнем ниже, но со страницей не сливается:
нижний разделитель полосы идёт и под ней. Перетаскиваемая невидимая вкладка
получает заливку полосы (`bg-accent`), чтобы не просвечивать над соседями. Фокус
с клавиатуры рисует обводку `1px` цветом `ring` внутри вкладки
(`-outline-offset-1`).

**Подпись** (В47, `tabLabel.ts`). Текст `13px` (правило текста интерфейса для
`header.chrome-row .text-sm`), одна строка. Подпись это самый глубокий открытый
раздел: на Everything имя пространства, внутри коллекции имя коллекции, при
открытой карточке её видимый заголовок (`getNavigationLabel`), а без него
подпись карточки без папки и расширения. Вкладка без пространства подписана
`Choose Space`. Полную подпись показывает системная подсказка `title`.

Подпись, которая не помещается, растворяется у правого края маской `24px`
(`data-overflow`, измеряется по `scrollWidth`), без многоточия. Подпись, которая
помещается, не растворяется.

**Крестик.** Кнопка хрома `Button variant="chrome" size="chrome-icon"`, как
остальные кнопки ряда: плашка `24px` с `state-active` при наведении, lucide `X`
`13px` с линией `1px`, у правого края вкладки поверх подписи (`absolute`,
`right-2`): подсветка в `8px` от правой линии вкладки, как у любой иконочной
кнопки от границы («Иконочные кнопки хрома»). Виден только при наведении на вкладку, на любой вкладке, включая
видимую, и при фокусе с клавиатуры. Появляется за `100ms`: `opacity` от 0 и
`scale` от `0.9`, кривая `cubic-bezier(0.23, 1, 0.32, 1)`; скрытый крестик
нажатия не принимает. Одновременно и с той же кривой растворение подписи
сдвигается влево на `30px` и освобождает место под крестик; длины маски
зарегистрированы через `@property`, поэтому сдвиг плавный. При уменьшении
движения переходов нет. Доступное имя `Close Tab`, в порядок табуляции не
входит. Средняя кнопка мыши закрывает вкладку, на которой её нажали и
отпустили.

**Прокрутка.** Когда вкладки не помещаются и в `72px`, блок вкладок
прокручивается по горизонтали без полосы прокрутки (`scrollbar-width: none`,
`::-webkit-scrollbar` скрыт, `overscroll-behavior-x: contain`). Край, за
которым спрятаны вкладки, растворяется маской шириной `24px` с кривой правой
кромки боковой панели: справа `createRightFadeMaskStyle`, слева
`createLeftFadeMaskStyle`; прокрученный в середину блок растворяет оба края
пересечением двух масок (раздел «Растворение кромок»). Край считается
скрытым со смещения `1px` (`TOP_FADE_SCROLLED_THRESHOLD_PX`). Видимая вкладка
всегда прокручена в видимую часть целиком, с наименьшим сдвигом.

**Клавиатура** (В49, `tabKeyboard.ts`). В порядке табуляции одна вкладка,
по умолчанию видимая. Стрелки влево и вправо двигают фокус по кругу, Home и End
на первую и последнюю, Enter и пробел показывают вкладку, Delete и Backspace
закрывают её, и фокус уходит на соседнюю справа, а без неё слева. ⌃Tab и
⌃⇧Tab страница полосы ловит сама и передаёт бэкенду
(`activate_adjacent_tab`). Щелчок фокус в полосе не оставляет: нажатие не
фокусирует вкладку, и фокус уходит в показанную вкладку.

**Меню вкладки** (В50, `tabMenu.ts`). Правый щелчок открывает нативное меню
у указателя (`Menu` Tauri): `Move Tab to New Window`, разделитель, `Close Tab`,
`Close Other Tabs`. У единственной вкладки окна первый и последний пункты
выключены. Меню одно на полосу: пункты действуют на вкладку, для которой его
открыли последним. Своих всплывающих элементов страница полосы не рисует:
она высотой в один ряд и обрезала бы их (В6). Бросок файлов на полосу ничего
не делает.

**Перестановка** (В60, `tabDrag.ts`). Нажатие на вкладку и сдвиг дальше `4px`
превращают жест в перетаскивание, щелчок после него подавляется. Вкладка идёт
за указателем по горизонтали, не выходя за ряд вкладок, и лежит над соседями
(`z-10`) без анимации. Соседи сдвигаются на ширину вкладки за `150ms`
(`TAB_REORDER_MOTION_MS`) с кривой `cubic-bezier(0.22, 1, 0.36, 1)`, при
уменьшении движения сразу (`motionDuration`). Место меняется, когда вкладка
закрыла половину соседа. Пока идёт перетаскивание, вкладки не принимают
указатель. Отпускание показывает новый порядок сразу, без анимации и без
ожидания ответа бэкенда; Escape возвращает вкладку на место.

**Отрыв и присоединение** (от В61 до В63). Указатель ниже полосы больше чем
на `24px` (`TAB_DETACH_THRESHOLD_PX`) или за левым, правым либо верхним краем
окна отрывает вкладку: дальше её ведёт бэкенд, и новое окно идёт за указателем
так, что вкладка в его полосе стоит под указателем с прежним смещением захвата.
Единственная вкладка окна не отрывается: её перетаскивание двигает само окно.
В полноэкранном окне отрыв действует как `Move Tab to New Window` (В65), а
перетаскивание единственной вкладки ничего не делает. Пока перетаскиваемая
вкладка над полосой другого окна, в той полосе стоит маркер места вставки:
вертикальная линия `2px` (`DROP_MARKER_WIDTH_PX`) на всю высоту ряда цветом
`bg-foreground`, по центру границы между вкладками и внутри ряда на обоих его
концах. Маркер не принимает указатель и скрыт от экранного диктора. Место
вставки это число вкладок, чей центр левее указателя.

### Тулбар

`<header>`: `h-8 border-b border-border bg-chrome`, `data-tauri-drag-region` для
пустых зон перетаскивания окна. Высота строго 32px. Интерактивные элементы
внутри top chrome не выключают drag целиком: они используют общий threshold
gesture (`4px`) — короткий жест остаётся click/focus, движение за порог
запускает native window drag и гасит последующий click.

С 03.10.2026 первый ряд страницы вкладки начинается с переключателя
пространства: резерв светофоров и кнопка бокового меню переехали в полосу
вкладок над страницей (раздел «Полоса вкладок», SPEC_TABS.md, В43, РП6).
Traffic-light reserve размечается как `data-traffic-light-reserve`, имеет
ширину `80px`, наследует surface хрома вокруг себя и не содержит
интерактивных DOM-кнопок; он стоит в полосе вкладок и в окне настроек.
Видимость inactive native traffic lights управляется только AppKit-слоем, не
CSS.

Кнопка бокового меню (`SidebarToggleButton`, `data-top-chrome-sidebar-toggle`)
стоит в полосе вкладок сразу после резерва: стандартная иконочная кнопка хрома
(`variant="chrome"`, `size="chrome-icon"`) с lucide `Columns2`. Подпись для
экранного диктора `Hide Sidebar` или `Show Sidebar`, `aria-pressed` пока меню
открыто. Действие то же, что у пункта View → Hide Sidebar (⌃⌘S), у кнопки
`Hide Sidebar` в нижней панели, у свайпа двумя пальцами и у перетаскивания края
меню. С 03.10.2026 у каждой вкладки своё боковое меню: ширину и свёрнутость
хранит бэкенд в памяти вкладки (`SavedTab.sidebar`), меняет командой
`set_window_sidebar` и сообщает событием `window-sidebar-changed` странице
вкладки и полосе (В56). Кнопка стоит в одной точке окна при любой вкладке и
показывает меню видимой вкладки; при переключении вкладок меню может
открыться или закрыться, если у вкладок оно разное.

Почему `Columns2`, а не `PanelLeft` (решение пользователя 02.10.2026):
`PanelLeft` рисует узкую колонку у края, а левая панель Mine держит коллекции
с превью и часто шириной с ленту. Окно Mine состоит из двух панелей, и знак
двух равных колонок изображает именно его.

### Нижняя панель действий (Action Bar)

`h-8 bg-accent border-t border-border px-8`. Отступы 32px с обеих сторон.
Правая часть остаётся свободной для transient status text вроде `Syncing…`;
глобальной Search-кнопки в нижней панели нет.

Компонент `ActionButton` — двуслойная кнопка (две «пули»). Внешняя пуля
использует общий слой состояния `state-active`, внутренний label
`bg-component-fill-inner`, поднятый уже от подсветки. Внутренний label имеет тот же точный вычисленный цвет,
что default `Button` на этой поверхности: правило лица в `buttons.css` красит
его лицевой стороной объёмной кнопки (раздел «Объём кнопки»).

- Структура: `<div role="button">` (внешняя пуля) → `<span hotkey>` + `<span label>` (внутренняя пуля)
- Внешняя пуля: `rounded-1` (3px), `h-6` (24px), `p-[2px]`, `overflow-hidden`
- Внутренняя пуля: `rounded-[2px]`, `bg-component-fill-inner`, `h-5`, `inline-flex items-center`, `px-[1ch]`, `leading-none`
- Hotkey: текст на фоне внешней пули, `h-5`, `inline-flex items-center`, `px-[1ch]`, `leading-none`
- Зазор между внешней и внутренней пулей: 2px (все стороны, через `p-[2px]` на внешней)
- Шрифт: `font-mono text-sm`
- `forwardRef<HTMLDivElement>` для программного управления

Размеры: внешняя — 24px (`h-6`), внутренняя — 20px (`h-5`, 24 - 2×2px зазора).
Вертикальное центрирование фиксируется высотой inner text boxes, а не `py`, чтобы
метрики monospace-шрифта не давали оптический сдвиг в 1px.

### Сайдбар

Есть один layout width mode: compact/non-compact по ширине сайдбара (порог
320px). Экспериментальный channel card display mode удалён; Settings не
содержит переключатель `Rows` / `Cards`.

#### Полный режим (width >= 320px)

Три колонки в каждой строке.

| Колонка | Содержимое | Ширина |
|---|---|---|
| Левая | Название канала | `min-w-[100px] max-w-[150px] flex-1` |
| Центральная | Превью-карточки | `flex-1 min-w-0`, `h-8 overflow-hidden` |
| Правая | Счётчик + действия | `w-8 text-right` |

Шрифт названий: `font-sans text-base` (14px). Счётчики справа:
`font-mono text-sm text-right`. Строки разделены
`border-b border-sidebar-border`. Паддинги навигации: `px-8 pt-8`;
строки в полном режиме не имеют собственного горизонтального padding, чтобы
названия каналов, правые счётчики и link-editor action buttons стояли
заподлицо с краями navigation column. Это отдаёт свободную ширину центральной
полосе preview-карточек. Для визуальной компенсации glyph side bearings label
text получает `translate-x-px`, а правый count text получает `-translate-x-px`;
это не меняет layout box и не влияет на preview-strip ширину.
Top inset 32px должен жить на scroll-container (`data-sidebar-scroll`), а не в
отдельной фиксированной header-плашке: если header slot (например iCloud
conflict banner) ничего не рендерит, он не должен оставлять пустой блок над
списком.

Превью-карточки: `size-8 object-cover`, `gap-1` (4px). У миниатюр своя ячейка
строки (решение пользователя 07.10.2026): от левой направляющей до правой, с
`4px` воздуха после левой. Следующая ячейка (счётчик и Connect, вместе с
пикселем правой направляющей) стоит в строке сама (`data-sidebar-meta-cell`),
поэтому ячейка миниатюр кончается на направляющей, а не тянется под счётчик, и
её маска не знает ширины соседней ячейки. Правый край по теме: в светлой
никакого эффекта, превью идут до самой направляющей (`--preview-edge-gap: 0px`)
и обрезаются краем ячейки (решение пользователя 07.10.2026: «миниатюра просто
уходит за край и всё»); в тёмной `4px` воздуха и растворение последних `24px`
по той же multi-stop alpha-кривой, что строки (`createRightFadeMaskStyle` без
хвоста, свойство `--sidebar-preview-mask`, маску ставят только правила тёмной
темы), это читается как тень. Для светлой темы опробованы и отклонены
растворение, приглушение прозрачностью, цветом и размытием и scroll edge effect
macOS и iOS 26 и 27 (SPEC_FRONTEND.md, «Thumbnail strip»). Текстовые
thumbnail (PNG с прозрачным фоном) обёрнуты в
`bg-accent` + `dark:invert`. Видео-блоки показывают первый кадр (H.264
декодирование через OpenH264).

**Заглушки до прихода миниатюр (01.10.2026).** Счётчик строки приходит раньше
миниатюр (запуск, открытие пространства). Пока чтение превью не ответило для
строки (в `channelPreviews` нет её ключа), полоса держит заглушки вместо
пустоты: по одной на карточку, но не больше `SIDEBAR_PREVIEW_SLOTS` (20, столько
же превью читается на коллекцию; лишние уходят за обрезанный край, как
настоящие). Коллекция без карточек заглушек не показывает. Заглушка и настоящая
плитка берут один класс `SIDEBAR_PREVIEW_TILE_CLASS` (`size-8 shrink-0
overflow-hidden bg-accent`): тот же размер, без скругления, та же маска с
растворением справа, поэтому при замене ничего не сдвигается. Заливка
`bg-accent` взята у скелета карточки ленты (`CardSkeleton`); мерцания нет, у
системы его нет. Миниатюра, которая ещё декодируется, выглядит так же: под
картинкой видна заливка плитки, а `bg-card` текстовой миниатюры появляется
только вместе с чернилами, после загрузки изображения
(`MicroPreviewThumbnail`, `data-micro-preview-state`).

**Заглушки на время построения превью (01.10.2026).** Чтение миниатюр
возвращает только карточки, чьё превью уже есть, поэтому в пространстве с
пустым кэшем строка получает пустой список. Пока идёт фоновый проход превью
(необязательный `previewsPending` у `Sidebar`, его вычисляет `App`), строка
ставит сначала настоящие миниатюры, затем заглушки на остальные места:
`max(0, min(count, SIDEBAR_PREVIEW_SLOTS) - shown)`. Новая миниатюра занимает
место одной заглушки, число мест не меняется, поэтому ничего не сдвигается.
Когда проход закончен, строка показывает только то, что есть. Копия строки при
перетаскивании получает тот же признак. Карточки ленты в это время рисуют ту
же заливку `bg-accent` (SPEC_CARD_MEDIA_GEOMETRY.md, «Карточка без превью»).

Title text использует тот же right-fade mask contract, что и preview strip:
`24px` fade + `4px` прозрачный tail перед левой направляющей. Это не
`text-overflow: ellipsis`. Responsive contract двуступенчатый: пока ширина
сжимается, сначала деградирует central preview rail; только когда rail
упирается в минимум, начинает сужаться title slot в диапазоне `100–150px`.

#### Compact-режим (width < 320px)

Две колонки: название + счётчик. Без карточек-превью.

| Колонка | Содержимое | Ширина |
|---|---|---|
| Левая | Название канала | `flex-1 truncate` |
| Правая | Счётчик + действия | `w-8 text-right` |

Шрифт названий: `text-base` (14px), без `font-mono`. Правый счётчик:
`font-mono text-sm text-right`. Стиль shadcn SidebarMenuButton: `rounded-1
p-2`. Без разделительных линий. Channel rows не получают фонового выделения на
hover/active; текст участвует в общем sidebar row focus-mode contract.

#### Общее

Ширина по умолчанию 360px: с ней бэкенд создаёт боковое меню каждого нового окна (`SIDEBAR_DEFAULT_WIDTH_PX`, SPEC_TABS.md, В56), страница поднимает её до своего минимума. Диапазон ресайза: от 220 до 600px; перетаскивание линии упирается в пределы и меню не сворачивает (07.10.2026). Ручка ресайза это сама линия между меню и лентой с видом рельса shadcn `SidebarRail`: полоса захвата 16px только по высоте самой линии (верхний ряд и тело, без нижнего бара), при наведении через 300мс линия 2px на полшага ярче линии (`--sidebar-border-hover`), курсор показывает, куда может пойти край (SPEC_FRONTEND.md, «Sidebar Resize»). Паддинг строки в полном режиме: `py-1` (4px), без `px-*`.
App shell keeps the right/main pane at a minimum of `304px`: `240px` metadata
card minimum plus two `32px` side insets. Desktop `minWidth` is `904px`
(`600px` max sidebar + `304px` min right pane).

Обычные строки sidebar не заменяют счётчик hover-действиями: правый `w-8`
slot всегда показывает count в `font-mono`. Rename/Delete доступны через
`ContextMenu` строки, а не через hover-многоточие.

Строки создания коллекции (`data-sidebar-new-channel-row`) в покое нет: она
появляется вверху списка, под `Everything`, только пока новую коллекцию
называют или тащат карточку. Команда живёт во втором ряду верхней панели
(`+` у правого края колонки) и на ⇧⌘N. Полный контракт в разделе «Создание
коллекции».

#### Перетаскивание строк (reorder)

Контракт жеста — переупорядочивание в боковых списках macOS (Finder, Notes,
Things):

1. Исходная строка на время жеста исчезает из списка полностью
   (`opacity-0`, transform применяется) — она и есть движущийся плейсхолдер,
   показывающий точное место вставки. Полупрозрачный призрак на старом месте
   запрещён.
2. За курсором следует копия строки в `DragOverlay`
   (`SidebarTagRowDragPreview`): те же элементы разметки, что у строки —
   title cell, preview rail с настоящей полосой миниатюр, счётчик — на
   поверхности `bg-sidebar` + `border` + `shadow-md`. Медиа строки обязано
   лететь вместе с ней. Точка захвата сохраняется — модификатор snap-to-cursor
   к этому жесту не применяется. Копия не содержит поведения: ни NavLink, ни
   hover-превью, ни кнопок.
3. Соседние строки раздвигаются transform-переходом dnd-kit, монотонно, без
   осцилляций. Цель сортировки — слот под указателем (`pointerWithin`) по
   rect'ам, замеренным на старте жеста, только среди сортируемых строк;
   `closestCenter` — только fallback, когда указатель покинул список. Центр
   прямоугольника схваченной строки целью не является: строка висит на курсоре
   там, где её взяли, и цель по центру уводила бы дырку на полстроки от
   курсора.
4. На время жеста строки инертны: `[data-sidebar-tag-dragging="true"]` на
   scrollport выключает pointer-events строк (ховеры, превью, count-swap) и
   ставит `cursor: grabbing`. Hover-превью дополнительно глушится в JS.
5. Отпускание: новый порядок применяется в тот же кадр (optimistic,
   `applyPendingTagOrder`), копия долетает в плейсхолдер drop-анимацией 200ms
   `cubic-bezier(0.22,1,0.36,1)`; на время полёта реальная строка скрыта
   side-effect'ом. Снап-бэк и поздний прыжок после записи запрещены.
6. Escape или дроп мимо списка возвращают порядок без изменений.
7. Перетаскивание карточек/медиа/текста на коллекции не затрагивается: их цель
   по-прежнему решается hit-testing'ом по живому DOM.

Контракт закреплён браузерным аудитом `bun run test:sidebar-reorder`
(`scripts/sidebar-reorder-audit.mjs`, роут `/__sidebar-reorder-audit`).
Sidebar navigation rows, включая `Everything` и каналы, не используют
`hover:bg-*`, `bg-sidebar-accent` или `text-sidebar-accent-foreground`: выбор
маршрута отражается состоянием приложения, но не визуальной плашкой строки.
Обычный count slot не меняется по hover.

Row focus-mode:
- Без hover/focus все row labels и counts используют `text-muted-foreground`.
- Текущий выбранный route (`Everything` или активный канал) всегда использует
  `text-foreground`.
- Когда курсор или keyboard focus находится внутри строки, sidebar получает
  `data-sidebar-row-focus-mode="true"`.
- Focused row становится `text-foreground`, остальные row labels/counts
  остаются `text-muted-foreground`.
- Активный route остаётся `text-foreground`, даже если focus находится на
  другой строке.
- Thumbnail strips и preview cards вообще не участвуют в этом state и
  остаются визуально неизменными.
- Drag-over карточки, inline-media или выделенного фрагмента над channel row
  использует тот же row focus-mode, что hover: без отдельной ring-рамки,
  outline, inset или legacy drop-highlight.
- Вход/выход из focus-mode анимируется `180ms cubic-bezier(0.22, 1, 0.36, 1)`.
  Переключение между строками внутри уже активного focus-mode идёт мгновенно
  через `data-sidebar-row-switching="true"` на один animation frame.

#### Link-editor режим (Detail открыт)

Когда открыта карточка, sidebar превращается в редактор связей этой карточки с
каналами. `Everything` остаётся обычным пунктом навигации с общим счётчиком и
без checkbox. Список строк каналов использует ту же геометрию, что обычный
sidebar.

Top inset списка в раскрытой карточке не меняет геометрию обычного sidebar.
Основной shell использует второй top-bar level (`h-8 border-b border-border`)
с отдельными sidebar/content сегментами; сам sidebar scroll-content всегда
использует `pt-8` (32px). В expanded главной это даёт общий visual top offset
64px: второй bar 32px + content inset 32px. Когда Detail открыт в
non-compact shell, второй bar становится Detail/link-editor chrome: в sidebar
segment живёт `Collections:` (переключатель `All / Connected` удалён 07.10.2026), в content segment filename,
overflow и close. Body-level `absolute inset-x-0 top-0 h-8` overlays для
Sidebar/Detail в App shell запрещены: они создают третий слой под вторым bar.

Верхняя surface:

| Surface | Geometry |
|---|---|
| Main secondary top bar | `h-8 border-b border-border bg-background`, split sidebar/content |
| Detail/link-editor secondary bar | тот же second-level bar, `bg-accent`; sidebar segment `px-8 gap-2`, content segment `px-8 gap-3` |

Non-compact Detail close не должен распадаться на несколько визуальных шагов.
Второй top-bar level держит два абсолютных слоя внутри тех же sidebar/content
segments: main layer (`data-main-secondary-main-layer`, число коллекций и
счётчик элементов) и
Detail/link-editor layer (`data-secondary-sidebar-link-mode-bar`,
`data-secondary-detail-top-menu`). Surface bar привязан к entered-state
Detail-layer, а не к наличию closing snapshot: как только close начинается,
bar сразу переходит в main surface, Detail controls уходят через
`opacity + translateY(-8px)`, а main layer возвращается через
`opacity + translateY(6px)`. Snapshot открытой карточки остаётся только для
анимации текста/кнопок; он не удерживает `bg-accent` после начала закрытия.
Обычный non-compact close использует короткий shell-exit budget около `190ms`;
compact Detail top chrome сохраняет отдельный `260ms` budget, потому что там
анимируются элементы permanent top chrome.

В main browsing state второй top-bar level — тихая информационная строка, а не
общий toolbar. Над боковым меню она показывает число коллекций и кнопку `+`,
над лентой число элементов текущей коллекции; в content segment допускается
только одна пилюля для режима `View: Grid / Graph` («Пилюля», размер `row`).
Она стоит сразу после счётчика текущей коллекции по левой оси content
segment. Зазор между счётчиком и switcher равен spacing-only gap левой
ячейки (`gap-5`). Отдельные
`ActionButton`-переключатели `Graph/Grid` в bottom action bar или top fallback
запрещены.

Art direction: это ambient metadata, а не dashboard. Строка должна считываться
как часть системного chrome: ровная, низкоконтрастная, без KPI-акцента и без
визуального соревнования с карточками. Запрещены badges, bold numbers, colored
deltas, cards, pills, uppercase labels и любые hover/focus states, кроме
состояний пилюли view-mode и иконочной кнопки `+` над
боковым меню.

Левый segment (`data-main-secondary-top-bar-sidebar-segment`) это шапка списка
коллекций под ним (`data-main-secondary-stats-left`). С 03.10.2026 по решению
пользователя он окрашен поверхностью таблицы `bg-sidebar`, как и поле `Find
collections` во втором ряду хрома (`data-sidebar-top-search-surface`), с
запросом и без: колонка таблицы продолжается вверх до переключателя
пространства. Открытая карточка окрашивает весь ряд в
`bg-accent`, и segment тоже. Устроен как правая половина над лентой: только левый отступ `pl-[--chrome-edge-pad]`, `h-full`,
`items-center`, `overflow-hidden`, `gap-5`. Текстовый режим:
`font-mono text-tertiary-foreground leading-none`, regular weight, кегль 13 px
(«Текст интерфейса 13 px»). Содержимое:

- слева число коллекций (`data-main-secondary-collection-count`):
  `1 collection`, иначе `N collections`; число берётся из того же списка
  коллекций, что рисует боковое меню. Пока в `Find or create...` набран
  текст, это число коллекций, которые оставил фильтр (`filterSidebarTags`);
- за ним индикаторы загрузки из iCloud и индексации (`ActivityIndicators`),
  видимые только во время работы;
- у правого края ячейки иконочная кнопка `+` (`data-main-secondary-new-collection`,
  `aria-label="New Collection"`): стандартная кнопка верхней панели в
  `ChromeActions windowEdge={false} className="ml-auto mr-2"`, то же действие,
  что ⇧⌘N. Кнопка стоит в 8 px от правого края колонки, на одной вертикали с
  кнопкой очистки фильтра над ней и с кнопкой `Connected` строк коллекций.
  Если команды нет, ячейка получает правый отступ сама.

Статистики файлов пространства (`files`, `.md`, `media`, объём) в этой строке
больше нет.

Числа форматируются по `ru-RU`: группировка пробелами.

Правый segment (`data-main-secondary-top-bar-content-segment`) показывает
количество элементов в текущем route scope у левой оси контентной области и
держит `View: Grid / Graph` сразу справа от счётчика: `px-8`, `justify-start`,
`gap-5`, `font-mono text-sm text-tertiary-foreground leading-none`.
`View:` и неактивные segments наследуют тот же `text-tertiary-foreground`,
что счётчик. Текст счётчика: `260 elements`. В `Everything` это количество
всех элементов, в канале — количество элементов, прикреплённых к этому каналу.
Search/filter state не меняет этот счётчик: это статистика канала, а не
количество видимых результатов.

Текстовый контракт правого segment:

- `1 element`, otherwise `elements`
- `1 element in collection`, otherwise `elements in collection` в канале
- `0 elements` для пустого канала
- никаких labels вроде `Cards:` или имени канала; контекст уже задан route
  title в permanent top chrome

Responsive contract: строка не переносится и не меняет высоту. Если левому
segment не хватает ширины, число коллекций обрезается многоточием как единый
блок, кнопка `+` не сжимается. В collapsed Sidebar state левая ячейка не
рендерится, segment остаётся пустой drag region. Правый count остаётся на левой оси content segment; на
экстремально узкой ширине он может truncate только как единый текстовый блок.

Realtime contract: обновление чисел не анимирует их и не показывает
loading/skeleton text. Пока snapshot не загружен, segment рендерит пустое место
на той же геометрии. После backend event строка меняется атомарно в следующий
React commit; запрещены промежуточные `calculating`, `rendering layout` и
прочие служебные сообщения в chrome.

Содержимое surface: `Collections:` + иконочная
кнопка `+` (`data-secondary-link-mode-new-collection`, `aria-label="New
Collection"`), то же действие, что ⇧⌘N. Кнопка `+` стоит на том же месте, что
над закрытым списком: `ChromeActions windowEdge={false} className="ml-auto
mr-2"`, 8 px от правого края колонки, поэтому при открытии карточки она не
сдвигается. Слой получает только левый отступ `pl-[--chrome-edge-pad]`, а без
команды и правый. `Collections:` использует
`font-mono text-tertiary-foreground`, как `View:` над лентой. Переключателя
`All / Connected` в этой surface больше нет (удалён 07.10.2026 вместе с
режимом): список коллекций открытой карточки показывает все.

Если включён Compact Detail top menu, эта link-editor surface не рендерится.

Открытая карточка: панель сведений не отнимает место у содержимого
(решение пользователя 07.10.2026, SPEC_FRONTEND.md, Detail). Содержимое
всегда стоит в полном размере `W`: колонка чтения `48rem` или, если
содержимое одна картинка, её собственный размер, когда он меньше
(`min(768, w, 0.85 × высота окна × w / h)`). Рядом с панелью сетка
`minmax(pad,1fr) | W | minmax(pad,1fr) | 20rem | pad` (`pad` это
`--card-content-pad`): лишнее место уходит в гибкие колонки, панель `20rem`
стоит с отступом `pad` от правого края. Тело карточки не добавляет
локальный `pl-*` guard; дистанцию между содержимым и панелью задаёт сетка.

Как только контейнер уже `3 × pad + W + 320`, то есть зазор между
содержимым и панелью дошёл до минимума `pad`, вид сразу становится
мобильным: содержимое по центру шириной `W`, под ним сведения, кнопки и
Related notes той же ширины, по центру, с отступом `--card-content-pad`;
прокрутка вертикальная.

Metadata card keeps `min-width: 240px`, so the bottom `Source` / `Connect`
button row cannot compress below the buttons' intrinsic content.

Фон карточки сведений (`data-detail-metadata-card`) это поверхность карточки
`bg-card`, уровень второго ряда хрома, в обеих темах (решение пользователя
06.10.2026; раньше `bg-accent`, уровень нижней панели). Кнопки внутри
поднимаются от этой поверхности.

Motion contract: верхний chrome в Detail и sidebar link-editor surface входят и
выходят через мягкий `opacity + translateY` transition с тем же темпом
(`220–280ms`, `cubic-bezier(0.22, 1, 0.36, 1)`). Close не должен блокировать
возврат к grid: страница закрывается мгновенно, а exit дочёркивается отдельным
неблокирующим chrome overlay.

`Connect`/`Disconnect` row actions не ждут closing-анимацию верхнего chrome:
при `detailChromeClosing` строки сразу возвращаются в обычный sidebar mode, а
closing snapshot остаётся только у верхнего link-editor chrome.

Membership action behaviour: checkbox в link-editor не используется. Клик по
строке канала навигирует как обычный sidebar item; только прямой click/key по
правой action button меняет membership. Count остаётся в обычном правом
layout slot `h-8 w-8`; action button рисуется абсолютным overlay поверх строки
и не участвует во flex-раскладке preview strip. В link-editor яркость sidebar
rows не следует route contract: `text-foreground` получают уже связанные
каналы и строка под курсором или в фокусе, как в ленте; остальные строки
остаются `text-muted-foreground`. С 28.09.2026: строка под курсором в
развёрнутой карточке раньше не подсвечивалась.
Для уже связанного канала
overlay всегда показывает серую кнопку `Connected`; на hover/focus строки текст
замещается на `Disconnect`. Для несвязанного канала slot по умолчанию
показывает count; на hover/focus count скрывается и появляется `Connect`.
Action button: `absolute right-0 top-1/2 -translate-y-1/2 z-10 h-6 w-[10ch]
rounded-1 bg-component-fill px-[1ch] font-semibold`, hover/focus outline
`outline-1 -outline-offset-1 outline-component-fill-hover`.
Видимый текст `Disconnect` использует `text-detach` (разъединение, не удаление); `Connected` и
`Connect` остаются `text-foreground`.

CollectionPicker inside card/Detail menus follows the same row action visual
model but keeps sidebar taxonomy order exactly as provided. Connected/recent
state never reorders rows while the menu is open. Search uses shared
`SearchMenuInput`: a flat ghost menu-header row behind `border-b`, without a
separate rounded input frame. Active keyboard item uses `state-active`, hides the
row count, and reveals the right action button. `ArrowUp` /
`ArrowDown` move across rows and the conditional create action, `Enter` runs
the visible `Connect`/`Disconnect` or create action, and `Escape` from a
submenu returns to the parent `Connect` item instead of closing the whole
overflow menu.
Pointer and keyboard navigation share the same `activeIndex`: moving the mouse
selects that row, pressing arrows transfers ownership back to keyboard, and
there is never a simultaneous pointer hover and keyboard hover. Right-slot
visibility changes are immediate, without opacity transition.
CollectionPicker menu content uses floating width role `picker` (`20rem` with
available-width cap). Its scrollable list is not capped by a raw rem value:
`QuantizedMenuScrollArea` computes the visible list height as whole `default`
rows after subtracting the search header and any fixed footer from the Radix
available height. The `20rem` role width is required because the right action
slot is fixed at `10ch`; narrower menus leave too little scan width for Russian
collection names. The ordinary Card overflow menu around it remains role
`command`.
Keyboard-triggered scroll cannot transfer ownership to a stationary pointer:
rows ignore `pointerenter` and ignore the first post-keyboard `pointermove` if
its coordinates match the last known pointer position. Pointer hover never
calls `scrollIntoView`; only keyboard-owned active row may auto-scroll.
Slot сохраняет `h-8` vertical centering. Count не должен прыгать при появлении
action button.

Batch Connect must reuse the same CollectionPicker row/search/action language
through `BatchCollectionPicker`, not a separate hand-styled list. Batch changes
only membership semantics: all selected cards connected -> `Disconnect`;
otherwise -> `Connect`; no partial selected-card counters like `1/3`.

Stable preview invariant: обычный sidebar и link-editor используют один и тот
же row component и один thumbnail strip. При открытии карточки нельзя
размонтировать строки каналов или `<img>` thumbnail'ы; меняется только правый
row-action slot (`count/menu` ↔ `Connected/Connect/Disconnect`). Это убирает blink превью при
переключении в Detail.

### Создание коллекции

Новую коллекцию называют прямо в списке бокового меню. Пути входа: кнопка `+`
во втором ряду верхней панели, ⇧⌘N, бросок карточки на строку создания и
`Enter` в `Find or create...`.

**Строка создания.** `NewChannelRow` (`data-sidebar-new-channel-row`, ключ
строки `create-channel`) стоит вверху списка, сразу под `Everything`, внутри
списка строк (`data-sidebar-rows`). В покое строки нет. Она видна, только пока
у неё есть работа: пока коллекцию называют (тогда это поле имени) и пока
тащат карточку (тогда это цель броска, которая создаёт коллекцию сразу с этой
карточкой). `Everything` остаётся на месте и не прячется. Порядок строк для
клавиатуры и общих швов задаёт `buildSidebarRowOrder`: `Everything`, строка
создания, коллекции.

**Цель броска: строка таблицы, как остальные** (замечание пользователя от
07.10.2026: подпись перечёркивала линии колонок). Подпись `New Collection`,
имя команды, стоит в колонке имени (`SidebarRowTitleCell`) и обрезается её
растворением, линию колонки не пересекает. Ячейка превью пустая. Плюс стоит
на месте счётчика, в правой зоне. Высота строки общая, своих отступов нет.
У строки свой шов (`data-sidebar-row-surface`), и когда карточка над ней, шов
загорается акцентом, как у любой строки, над которой держат карточку. В свёрнутом
меню строка остаётся одной ячейкой: подпись с обрезкой и плюс справа.

**Движение.** Появляясь, строка раздвигает список: обёртка
`data-sidebar-row-part` раскрывает высоту от нуля до своей за `150ms` на
`cubic-bezier(0.22, 1, 0.36, 1)` (keyframes `sidebar-row-part` в
`src/styles/global.css`). Уходит строка мгновенно. Других анимаций у создания
нет: варианты со сворачиванием `Everything`, удержанием введённого имени и
обратным ходом при отмене опробованы и отклонены 02.10.2026. При
`prefers-reduced-motion` раскрытие гасит общее правило `global.css` (Ф12 в
SPEC_AUDIT_FIXES.md): строка встаёт сразу.

**Поле имени и кнопка `Create`.** Через строку проходит правая зона списка
(`--sidebar-zone`) с той же направляющей, что у строк коллекций
(`data-sidebar-editable-row-guideline`, `w-px bg-sidebar-border`,
`right: var(--sidebar-zone)`); в compact-режиме направляющей нет. Поле имени
кончается перед зоной: правый отступ строки ввода равен зоне, пикселю
направляющей и `8px`. Кнопка `Create` стоит в зоне по правилам кнопки
`Connected`: `8px` от краёв зоны со всех сторон, ширина равна зоне минус
`16px`, класс `SIDEBAR_ROW_ACTION_BUTTON_CLASS`. За подписью идёт знак клавиши
`↵` в `font-mono text-sm font-normal text-muted-foreground`, как горячие
клавиши нижней панели. Знак берётся из общей таблицы клавиш
`bindingLabel({ key: "Enter" })` (`src/lib/commandBinding.ts`), руками в
строке не пишется. Доступное имя кнопки `Create`, клавиша объявлена через
`aria-keyshortcuts="Enter"`. `Enter` или уход фокуса с непустым именем создают
коллекцию; пустое имя и `Escape` отменяют создание.

**Начальное имя.** Если перед `+` или ⇧⌘N в фильтре набран текст, поле имени
открывается с этим текстом (trimmed), каретка стоит в конце.

**Место в порядке.** Коллекция, созданная через `+`, ⇧⌘N, бросок карточки или
`Enter` в фильтре, встаёт первой в ручном порядке: после `createChannel`
приложение вызывает `reorderChannels`, новая коллекция получает позицию 0,
остальные сдвигаются на одну. Известное ограничение: коллекция из меню
`Connect` карточки, из `Create collection` переключателя коллекций, из
перетащенного медиа или выделенного текста и из расширения пока встаёт
последней.

**Открытая карточка.** Кнопка `+` стоит на том же месте, что над закрытым
списком: у правого края колонки, в `8px` от него. Если коллекции открытой
карточки показаны в режиме `Connected`, новая коллекция сразу получает эту
карточку, как при броске карточки на строку создания. В режиме `All`
создаётся обычная пустая коллекция.

**Фильтр.** Пока в `Find or create...` набран текст, число коллекций во
втором ряду считает только оставленные фильтром. `Enter` без выбранной
стрелками строки открывает коллекцию с набранным именем (без учёта регистра),
а если такой нет, создаёт её по правилам выше (первой, с открытой карточкой в
режиме `Connected`) и очищает фильтр. Строка создания не входит в навигацию
стрелками по результатам фильтра.

### Окно настроек (Settings window)

Отдельное компактное окно (label `settings`, 760×560, min 640×460), второй
Vite-entry (`settings.html` → `src/settings/`) — не тянет App/Grid/Detail.
Спецификация: SPEC_SETTINGS_WINDOW.md.

Хром консистентен с хромом вкладок: `titleBarStyle: Overlay` + `hiddenTitle`,
верхний бар `h-8 bg-chrome border-b border-border` с traffic-light reserve
`80px`, заголовок `Settings` (`font-mono text-sm text-muted-foreground`),
`data-tauri-drag-region`; native background синхронизируется через
`useNativeWindowChromeSurface("--chrome")`, как у вкладок: страница сообщает
цвет бэкенду (`report_window_surface`).

Лэйаут: левая навигация `176px` (`border-r border-border`, строки
`h-8 rounded-1 px-2 font-mono text-sm`, язык сайдбара; активная `state-active
text-foreground`, остальные `text-muted-foreground` с hover до foreground) +
контент `p-s4`, заголовок раздела `text-lg font-semibold`, секции `gap-s3`.

Строка настройки: лейбл слева (`text-base`) с опциональной подписью
(`text-sm text-muted-foreground`) под ним, контрол справа. Никаких новых
токенов — всё из существующей системы.

Строка пространства (Spaces): имя → путь → сводка
`N elements · N markdown · N media · N files · size` (голые числа — язык
счётчиков; `formatBytes`: десятичная база как в Finder). Клик по строке
показывает пространство во вкладке (`show_space`, 03.10.2026): выбирает его
вкладку, выбранную последней, а без неё открывает новую вкладку в последнем
окне. Строки пространств, открытых хотя бы в одной вкладке, получают
`state-active` (канон выбранного, без текстовых меток; таких строк может быть
несколько), остальные `bg-accent hover:state-active`. Строки
перетаскиваются (dnd-kit, distance 8 — клик не drag); порядок в config —
канонический для всех списков пространств. Правый слот фиксированного размера
(`size-8`): `⋯`-кнопка `opacity-0 → group-hover/focus-within:opacity-100`
(opacity-канон карточек, открытое меню пиннит видимость). Никаких постоянных
кнопок у строк: единственная команда `Remove Space` живёт в `⋯`-меню
(`variant="detach"` + `Unlink`); `Remove Space` доступен всегда, вкладки
забытого пространства переходят к выбору пространства. Полные зафиксированные решения:
SPEC_SETTINGS_WINDOW.md § Design decisions.

Межоконная синхронизация: settings-окно пишет localStorage (общий per origin)
и эмитит Tauri-событие `settings-changed` (`{ key }`); страницы вкладок и
полосы вкладок перечитывают изменённый ключ. Тема применяется каждым окном самостоятельно при старте
(`applyTheme(getStoredTheme())` до первого рендера) — модуль
`src/lib/themeMode.ts`.

Graph имеет отдельный пункт в левой навигации Settings. Три стандартные
`SettingRow` с `Checkbox` управляют `Collections`, `Wikilinks` и
`Related notes`; все значения сохраняются одним объектом
`mine.graphPreferences`. В самом Graph View нет дублирующего settings trigger,
search field или scope selector. Текущий route автоматически определяет
collection/library snapshot.

### Сетка

Masonry с round-robin распределением по колонкам. Gap: 32px (`--spacing-s5`). Минимальная ширина карточки: 220px; максимальная ширина не фиксируется токеном и определяется алгоритмически перед переходом к следующему числу колонок. Лента должна ощущаться как бесконечный canvas: scroll может быть быстрым, но медиа не должны появляться заметными рывками после входа карточки во viewport.

Performance contract не сводится к увеличению DOM window. Grid использует
отдельные адаптивные бюджеты для render window, image priority window и planned
media preload/decode window. Целевой scroll-readiness контракт описан в
[SPEC_FEED_SCROLL_PERFORMANCE.md](SPEC_FEED_SCROLL_PERFORMANCE.md): bounded
DOM window, eager-зона для ближайших картинок и более широкий preview-only
`Image.decode()` preloader без дополнительных mounted cards и без original
source media в hot scroll path.

Top inset ленты на главной: 64px от permanent top chrome до верхнего края
masonry layout складываются из второго shell top-bar level `h-8` и внутреннего
virtual layout inset `32px` через `marginTop`. Inset живёт на внутреннем
virtual layout, а не на scrollport.

Паддинги сетки единые для раскрытого и свёрнутого сайдбара: 32px по бокам в
обычном дизайне и 16px в alt design. Сворачивание сайдбара не увеличивает
боковые отступы карточек и не компенсирует ширину rail внутри Grid.

Пустой канал показывает только текстовый placeholder, без card surface, quote
marker, border, иконок или CTA-кнопок. Placeholder центрируется в видимом
viewport Grid и оформляется как plain italic text: `p`, `text-center`,
`text-base italic text-muted-foreground`. Текст: `Cards connected to this
channel will appear here.` Для `Everything` и пустой search выдачи этот
placeholder не показывается.

Карточки: линия рамки 1px цвета `--card-frame-color` (по умолчанию `--border`) поверх содержимого (раздел «Линия рамки поверх содержимого» ниже), без скругления по умолчанию (`rounded-0`). Обводка = +1 уровень к фону. Hover не меняет frame карточки: без смены цвета рамки, второй линии, тени, glow, inset overlay или transition. Hover-affordance карточки — только action controls. Keyboard/focused state принадлежит GridItem, не Card: focused item получает `data-feed-grid-item-focused="true"`, а существующий Card frame меняет цвет своей линии (`--card-frame-color`) на тот же token, что left sidebar row focus seam (`var(--border-accent)`), с тем же `180ms cubic-bezier(0.22, 1, 0.36, 1)` transition. Без второй линии, слоя поверх линии рамки, ring/glow или `foreground` border; Card не получает focus props/classes.

Grid поддерживает один interaction owner: `keyboard` или `pointer`.
Arrow-навигация переводит ленту в keyboard mode и отключает CSS-hover affordance
карточек (`hoverEnabled=false` у CardHoverMenu), поэтому неподвижный курсор не
может одновременно подсветить другую карточку. Реальное движение pointer с
новыми координатами возвращает pointer mode; stationary pointermove после
keyboard-scroll игнорируется.

Overflow menu, opened from focused-card `Cmd+K`, pins its anchor visuals while
the menu is open: the anchor keeps `data-feed-grid-item-focused`, `⌘K` badge,
frame focus and graphic wash even after pointer movement switches Grid back to
pointer mode. This pin is visual only; pointer hover works on other cards. The
pinned anchor keeps `CardHoverMenu.hoverEnabled=false`, so bottom hover actions
do not appear under an open keyboard menu.

Графические поверхности карточек помечаются единым `GraphicSurface`/`data-card-graphic-surface` контрактом. При keyboard focus GridItem применяет только к этим surfaces дополнительный wash: light theme `oklch(0 0 0 / 14%)` затемняет, dark theme `oklch(1 0 0 / 18%)` высветляет. Текстовые карточки и текстовые области mixed cards не получают этот state.

Focused GridItem дополнительно показывает shortcut badge в левом верхнем углу: `data-feed-grid-action-badge`, внутри `data-feed-grid-action-layer` (`absolute inset-px`), затем `absolute left-2 top-2`, `h-6`, `px-[1ch]`, `rounded-1` (3px), `bg-component-fill`, `text-sm font-semibold text-foreground`, `pointer-events-none`. Action layer компенсирует 1px Card frame, поэтому offsets badge считаются из той же внутренней плоскости карточки, что и Card Hover Menu controls: `top-2` как у верхних кнопок, `left-2` как у нижнего ряда коллекций. Текст badge `⌘K`; он сообщает scoped action shortcut для открытия card overflow menu и не является hover affordance. `Cmd+K` toggles top-right `More`/overflow menu; нижний ряд коллекций не появляется, карточка не поднимается.

Состояния карточки ленты сведены в одну систему
([SPEC_CARD_STATES.md](SPEC_CARD_STATES.md), 28.09.2026). Наведение мышью
показывает только кнопки карточки. Клавиатурный фокус красит собственную
границу карточки в `--border-accent`, картинка при этом получает затенение
`--graphic-card-focus-overlay`, текстовая карточка только границу. Подсветка
от строки коллекции в боковом меню красит только границу, без затенения:
строка зажигает много карточек разом. Подсветка ленты от строки включается
только при задержке и медленном курсоре, молчит при прокрутке и сменяется
растворением (С7). Сама строка (название, число, кнопка) отвечает курсору
сразу (С7.10). Пилюли `Connected` у коллекций карточки показывает только
клавиатурный фокус, мгновенно (С4); курсор мыши меню не меняет.
Затенение лежит на окне медиа (`[data-card-graphic-surface] >
[data-card-lift="window"]::after`) и поднимается с ним при подъёме карточки.
Выделенная карточка (`data-feed-grid-item-selected="true"`) красит ту же
границу в `--feed-selection-frame` (`oklch(0.145 0 0)` в светлой теме,
`oklch(0.985 0 0)` в тёмной) и тоже затеняет картинку. Ничего не рисуется
снаружи карточки, masonry layout не меняется, выделение сильнее остальных
состояний только яркостью границы. Подсветка от строки коллекции помечается
`data-feed-grid-item-collection-lit="true"`.

Marquee selection rectangle принадлежит Grid и рисуется только во время
empty-area drag внутри `data-grid-layout`: `data-feed-grid-marquee-selection`,
`border-radius: 0`, `pointer-events: none`, fill: поверхность ленты со слоем
состояния, непрозрачной смесью, на `72%`
(`color-mix(in oklch, color-mix(in srgb, var(--surface), var(--foreground) var(--active-alpha)) 72%, transparent)`,
для читаемости поверх контента), border `--border`. Без glow, blur,
gradient, shadow или цветных selection-токенов.

Команды группового выделения появляются при `selectedSlugs.size >= 1`. Островка
внизу ленты с 23.08.2026 нет: команды стоят слоем в половине второго ряда над
лентой (`GroupSelectionCommands`, портал в `data-secondary-selection-bar`),
своей поверхности у них нет. Слева счётчик `{n} element(s) selected`
(`font-mono text-sm text-muted-foreground`), справа одна `ChromeActions`:
`Connect` со значком, `Disconnect` только в коллекции, `Merge` только при двух
и более выбранных, красный `Delete` и последним крестик `Clear selection`.
Правый край и промежутки по правилу «Иконочные кнопки хрома», как у меню и
закрытия открытой карточки: `8px` от края окна до подсветки крестика
(`--chrome-edge-pad`), `4px` между кнопками; у ряда только левый отступ
`--main-secondary-pad-x`. Крестик это `ChromeCloseButton` (`Button
variant="chrome" size="chrome-icon"`) с подсветкой `24×24` при наведении
(решение пользователя 05.10.2026; прежде команды шли сразу за счётчиком, а
крестик был `ghost` размером `32px` без подсветки). При сужении ряда первым
обрезается счётчик, команды сохраняют размер; ряд прокручивается, только
когда не помещаются сами команды. `Connect`, `Disconnect` и `Merge` в варианте
`default` (`Disconnect` с `text-detach`), `Delete` в варианте `destructive`.
Полный контракт:
[SPEC_GROUP_SELECTION.md](SPEC_GROUP_SELECTION.md).

Focused-card batch `Cmd+K` menu следует тому же icon economy: иконка есть у
`Connect`, у `Disconnect`, `Merge` и `Delete` иконок нет, но сохраняется
пустой leading-slot для выравнивания текста.

Group drag preview использует macOS-style drag flocking: каждый видимый слой —
реальный frozen card preview из selected set, не пустая plate и не interactive
`Card`. До четырёх слоёв видимы; полный payload остаётся в `dragSlugs`, а при
переполнении показывается count badge. Front card не трансформируется; back
cards используют только integer `translate3d` + малые углы:
`-6/-6/-0.9deg`, `7/-11/0.75deg`, `-2/-16/-0.45deg`. `scale(...)` запрещён.
Stack не вводит новые радиусы и не двигает реальные masonry cards; команды
выделения скрыты во время block drag.

Все карточки ленты стоят на одной поверхности `--card`, уровне второго ряда хрома, в обеих темах (решение пользователя 06.10.2026; прежняя отдельная заливка `--accent` у постов в тёмной теме убрана). Заливка рисуется обычным цветом, как у хрома с тем же токеном. Поверхность лежит на обрезке содержимого (`[data-card-frame-clip]`), линия рамки поверх неё (раздел «Линия рамки поверх содержимого»). С 06.10.2026 карточка одна для всех видов записей: вид задаёт только содержимое, своих полей и элементов у ссылки, файла или поста нет ([SPEC_CARD_UNIFIED.md](SPEC_CARD_UNIFIED.md)).

#### Линия рамки поверх содержимого

Линия рамки карточки рисуется последней, поверх всего, что карточка держит (`[data-feed-card-frame]::after`, 1px цвета `--card-frame-color`), а содержимое обрезано по середине линии (решение пользователя 06.10.2026: «нужен pixel perfect результат»). Рамка устроена в три слоя: сама рамка с отступом 0.5px и линией поверх, обрезка `[data-card-frame-clip]` с углом на 0.5px меньше радиуса и поверхностью `bg-card`, поле содержимого `[data-card-frame-content]` ещё на 0.5px дальше, там же, где его оставляла граница в 1px, поэтому раскладка и высоты не меняются. Слот медиа (`GraphicSurface`) обрезает медиа слоем `[data-card-media-clip]`, который выходит на 0.5px за видимый край слота с каждой стороны и скруглён по середине линии (`--card-frame-line-radius`).

Почему так. Граница в 1px выравнивается по физическим пикселям, а обрезка содержимого нет; при отдельной границе с медиа внутри они расходились на долю пикселя, и оставались бледный столбец сбоку от картинки, полоска под ней, подъеденный угол. Когда линия лежит поверх, а край медиа под её серединой, любое расхождение закрыто непрозрачной линией, внутренний край линии сглаживается с медиа, внешний с фоном страницы. Видимый угол медиа это внутренний угол линии.

В карточке с рамкой, где медиа стоит сверху, а под ним текст (SPEC_FEED_DISPLAY.md, Д20), медиа закрывается обводкой: это та же линия рамки, отражённая под медиа. Целое кольцо с радиусом карточки R и высотой 2R (2px при углах 0), нарисованное так же, как линия рамки, со срезанной верхней половиной: нижний край и нижние углы обводки повторяют верхний край и верхние углы рамки пиксель в пиксель. Кольцо во всю ширину рамки, его бока лежат на линиях рамки. Обводка рисуется поверх медиа, обрезка медиа заходит под неё на 0.5px; под медиа её нижний край занимает верхний пиксель текстовой части, высота карточки не меняется, при подъёме (С8.3) она поднимается с медиа. Цвет и переход те же, что у линии рамки (`--card-frame-color`, `--card-frame-fade`). Есть ли текст под медиа, решает описание карточки (`textUnderMedia`), не положение в разметке. Медиа, которое заканчивает карточку, несёт то же кольцо в своей обрезке поверх окна: в покое его закрывает нижняя линия рамки, при подъёме оно поднимается с окном над подписью или рядом коллекций.

Expanded image preview использует минималистичное разделение primary/secondary plane: фон страницы опускается до третичной ступени через `background: oklch(0.14 0 0 / 72.08%)` (холст тёмной темы, доля 1 минус третичная тёмная) и `backdrop-filter: saturate(0.55)` без blur; foreground image получает только утилитарное отделение: тень ступени К11 `shadow-2xl` (`0 25px 50px -12px rgb(0 0 0 / 0.25)`) и `outline: 1px solid oklch(0.243 0 0)` (линия тёмной темы). Просмотр изображения всегда в тёмной теме. Кнопка выхода из preview — не `X`, а inward-arrows `Minimize2` с действием `Collapse image preview`.

## Архитектурные принципы

- **Монохром** — палитра строго чёрно-белая с оттенками серого. Цвет только для семантики: `destructive` (красный), `chart-*` (графики)
- **Тёмная тема по умолчанию** — светлая через `@media (prefers-color-scheme: light)`. Тёмно-серый фон (#0C0C0C, sRGB 0.049)
- **Без теней и градиентов** — исключения: hover-оверлей на карточках изображений (`bg-gradient-to-t from-black/60`), утилитарная тень всплывающих элементов (для отделения слоя от контента)
- **1px solid borders** — основной визуальный разделитель. Без двойных линий, пунктиров, инсетов
- **Нативное ощущение** — `-webkit-user-select: none` на кнопках и навигации, `overscroll-behavior: none`, скрытые скроллбары WebKit
- **Resize handle без выделения** — sidebar resize gesture блокирует WebKit
  text selection уже на `pointerdown`: `body.sidebar-resizing`,
  `preventDefault()`, clear `document.getSelection()`, transparent
  `::selection`.
- **Системные шрифты.** SF Pro и SF Mono приходят с macOS, сборка не несёт файлов шрифтов, кроме необязательного Departure Mono (`font-display: swap`).

## Рендеринг

- **Antialiased** — `body` задаёт `-webkit-font-smoothing: antialiased` и `-moz-osx-font-smoothing: grayscale` для соответствия нативному рендерингу macOS
- **Скрытые скроллбары** — `.overflow-y-auto::-webkit-scrollbar { display: none }` глобально
- **Мгновенная навигация** — без `scroll-behavior: smooth`, переходы между каналами происходят мгновенно

## Brand Identity

Текущий знак Mine — строчная `m` из Redaction 100 Italic. Это единственный
актуальный logo/glyph variant в системе; сравнительные матрицы и альтернативные
wordmark-пробы не являются частью продукта.

Иконки не масштабируются одним bitmap'ом на все поверхности. У каждой поверхности
свой контракт:

| Поверхность | Asset contract |
|---|---|
| iOS app icon | Белый квадратный source asset; скругление и mask применяет iOS. В source-файле не рисуется собственная рамка или тень |
| macOS/Tauri app icon | Прозрачный canvas с inset white rounded tile и чёрной `m`, чтобы Dock не показывал oversized белый квадрат |
| Browser extension toolbar | Transparent square PNGs `16/24/32/48/128`; внутри inset white circle и чёрная `m`, без оранжевого фона и без app-like squircle |
| Instagram feed overlay | Белая круглая кнопка поверх поста; внутри отдельный glyph-only asset `clipper-overlay-32.png`, а не toolbar/app icon |

## Расширение (браузерный попап)

Попап расширения — проекция основного приложения в браузер. Собирается через Vite (`vite.extension.config.ts`), импортирует те же компоненты и токены через алиас `@/`.

### Что общее

- **CSS-токены** — `@import "@/styles/global.css"` в `popup-layout.css`
- **Шрифты.** Системные, как в приложении: стек задаёт `global.css`, файлов шрифтов в расширении нет.
- **Компоненты** — `<Button>`, `<Input>`, `<ScrollArea>` из `@/components/ui/*`
- **Утилиты** — `cn()` из `@/lib/utils`
- **Цвета** — все семантические токены (`--foreground`, `--muted-foreground`, `--border`, `--accent`)
- **Скругления, отступы, типографика** — из общей шкалы

### Что отличается

| Аспект | Основное приложение | Расширение |
|---|---|---|
| Размер окна | Полноэкранное | 360x600px (popup) |
| Layout | Sidebar + Grid + Detail | Компактная форма (preview + channels + save) |
| Навигация | react-router, стрелки, scoped card/Detail Cmd+K | Нет — одно состояние |
| IPC | Tauri commands | Native messaging (`chrome.runtime.sendNativeMessage`) |
| CSS entry | `global.css` | `popup-layout.css` (импортирует `global.css` + добавляет popup-размеры) |

### Popup-специфичные стили

```css
/* popup-layout.css */
@import "@/styles/global.css";
body { width: 360px; min-height: 200px; max-height: 600px; overflow-y: auto; }
```

Никаких собственных токенов, цветов, шрифтов или компонентов. Дрейф дизайна невозможен — единственный источник правды в `global.css`.
