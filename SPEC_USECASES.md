## Референсы

| Приложение | Метафора | Организация | Сильная сторона |
|---|---|---|---|
| **Are.na** | Граф идей, гипертекст | Ручная: каналы + связи | Блок живёт в нескольких каналах, навигация по связям |
| **Cosmos** | Визуальная студия вдохновения | Полуавтомат: кластеры + ИИ-теги | Мультимодальный поиск: цвет, настроение, семантика |
| **Mymind** | ИИ-расширение памяти | Автомат: ИИ всё организует сам | Сохраняй всё, не думай об организации |

## Позиционирование Mine

Локальный визуальный букмаркинг. Файлы на диске, коллекции вместо папок, полный контроль над данными. Без облака, без подписки, без ограничений.

От **Are.na** берём: каналы, блоки, связи, блок в нескольких каналах.
От **Mymind** берём: мгновенное сохранение, умные карточки.
От **Cosmos** берём: визуальный поиск (позже, через эмбеддинги).

Чего **не берём** (социальное): подписки, ленты, чужие каналы, совместное редактирование, публичный доступ.

## UC-01: Быстрое сохранение из браузера

**Актор:** пользователь просматривает веб

**Сценарий:**
1. Находит интересное изображение/статью/ссылку в браузере
2. Нажимает расширение Mine (или горячую клавишу)
3. Выбирает коллекции из списка или вводит новые
4. Контент сохраняется в vault:
   - Ссылка → `.md` с frontmatter (url, `Mine Collections`) + body H1 + миниатюра (og:image)
   - Статья/фрагмент → `.md` с frontmatter + текст в теле + скачанные изображения
   - Изображение → `.md` с frontmatter + файл изображения
5. В приложении появляется новая карточка

**Пример файла на диске (ссылка):**
```
stripe-homepage.md
stripe-og.png
```

## UC-02: Drag-and-drop файлов в приложение

**Актор:** пользователь с файлами на диске

**Сценарий:**
1. Открыт канал (или общий вид) в приложении
2. Перетаскивает один или несколько файлов из Finder в окно
3. Для каждого файла: копирование в vault + создание `.md` с frontmatter
4. Если открыта конкретная коллекция — wikilink этой коллекции автоматически добавляется в `Mine Collections`
5. Генерируются thumbnails
6. Карточки появляются в сетке

**Поддерживаемые типы:**
- Изображения: PNG, JPG, WEBP, GIF, SVG
- Документы: PDF, MD, TXT
- Видео: MP4, MOV (thumbnail из первого кадра)
- Любые файлы: отображаются с иконкой типа

## UC-03: Просмотр канала — сетка карточек

**Актор:** пользователь исследует свою коллекцию

**Сценарий:**
1. В боковой панели выбирает коллекцию
2. Основная область показывает все блоки с wikilink на эту collection page в `Mine Collections`
3. Плавная прокрутка даже на тысячах карточек (виртуализация)
4. Карточки адаптируются по типу:
   - **image** — thumbnail с соотношением сторон оригинала
   - **link** — миниатюра страницы + заголовок + домен
   - **article** — og:image или первые строки текста
   - **video** — кадр с иконкой воспроизведения
   - **file** — иконка типа + имя + размер

**Режимы отображения:**
- Сетка (по умолчанию) — равномерные столбцы
- Masonry — разная высота, плотная укладка
- Список — строки с деталями

**Сортировка:**
- По дате добавления (по умолчанию)
- По дате изменения файла
- По имени
- По типу
- Вручную (drag-and-drop)

## UC-04: Блок в нескольких коллекциях

**Актор:** пользователь организует коллекцию

**Сценарий:**
1. Просматривает карточку в коллекции "Typography"
2. Нажимает collection picker / checkbox connect
3. Добавляет коллекцию: "Design Inspiration"
4. В frontmatter файла обновляется `Mine Collections`:
   `["[[Typography]]", "[[Design Inspiration]]"]`
5. Блок теперь виден в обеих коллекциях
6. На карточке отображается бейдж с количеством каналов
7. Клик по бейджу — список каналов (тегов)

**Просмотр связей:**
- На карточке: collection badges
- В детальном виде: все теги + связанные блоки через wikilinks

## UC-05: Surface Search

**Актор:** пользователь ищет карточки или каналы без ухода с текущей страницы.

**Сценарий A — поиск в текущем Grid:**
1. Пользователь находится на Everything или внутри конкретной коллекции.
2. Нажимает `Cmd+F`.
3. В правой content pane открывается inline search input.
4. По мере ввода текущий Grid фильтруется по `display_title`, filename fallback,
   description и полному Markdown body.
5. Результаты остаются карточками того же Grid и сортируются по релевантности:
   title matches выше body-only matches.
6. Если совпадение найдено в article body, карточка показывает excerpt вокруг
   первого совпадения и подсвечивает matched text.
7. Если query на другом языке (`память`) семантически соответствует английской
   карточке (`memory is a flock of birds`), hybrid search может вернуть эту
   карточку даже без буквального совпадения. В этом случае карточка показывает
   semantic excerpt без фальшивой подсветки.
8. Очистка query возвращает обычный порядок текущей страницы.

**Сценарий B — поиск в Sidebar:**
1. Пользователь нажимает `Shift+Cmd+F`.
2. В левом Sidebar открывается inline search input.
3. Фильтруются только каналы; текущий Grid route не меняется.
4. `Escape` очищает query, повторный `Escape` закрывает Sidebar search.

`Cmd+K` не участвует в поиске и остаётся scoped-сценарием карточки/Detail.

## UC-06: Внешние изменения (работа через Finder)

**Актор:** пользователь работает с файлами вне приложения

**Сценарий:**
1. Пользователь копирует `.md` + медиафайл в vault через Finder
2. File watcher обнаруживает изменения
3. Новые `.md` файлы: парсится frontmatter → индексация + thumbnail
4. Изменённые `.md` файлы: перечитывается frontmatter → обновление индекса
5. Удалённые файлы: убираются из индекса + thumbnail
6. UI обновляется в реальном времени

**Принцип:** файловая система — источник правды. Любое действие в Finder эквивалентно действию в приложении. Пользователь может редактировать frontmatter в текстовом редакторе — приложение подхватит изменения.

## UC-07: Создание и управление каналами

**Актор:** пользователь организует пространство

**Сценарии:**
- **Создать канал из тега:** в sidebar рядом с тегом — кнопка «Сделать каналом». Тег закрепляется в sidebar
- **Создать канал с нуля:** вводит название → создаётся тег, который сразу становится каналом
- **Переименовать:** новое имя → тег обновляется во всех `.md` файлах
- **Удалить канал:** тег теряет статус канала, но остаётся в frontmatter файлов (блоки не удаляются)
- **Описание, цвет, иконка:** хранятся в `.arena/index.db` (метаданные канала)

## UC-08: Детальный просмотр блока

**Актор:** пользователь изучает конкретный элемент

**Сценарий:**
1. Клик по карточке в сетке
2. Открывается детальный вид (lightbox):
   - **image** — полноразмерное изображение с зумом
   - **link** — миниатюра + метаданные + кнопка «Открыть в браузере»
   - **article** — рендеринг Markdown, режим чтения
   - **video** — встроенный плеер
   - **file** — иконка + Quick Look
3. Под контентом — атрибуты из frontmatter: коллекции, дата, источник, URL
4. Связанные блоки через wikilinks
5. Действия: добавить тег, удалить, открыть в Finder, скопировать ссылку

## UC-09: Импорт из Are.na

**Актор:** существующий пользователь Are.na

**Сценарий:**
1. Настройки → Импорт → Are.na
2. Авторизация через Are.na API (токен)
3. Список каналов пользователя с превью
4. Выбор каналов для импорта (чекбоксы)
5. Импорт:
   - Для каждого блока: `.md` с frontmatter + медиафайл
   - Имя канала Are.na → collection page + wikilink in `Mine Collections`
   - Блок в нескольких каналах Are.na → несколько wikilinks в `Mine Collections`
6. Прогресс-бар с деталями

## UC-10: Быстрые действия

**Актор:** опытный пользователь

**Сценарий:**
1. `Cmd+K` при keyboard-focused карточке открывает её scoped overflow menu.
2. `Cmd+K` в Detail открывает верхнее scoped overflow menu.
3. Глобальной command palette и глобального Search действия нет; поиск живёт
   только в `Cmd+F` / `Shift+Cmd+F` surface modes.
   - Сменить вид (сетка/masonry/список)
   - Открыть vault в Finder
   - Пересобрать индекс
