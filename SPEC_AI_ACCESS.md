# SPEC_AI_ACCESS

Related documents: [ARCHITECTURE.md](ARCHITECTURE.md) | [SPEC_SEARCH.md](SPEC_SEARCH.md) | [SPEC_STORAGE.md](SPEC_STORAGE.md) | [SPEC_VAULT_LIFECYCLE.md](SPEC_VAULT_LIFECYCLE.md)

Доступ AI-агентов к материалам пространства. Статус: **SPEC, требования на
одобрении** (обновлено 27.08.2026 под решение 044). Реализация не начата.

## Зачем

Главная ценность интерфейса — производные данные, которых в сырых файлах
нет: гибридный поиск (FTS5 плюс семантические эмбеддинги), модель коллекций,
резолв медиа-ссылок, метаданные карточек. После решения 044
([SPEC_BLOCK.md](SPEC_BLOCK.md)) вид карточки — производное от содержимого;
поля `type` в файлах нет, и интерфейс не должен его изобретать заново.

При этом интерфейс **самодостаточен**: сырое содержимое — тело карточки,
список карточек, пути медиа — отдаётся через него же. У потребителя без шелла
(claude.ai, Desktop, телефон) другого канала нет, а агент с шеллом не обязан
жонглировать двумя способами доступа. «Это можно сделать grep-ом» — не
критерий исключения; критерий — нужна ли операция для работы с материалами
(уточнение 25.08.2026 после возражения пользователя).

## Решение

Ядро → CLI → MCP, в этом порядке (обсуждение 24.08.2026):

- читающий API выносится в ядро (Rust, тот же крейт);
- первым слоем — CLI `mine`: дёшево, отлаживаемо, полезно и человеку;
- MCP-сервер — этап 2, тонкий адаптер над тем же ядром (`mine mcp`),
  когда появится потребитель без шелла (claude.ai, Desktop, телефон).
  Совместимость закладывается сейчас: JSON-контракт CLI и есть будущие
  схемы MCP-инструментов.

## Требования: ядро

- **Read-only гарантия.** SQLite открывается в режиме только для чтения;
  никакой записи в индекс, в исходники, в кэш превью. Watcher не поднимается,
  реконсиляция не запускается.
- **Сосуществование с приложением.** Индекс в WAL; читающее подключение не
  блокирует запись работающего приложения и не падает от неё.
- **Свежесть — честная.** Ядро читает то, что индекс успел записать. Если
  приложение не запущено и хранилище менялось извне, данные могут отставать;
  это констатируется, не чинится (реконсиляция — собственность приложения).
- **Выбор пространства.** По умолчанию — `vault_path` из `config.json`
  приложения; любое из `known_vaults` — по флагу. Путь вне известных
  пространств отклоняется с внятной ошибкой.
- **Семантический поиск.** Использует модель fastembed из кэша приложения.
  Модели нет — поиск деградирует до лексической части с пометкой в ответе,
  не падает.

## Требования: CLI `mine`

Отдельный bin target существующего крейта, как `cold-space-audit`.

Подкоманды первой очереди:

| Команда | Назначение |
|---|---|
| `mine spaces` | Известные пространства, активное помечено |
| `mine search <query> [--space P] [--limit N]` | Гибридный поиск, результат с score и слагами |
| `mine collections [--space P]` | Коллекции со счётчиками |
| `mine cards --collection C [--limit N --offset K]` | Карточки коллекции |
| `mine card <slug>` | Полная карточка: frontmatter, body, абсолютные пути медиа |

Согласование с решением 044: в выводе нет поля `type`. Карточка описывается
содержимым — `body`, список медиа с путями, `url` — и производным
`card_kind` («какой карточкой это показывается»), помеченным как derived.
Фильтр «только медиа/только текст» в `mine search`, если появится, работает по
производному виду, а не по несуществующему полю.

Контракт вывода:

- по умолчанию — человекочитаемый текст;
- `--json` — стабильный версионированный JSON (`{"contract": 1, …}`);
  это же будущие схемы MCP-инструментов;
- типизированные коды возврата: 0 успех, 2 неверные аргументы,
  3 пространство недоступно, 4 не найдено;
- ошибки — в stderr, машинный вывод — только в stdout.

## Требования: MCP (этап 2, отдельная приёмка)

- `mine mcp` — stdio-сервер в том же бинарнике;
- инструменты повторяют подкоманды CLI один в один, схемы — из JSON-контракта;
- проектируется после приёмки CLI; сейчас фиксируется только совместимость.

## Вне объёма

Запись через AI (создание и правка карточек), удалённый доступ и
аутентификация, MCP resources и стриминг.

## Тесты

- интеграционные тесты CLI против фикстурного пространства: каждая
  подкоманда, оба формата вывода, коды возврата, read-only (снимок файлов
  до и после прогона идентичен);
- поиск без модели эмбеддингов: лексическая деградация с пометкой;
- параллельный прогон с открытым на запись индексом.
