## Источник истины

`src/lib/commandRegistry.ts` — единственное место, где команда получает
сочетание, имя и контекст. Привязка — данные (`CommandBinding`: клавиша плюс
модификаторы), а не рукописный матчер: подпись и сопоставление выводятся из
одной записи, поэтому переназначение вообще возможно. Нижняя панель, оверлей ⌘/ и обработчики читают
оттуда: сочетание не может разойтись между местом, где оно показано, и местом,
где оно реализовано. Матчеры проверяют модификаторы точно: команда на ⌘ не
срабатывает на ⌘⇧.

Нативное меню (Rust, `src-tauri/src/lib.rs`) дублирует четыре команды со
своими акселераторами: Settings ⌘,, Find Elements ⌘F, Find Collections ⌘⇧F,
Hide Sidebar ⌃⌘S. В упакованном приложении акселератор меню владеет ⌃⌘S —
webview-обработчик уступает, чтобы не переключать панель дважды. С 03.10.2026
пункт Hide Sidebar исполняет бэкенд: он сворачивает боковое меню окна вкладок в
фокусе, а без него последнего окна вкладок (SPEC_TABS.md, В56). Там же пункты
вкладок и окон (раздел «Вкладки и окна»).

### Вставка в ленту

⌘V это предопределённый пункт Edit → Paste нативного меню (09.11.2026). Страница
вкладки с 03.10.2026 дочерний webview окна (`add_child`), а wry у дочернего webview
отвечает «нет» на `performKeyEquivalent:` (`WryWebView` в wry 0.54.4). Поэтому
сочетание с ⌘ сначала получает меню, и пункт с этим сочетанием забирает его себе
(SPEC_EDITING.md, Л12). Нажатие ⌘V до страницы как `keydown` не доходит. Paste шлёт
первому ответчику `paste:`, и WebKit превращает его в событие `paste` страницы. Лента слушает это событие (`App.tsx`), а не нажатие. Поэтому
лента принимает и Paste, выбранный в меню указателем.

- Где стоит клавиатура, решает фокус (`document.activeElement`), а не цель события:
  WebKit направляет `paste` по выделению. В поле ввода, редакторе, меню, диалоге, оверлее
  и при открытой карточке событие остаётся нативным, лента буфер не читает.
- Над лентой, на графе и при фокусе на строке бокового меню лента читает буфер
  (`read_clipboard_payload`) и отменяет событие.
- Страница, которая получает и `keydown`, и `paste:` (окно без вкладок, браузерная
  проверка), вставляет один раз: на `keydown` лента не отвечает.
- Команда `paste` в реестре помечена `fixed: "system"`: переназначение оставило бы ⌘V
  вставлять через меню, и старое сочетание продолжало бы работать (SPEC_AUDIT_FIXES.md,
  Ф11). Сохранённое переопределение реестр не применяет.

## Вкладки и окна

С 03.10.2026 ([SPEC_TABS.md](SPEC_TABS.md), В55, от В57 до В59). Эти сочетания
macOS закрепляет за вкладками и окнами во всех приложениях, поэтому команды не
переназначаются (`fixed: "system"`).

| Сочетание | Команда | Пункт нативного меню |
|---|---|---|
| ⌘T | New Tab | File → New Tab |
| ⌘N | New Window | File → New Window |
| ⌘W | Close Tab | File → Close Tab |
| ⇧⌘W | Close Window | File → Close Window |
| ⇧⌘], ⌃⇥ | Show Next Tab | Window → Show Next Tab |
| ⇧⌘[, ⌃⇧⇥ | Show Previous Tab | Window → Show Previous Tab |
| ⌘1 по ⌘8 | Select Tab 1 to 8 | Window → Select Tab с номером |
| ⌘9 | Select Last Tab | Window → Select Last Tab |
| без сочетания | Move Tab to New Window | Window → Move Tab to New Window |

Сочетания с ⌘ это пункты нативного меню (`build_app_menu` и `on_menu_event` в
`lib.rs`). Меню получает сочетание раньше страницы, поэтому команда работает в
любой странице окна, в полосе вкладок тоже. Пункт действует на окно вкладок в
фокусе, а без него на последнее окно вкладок. Пункты File свои, а не готовый
`close_window` из muda: тот намертво занимал бы ⌘W. Close Tab и Close Window
закрывают окно настроек, когда оно в фокусе.

⌃⇥ и ⌃⇧⇥ (⌃Tab и ⌃⇧Tab) меню не принимает: их ловят сами страницы вкладки и полосы
(`adjacentTabDirection` в `src/tabbar/tabKeyboard.ts`) и передают бэкенду
командой `activate_adjacent_tab`. Страница вкладки слушает их в фазе перехвата,
поэтому они работают из любого экрана, из полей и диалогов тоже. Простой ⇥
(Switch view) требует точного набора модификаторов и с ⌃⇥ не пересекается.

New Tab открывает пространство видимой вкладки окна на Everything, New Window
пространство видимой вкладки последнего окна (В51, В54). Следующая и
предыдущая вкладка идут по кругу. ⌘1 по ⌘8 выбирают вкладку по номеру и ничего
не делают, если вкладки с таким номером нет; ⌘9 всегда выбирает последнюю.

В реестре эти команды записаны как остальные, подписи берутся из общего
словаря клавиш (`commandBinding.ts`). Второе и следующие сочетания команды
лежат в поле `alternates` и сопоставляются так же, как основное; ⌘1 по ⌘8 это
одна команда `select-tab` с признаком `run` и одной подписью `⌘1…⌘8`. Больше
одного сочетания бывает только у команды, которую нельзя переназначить. В
разделе Shortcuts команды вкладок и окон показаны только для чтения
([SPEC_SETTINGS_WINDOW.md](SPEC_SETTINGS_WINDOW.md), «Shortcuts»).

## Feed (лента)

| Сочетание | Команда | Примечание |
|---|---|---|
| ↑↓←→ | Navigate | Перемещение фокуса по раскладке |
| ↵ | Focus | Открыть сфокусированный элемент; при выделении — переключить его в выделении |
| ⇧↵ | Select | Добавить/убрать сфокусированный из выделения |
| ⌘K | Command | Меню элемента; при выделении — групповое меню. Только при клавиатурном фокусе. Меню выходит из значка `⌘K` в правом верхнем углу карточки, снизу и вровень с его правым краем; кнопки `Source` и `More` при этом не появляются (решения пользователя 05.11.2026; SPEC_CARD_STATES.md, С8.8) |
| esc | Unfocus | Ступенчато: сброс выделения → сброс фокуса |

**Стрелки в ленте** (решение пользователя 06.11.2026). Колонка ленты это карточки с одним значением `left` в позициях раскладки: навигация читает числа самой раскладки и не считает расстояний между карточками. Живая карточка это показанная карточка, а не скелет на её месте (`renderReadyBlockIds`).

- `ArrowLeft` и `ArrowRight` идут только в соседнюю в этом направлении колонку, где есть живая карточка. Внутри неё они берут карточку с наибольшим перекрытием по вертикали с текущей. При равном перекрытии или без перекрытия берут ближайшую по вертикальному зазору, затем верхнюю.
- `ArrowUp` и `ArrowDown` остаются в своей колонке: предыдущая или следующая живая карточка в ней. На конце колонки они ничего не делают и в другую колонку не переходят.
- Противоположная клавиша сразу после шага вбок возвращает на карточку, с которой пришли, поэтому `←` и `→` это пара. Помнится один шаг. Его сбрасывает любая другая стрелка, в том числе та, что никуда не сдвинула, любое другое перемещение фокуса и смена раскладки. После возврата следующий шаг снова идёт по правилу выше.
- Любая живая карточка достижима из любой другой: шаги вбок проходят все колонки, а `ArrowUp` и `ArrowDown` проходят все карточки колонки.
- `ArrowLeft` в самой левой колонке с живой карточкой переводит фокус в боковое меню (М1). При выделении фокус остаётся в ленте, как раньше.
- Одна колонка и все виды ленты с этими позициями идут по тому же правилу.

Без изменений: первая видимая карточка при первой стрелке (`firstVisibleSlug`), переход на неё, когда фокус вне экрана, прокрутка к карточке, клавиатурный подъём.

Карточка в клавиатурном фокусе поднимается так же, как при наведении, с рядом
имён коллекций и без кнопок (решение пользователя 05.11.2026; SPEC_CARD_STATES.md,
С8.5, С8.9). Выделенная карточка не поднимается.

Выделение диапазона с Shift+стрелками удалено 23.08.2026 (нестабильно, revert
`9d6fd04`).

## Sidebar (фокус в боковом меню)

Клавиатурный фокус переходит с карточки ленты, из открытой карточки и с графа на строки
бокового меню и обратно.
Переход работает всегда, переключателя нет (решение пользователя 06.11.2026;
[SPEC_FEED_DISPLAY.md](SPEC_FEED_DISPLAY.md), Д30).
Где стоит фокус, решает одно состояние страницы (`useSidebarKeyboardFocus.ts`):
строка меню, поле фильтра с запомненной строкой («Ввод текста в меню») или ничего.
Пока стоит строка, лента не держит фокус ни на одной
карточке, поэтому два места разойтись не могут.

**М1. Вход** (решение пользователя 05.11.2026). У карточки в клавиатурном фокусе
нет соседа слева: `findLayoutNeighborSlug` никого не находит для `ArrowLeft`.
Это левый столбец в любом виде ленты. `ArrowLeft` переводит фокус в меню, а
скрытое меню сначала открывает (М8). Фокус встаёт на строку коллекции, из которой пришёл пользователь, то
есть на строку текущего маршрута. Если эта строка вне видимой части списка,
список сразу прокручивается ровно настолько, чтобы её показать. Пока фокус в меню,
карточка теряет клавиатурный подъём, и стрелки лентой не управляют.

`ArrowLeft` со страницы входит в меню всегда, и запрос в поле `Find or create...` он не меняет
(решение пользователя 07.11.2026). Запрос мог остаться от набора мышью или от перезагрузки. Если он
скрывает строку текущей коллекции, фокус встаёт на верхнюю видимую строку. Если совпадений нет, фокус
встаёт в поле, каретка в конце текста. Скрытое меню открывается для клавиатуры, поэтому запрос виден.

У ленты автора своей строки в меню нет, поэтому `ArrowLeft` ставит фокус на верхнюю видимую строку по тому
же правилу (решение пользователя 07.11.2026). При открытой над ней карточке действуют правила карточки (М9).

**М2. Ходьба** (решение пользователя 05.11.2026). `ArrowUp` и `ArrowDown` идут по
строкам, которые открываются щелчком, и останавливаются на концах списка, по
кругу не идут. Список сразу прокручивается ровно настолько, чтобы показать строку.
Ходьба не меняет маршрут. Кнопка Connect и место под ней не меняются и в ходьбу не
входят.

`Enter` это главное действие строки, и фокус после него остаётся в меню (решение пользователя
06.11.2026). `ArrowRight` это всегда возврат (решение пользователя 07.11.2026): другую коллекцию
открывает только `Enter`.

**М3. `Enter`** (решение пользователя 06.11.2026). В ленте `Enter` открывает строку тем же
путём, что щелчок по ней, и фокус остаётся на этой строке. Коллекция становится текущей, поэтому
следующий `ArrowRight` с любой строки ведёт на первую видимую карточку её ленты: более ранней
карточки в ней нет.

При открытой карточке, в обоих её видах, `Enter` переключает связь карточки с этой
коллекцией тем же действием, что нажатие `Connect` или `Disconnect` под указателем, и фокус
остаётся на строке. Здесь `Enter` никогда не открывает коллекцию и не закрывает карточку. На
строке без этого действия, например `Everything`, `Enter` ничего не делает. Удержание клавиши
не повторяет действие.

**М4. `ArrowRight`** (решение пользователя 07.11.2026). Он всегда возвращает к текущей коллекции, с
любой строки и на любой поверхности. Он не открывает коллекцию и не меняет маршрут.

- В ленте он возвращает на карточку, с которой фокус ушёл, с её клавиатурным подъёмом, и ничего не
  перечитывается. После `Enter`, сменившего маршрут, он ведёт на первую видимую карточку текущей
  коллекции (`firstVisibleSlug`). Если в ленте нет карточки, фокус остаётся в меню. В ленте автора он так
  же возвращает на ту же карточку с любой строки, и маршрут не меняется (решение пользователя
  07.11.2026).
- При открытой карточке, в обоих её видах, он возвращает фокус на корень карточки (решение
  пользователя 06.11.2026: «давай в режиме карточки возвращать курсор в карточку правой стрелкой»).
  Карточка не закрывается.
- На графе он возвращает на граф, и в фокусе ничего нет (М10).

Возвращаясь на страницу, он очищает запрос и показывает целый список с прежней прокруткой: это возврат
в исходное состояние одним нажатием, как оба шага Escape вместе (решение пользователя 07.11.2026). Если
фокус остаётся в меню, запрос тоже остаётся.

**М5. Вид** (решения пользователя 05.11.2026 и 07.11.2026). Загорается то, что сделает клавиша. В ленте и
на графе `Enter` открывает коллекцию, поэтому название строки в фокусе становится ярким, тем же
`--foreground`, что под указателем (решение пользователя 07.11.2026). Число строки не меняется. При
открытой карточке `Enter` нажимает кнопку, поэтому название остаётся приглушённым, а горит кнопка.
Правило `global.css` для строки под указателем (`data-sidebar-row-focused`) к этому фокусу не относится.

Под этим фокусом ничего не движется: плашка, яркость названия, кнопка, её подпись и значок стоят на
месте в том кадре, где появился фокус, и так же уходят со строки, без перехода и анимации (решение
пользователя 07.11.2026). Это действует и на последнюю строку после ухода фокуса, до первого настоящего
движения указателя. Движение под указателем прежнее. Ни окно превью, ни стопка компактной строки под
этим фокусом не открываются. Строка текущей коллекции сохраняет свою обычную отметку. Скругление,
размеры и поля не меняются.

Строка в фокусе получает слой состояния `state-active` со скруглением `rounded-1`
поверх всей строки: лёгкое выделение серым, при открытой карточке и без неё. Это исключение
только для клавиатурного фокуса. У строки под указателем и у открытой коллекции
плашки нет, отвечает яркость названия (решение пользователя 22.10.2026,
DESIGN_SYSTEM.md, «Компактная строка боковой панели»). Открытая коллекция под этим
фокусом сохраняет своё яркое название. DOM-фокус на ссылку строки не переходит,
поэтому правило `:focus-visible` к этому фокусу тоже не относится.

В ленте кнопки на строке в этом фокусе не показываются (решение пользователя 06.11.2026),
потому что `Enter` их не нажимает: `Connect`, `Disconnect`, `Connected`, доля вроде `2/5` и
любое другое действие строки. Кнопки возвращаются, как только фокус уходит со строки.
Раскладка строки, ширина названия и столбец миниатюр не сдвигаются ни на пиксель, потому что
кнопки скрыты через `visibility: hidden`. Число строки остаётся и стоит на своём месте.

При открытой карточке строка в этом фокусе показывает кнопку, которую нажмёт `Enter`, точно в
том состоянии и виде, что под указателем над самой кнопкой, с подписью по состоянию, и она
обновляется сразу после `Enter` (решение пользователя 06.11.2026). `Connect` яркий, как под
указателем, `Disconnect` в своём цвете на связанной строке, а название остаётся приглушённым:
загорается ровно то, что сделает клавиша (SPEC_CARD_STATES.md, С7.10). На строке без действия,
например `Everything`, не загорается ничего. Состояние, подпись, размер и место кнопки те же. Кнопка стоит на
слое `state-active`, как на любой поверхности: у настоящей кнопки заливка следует за слоем и
отстоит от него на тот же шаг, что от панели, а слова вида Contents закрывают точечную линию
цветом плашки, поэтому слово стоит на плашке как на одной поверхности, вокруг него нет рамки,
и точки останавливаются перед словом (решение пользователя 06.11.2026). Наведение указателя и все строки без этого фокуса остаются как есть.

**М6. Нижняя панель** (решение пользователя 05.11.2026). Пока фокус в меню, панель
показывает записи ниже, а команды карточки из неё уходят. Записи берутся из
`src/lib/commandRegistry.ts`, контекст `sidebar`. Он исключает контекст `feed`,
поэтому сочетание значит в контексте одно. Нажатие на запись, которая является
кнопкой, делает то же, что клавиша. Подпись `↵` следует состоянию (решение
пользователя 06.11.2026).

| Сочетание | Команда | Примечание |
|---|---|---|
| ↑↓ | Navigate | Справочная запись, не кнопка |
| ↵ | Open | В ленте и на графе |
| ↵ | Connect или Disconnect | При открытой карточке, по состоянию строки. На строке без этого действия записи нет |
| ⌘K | Command | Меню строки. У строки Everything меню нет, и записи нет |
| → | Back | На любой строке (решение пользователя 07.11.2026) |
| esc | Unfocus | Снять фокус |
| esc | Clear | На строке при непустом запросе: очистить его («Ввод текста в меню») |

**М7. Меню строки** (решение пользователя 05.11.2026). ⌘K открывает меню коллекции в
фокусе, то же, что правый щелчок по строке, и оно выходит из этой строки. Меню
принимает клавиатуру, пока открыто. ⌘K или Escape закрывают его, и фокус остаётся
на строке. Действие меню, которое уводит со строки, работает как обычно: после
переименования фокус снова на строке, после удаления на соседней.

Меню открывается под строкой, его левый край стоит у начала названия. Правый щелчок
ставит меню у указателя, а указателя у клавиатуры нет.

**М8. Скрытое меню** (решение пользователя 05.11.2026). При скрытом меню
`ArrowLeft` в левом столбце открывает меню обычным способом показа и
ставит фокус на строку текущей коллекции, как в М1.

Такое меню скрывается только тогда, когда фокус уходит из него, по `ArrowRight` или Escape
(решение пользователя 06.11.2026). `Enter` его больше не скрывает. Меню, открытое до фокуса,
остаётся открытым.

- Если в ленте нет карточки, `ArrowRight` оставляет фокус на строке и
  меню открытым: фокусу больше негде стоять.
- Движение указателя заканчивает клавиатурный режим, но оставляет меню открытым.
  Следующая смена маршрута скрывает его, в том числе щелчок по строке, и фокус при этом
  ни на какую карточку не ставит.
- ⌃⌘S, пункт View, кнопка полосы вкладок, кнопка `Hide Sidebar` нижней панели и жест
  двумя пальцами влево заканчивают показ и скрывают меню. Жест вправо ничего не делает.
  Фокус возвращается на страницу, как по `ArrowRight`.
- На время показа страница сообщает бэкенду положение `open` (`report_sidebar_overlay`),
  как у меню поверх ленты. Поэтому бэкенд передаёт эти команды странице и сам ничего не
  сохраняет, а пункт View и кнопка полосы вкладок называют меню показанным. Когда показ
  заканчивается, страница снова сообщает то, что есть у окна. Пока вкладка скрыта, она
  сообщает положение окна.
- Перетаскивание края меню делает его открытым насовсем: сохранённое состояние становится
  «открыто», и показ заканчивается.
- Открытие не является настройкой пользователя. Сохранённое состояние `collapsed` в
  `windows.json` остаётся «скрыто» и заново не записывается, поэтому перезагрузка или новый
  запуск во время показа возвращает меню скрытым. Меню поверх ленты в узком окне следует
  тому же правилу, его открытость и так не хранится
  ([SPEC_NARROW_WINDOW.md](SPEC_NARROW_WINDOW.md), У8).
- Признак «меню открыто для клавиатуры» один, и хранится он только в памяти страницы.

**М9. Открытая карточка** (решение пользователя 06.11.2026). При открытой карточке
`ArrowLeft` переводит фокус в меню, когда клавиатура не в тексте: фокус не стоит в
редакторе, в редакторе ячейки таблицы, в поле ввода, в многострочном поле и ни в чём
другом редактируемом. Фокус встаёт на строку текущей коллекции, как в М1, а скрытое меню
открывается по М8.

С кареткой в тексте `ArrowLeft` и все остальные клавиши работают как обычная каретка
(решение пользователя 06.11.2026). Из текста меню недостижимо. Новых режимов нет, клавиши
редактора не меняются. Щелчок в текст возвращает каретку. Выйти из текста можно по Escape,
если редактору нечего закрывать: фокус переходит на корень карточки, следующий Escape
закрывает карточку ([SPEC_EDITING.md](SPEC_EDITING.md), Л16). Первый Escape в ячейке таблицы
ведёт в основной редактор, следующий на корень. Вне текста клавиатура стоит также при открытии
карточки и после щелчка вне текста.

- Правило одно для обоих видов открытой карточки: окна и полной страницы. Вопрос «стоит
  ли клавиатура в тексте» решает одна функция, `isKeyboardInText` в
  `src/lib/keyboardTargets.ts`, по `document.activeElement`.
- Переход не начинается, пока клавиатуру держит просмотр изображения, меню, диалог или
  другой оверлей. Плеер в фокусе тоже оставляет стрелки себе: они перематывают видео.
- `ArrowRight` и Escape на любой строке возвращают фокус на корень открытой карточки, без
  каретки, и карточка не закрывается (М4). Следующий Escape закрывает карточку, как обычно.
  Это заменяет «в фокусе ничего нет» только пока
  карточка открыта. Корень карточки это элемент `[data-detail-scroll]`, на который фокус
  встаёт при её открытии.
- `Enter` переключает связь карточки с коллекцией (М3). Щелчок по строке и ⌘⌥↑↓ открывают коллекцию
  и закрывают карточку через смену маршрута.
- ⌘⌥↑↓ при таком фокусе ведёт на первую видимую карточку новой ленты, даже если меню было открыто
  до этого.
- Ходьба, вид строки и ⌘K такие же, как из ленты. Пока фокус в меню, ⌘K, ↵ и esc принадлежат
  контексту `sidebar`, а не карточке, и записи `Command` и `Close` карточки из панели уходят.
- Кнопка Connect в строках при открытой карточке в ходьбу не входит. На строке в фокусе она
  выглядит как под указателем (М5), на остальных строках не меняется.
- Карточка, открытая во время фокуса из ленты другим способом, например щелчком мыши,
  по-прежнему возвращает фокус на страницу.

**М10. Граф** (решение пользователя 06.11.2026). На графе `ArrowLeft` тоже переводит фокус в меню.
Правила те же, что из ленты: фокус встаёт на строку текущего маршрута, скрытое меню открывается
по М8, а из поля ввода, меню и оверлея переход не начинается. Ходьба, плашка, ⌘K, ввод текста и записи
нижней панели такие же, как из ленты. Своего клавиатурного фокуса у графа нет, поэтому:

- `ArrowRight` с любой строки возвращает на граф, и в фокусе ничего нет. Маршрут не меняется
  (решение пользователя 07.11.2026). Escape при пустом запросе делает то же.
- `Enter` открывает коллекцию, вид остаётся Graph, и фокус остаётся на строке.
- Скрытое меню скрывается, когда фокус уходит из него.
- При открытой над графом карточке действуют правила карточки (М9).
- Указатель заканчивает режим, как в ленте, а поведение указателя на самом графе не меняется.

**М11. Перестановка строки** (решение пользователя 07.11.2026). ⌘⇧↑ и ⌘⇧↓ при фокусе на строке коллекции
сдвигают коллекцию на одно место вверх или вниз. Запись идёт тем же путём, что перетаскивание: та же
команда `reorderChannels`, те же позиции и тот же хранимый порядок.

- Фокус остаётся на сдвинутой строке, список сразу прокручивается ровно настолько, чтобы её показать.
  Сдвиг виден в том же кадре, без анимации (М5).
- `Everything` не двигается, и выше него ничего не встаёт. На концах списка клавиши ничего не делают и по
  кругу не идут.
- Там, где ручного порядка нет, клавиши ничего не делают: при непустом запросе, потому что список
  ранжирован, и пока идёт перетаскивание строки.
- Удержание повторяет сдвиг. Записи идут по одной и по порядку: пока одна в пути, новая ждёт, и пишется
  только самый поздний порядок. Этой же очередью пользуется перетаскивание
  ([SPEC_FRONTEND.md](SPEC_FRONTEND.md), порядок каналов).
- Клавиши работают в ленте, на графе и при открытой карточке. Из поля ввода, редактора и меню сдвиг не
  начинается, а `Enter`, стрелки и остальные клавиши не меняются.
- В нижней панели записи нет: таблица М6 перечисляет только то, что нужно для работы с фокусом, а сочетания
  видны в разделе Shortcuts окна настроек, как `←` в карточке.

Остальное поведение:

- Escape снимает фокус с меню, как с карточки в ленте. После него в фокусе ничего
  нет. При непустом запросе он сначала очищает запрос («Ввод текста в меню»).
- Движение указателя или нажатие заканчивает клавиатурный режим так же, как в
  ленте: указатель, который не сдвинулся, режим не заканчивает. Над нижней панелью
  указатель режим не заканчивает, иначе её кнопки уходили бы из-под него. Пока
  открыто меню строки, указатель режим тоже не заканчивает.
- Скрытие меню во время фокуса возвращает фокус на страницу, как `ArrowRight`. ⌘⌥↑↓ во время фокуса из ленты двигает фокус вместе с маршрутом, и он остаётся в меню,
  в том числе в меню, открытом для клавиатуры. Удаление текущей коллекции из меню строки тоже
  оставляет фокус в меню, на соседней строке. Tab между лентой и графом заканчивает режим в обе
  стороны: в фокусе ничего нет, лента карточку не берёт, а меню, показанное для клавиатуры,
  скрывается. Открытая поверх карточка, например результат поиска, возвращает фокус на страницу.
- Режим начинается только из клавиатурного фокуса ленты, из открытой карточки вне текста
  (М9), с графа (М10) или по `ArrowDown` из поля `Find or create...` («Ввод текста в меню»).
  Оверлеи, диалоги и поля ввода сохраняют свои клавиши.
- При выделении в ленте `ArrowLeft` в левом столбце ничего не делает.

## Ввод текста в меню

Символ, набранный при фокусе на строке меню, переводит фокус в поле `Find or create...`, и этот
символ оказывается в поле (решение пользователя 06.11.2026: «если у меня фокус на списке, то при
начале ввода символов у меня начнёт отображаться поиск»). Дальше работает поле. `ArrowDown` из поля
ведёт на верхнюю строку отфильтрованного списка. Escape возвращает исходное состояние, а следующий
Escape уходит на страницу или в карточку. Строка и поле не стоят в фокусе вместе: владелец фокуса
один (`useSidebarKeyboardFocus.ts`), и фокус стоит на строке, в поле с запомненной строкой или нигде
в меню.

**Запомненная строка** это строка, на которой стоял фокус перед первым символом. Вместе с ней
запоминается прокрутка списка. Обе живут, пока фокус ходит между полем и строками.

Правила:

- Символом считается одна буква, цифра или знак без ⌘, ⌥ и ⌃, с ⇧ или без, в любой раскладке
  (`isPrintableKeyboardKey`). Символ берётся из нажатия и дописывается в конец запроса, как в выборе
  коллекций (`CollectionPicker`). Мёртвая клавиша и ⌥ с символом набор со строки не начинают.
- `ArrowDown` в поле ведёт на верхнюю строку, как бы каретка ни попала в поле: набором, по ⇧⌘F или
  щелчком, над лентой, над карточкой и на графе.
- `ArrowUp` на верхней строке при непустом запросе ведёт в поле, каретка встаёт в конец текста. При
  пустом запросе он стоит на месте (М2). В самом поле он ничего не делает, поэтому удержание клавиши
  не идёт по кругу.
- Escape очищает запрос целиком, а не возвращает запрос, бывший до набора. На строке при непустом
  запросе он делает то же, что в поле, и уход на страницу становится вторым шагом.
- `Enter` и щелчок по строке оставляют запрос, и он виден в поле, в том числе при следующем показе
  скрытого меню. `ArrowRight` при возврате на страницу очищает запрос и показывает целый список
  (решение пользователя 07.11.2026, М4). Если в ленте нет карточки и фокус остаётся на строке, запрос
  тоже остаётся.
- `ArrowLeft` со страницы всегда входит в меню и запрос не меняет (решение пользователя 07.11.2026, М1).
- `Enter` из поля над открытой карточкой открывает коллекцию по имени и закрывает карточку через смену
  маршрута. Новое имя создаёт пустую коллекцию, и карточка в неё не попадает. Связи карточки меняют
  `ArrowDown` и `Enter` на строке.
- Меню, показанное для клавиатуры, остаётся и после `Enter` из поля, как после щелчка по строке (М8).
  Панель над лентой, открытая обычным способом, закрывается
  ([SPEC_NARROW_WINDOW.md](SPEC_NARROW_WINDOW.md), У6, У11).
- Пробел и `Backspace` на строке без запроса ничего не делают: начальный пробел фильтр отбрасывает, и
  он открыл бы поле, которое выглядит пустым. На строке с запросом они правят запрос из поля.

### Поле

- Рядом с лентой поле стоит в верхнем ряду над списком, в узком окне в шапке панели. При скрытом меню
  поля на странице нет, на время показа для клавиатуры оно есть (М8).
- Запрос хранится во вкладке и переживает перезагрузку (`collection_filter`), поэтому он может быть
  непустым ещё до входа в меню.
- В поле попадают набором со строки, щелчком, по `ArrowLeft` со страницы, когда совпадений нет, или по
  ⇧⌘F, в том числе над открытой карточкой. ⇧⌘F
  выделяет текст. Вне показа для клавиатуры ⇧⌘F открывает скрытое меню и сохраняет это открытие, а в
  узком окне открывает панель.
- Фильтр ранжирует строки, поэтому порядок под ним не ручной. `Everything` виден, если запрос входит в
  `everything`, `all` или `__all__`, и тогда стоит первым. Без совпадений список пуст, пояснительного
  текста в нём нет.
- Виды List, Contents и таблица показывают одни и те же строки: фильтр от вида не зависит.
- Без запомненной строки Escape при тексте очищает его и оставляет каретку в поле, без текста каретка
  уходит из поля. В панели узкого окна следующий Escape закрывает панель.

### Состояния и клавиши

**Фокус на строке, запрос пуст**

| Клавиша или событие | Что происходит |
|---|---|
| Символ | Фокус уходит в поле, символ становится запросом, плашка снимается, строка запоминается |
| Пробел | Ничего |
| `Backspace` | Ничего |
| Мёртвая клавиша, ⌥ с символом | Ничего. В поле они работают как обычно |
| ⌘ или ⌃ с символом | Своя команда, в поле не попадает |
| Символ при открытом меню строки, диалоге или поле переименования | Достаётся им |
| ⇧⌘F | Как символ, только без символа: строка запоминается, плашка снимается, текст запроса выделен |
| `ArrowUp` на верхней строке | Стоит на месте (М2) |
| Остальные клавиши и указатель | По М2, М3, М4, М7 и М9 |

**Фокус в поле, строка запомнена**

| Клавиша или событие | Что происходит |
|---|---|
| Символ, `ArrowLeft`, `ArrowRight`, ⌘A, ⌘C, ⌘V | Обычная правка, меню не покидается |
| `Backspace` до пустого поля | Фокус остаётся в поле, список целый |
| Совпадений не стало или они вернулись | Список следует за запросом, фокус остаётся в поле. Пустой список не возвращает фокус на страницу |
| `ArrowDown` | Плашка на верхней строке, каретка уходит из поля. Верхней может оказаться `Everything`. Без совпадений ничего |
| `ArrowUp` | Ничего |
| `Tab` | Обычный переход, дальше как щелчок мимо поля |
| `Enter` по имени существующей коллекции | Коллекция открывается, запрос остаётся, каретка в поле. Запомненной становится строка этой коллекции |
| `Enter` по новому имени | Коллекция создаётся, запрос очищается, каретка в поле |
| `Enter` по отклонённому имени | Строка создания с причиной, каретка в ней, запомненная строка забывается |
| `Enter` в пустом поле | Ничего |
| Escape | Запрос очищается, список целый, прокрутка прежняя, плашка на запомненной строке, меню остаётся |
| Крестик в поле | Текст очищается, каретка в поле. Строка остаётся запомненной |
| ⌘⌥↑↓ | Ничего |
| Составной ввод | Клавиши принадлежат способу ввода. `Enter`, подтверждающий составление, на имя не действует |
| Указатель движется | Ничего, набор продолжается |
| Щелчок мимо поля | Запрос остаётся, строка забывается, меню ведёт себя как после указателя (М8). Уход в другое окно и обратно строку не забывает |

**Фокус на строке, запрос не пуст**

| Клавиша или событие | Что происходит |
|---|---|
| `ArrowUp`, `ArrowDown` | Ходьба по видимым строкам, на нижней остановка (М2) |
| `ArrowUp` на верхней строке | Фокус в поле, каретка в конце текста |
| Символ | Фокус в поле, символ дописывается в конец запроса. Запомненная строка прежняя |
| Пробел | Как символ, потому что имя может содержать пробел |
| `Backspace` | Фокус в поле, последний символ удаляется |
| `Enter` в ленте | Коллекция открывается, фокус на строке (М3). Запрос остаётся, запомненной становится эта строка |
| `Enter` при открытой карточке | Связь переключается (М3). Запрос и запомненная строка не меняются. На `Everything` ничего |
| `ArrowRight` при открытой карточке, на любой строке | Возврат на корень карточки (М4). Запрос очищается, список целый, строка забывается |
| `ArrowRight` в ленте, на любой строке | Возврат на карточку текущей коллекции, маршрут не меняется (М4). Запрос очищается, список целый, строка забывается. Если в ленте нет карточки, фокус и запрос остаются |
| `ArrowRight` на графе, на любой строке | Возврат на граф, маршрут не меняется, в фокусе ничего нет (М10). Запрос очищается, список целый, строка забывается |
| Escape | Как в поле. Если строка не запомнена, потому что запрос остался от прежней работы, запрос очищается и фокус остаётся на этой строке |
| ⌘K | Меню строки (М7) |
| ⌘⌥↑↓ | Маршрут и фокус идут по всему списку, а не по видимым строкам. Если маршрут встал на скрытую строку, фокус стоит на том же месте списка |
| Указатель движется | Режим заканчивается, запрос остаётся, строка забывается |
| Строка исчезла, например удалена в другом окне | Фокус на строке с тем же местом или на последней |

**Условия вокруг**

| Условие | Что происходит |
|---|---|
| `ArrowLeft` со страницы, запрос скрывает строку текущей коллекции | Плашка на верхней видимой строке, запрос не меняется (решение пользователя 07.11.2026) |

| Запомненной строки к Escape больше нет | Плашка на строке с тем же местом или на последней. Целый список не бывает пустым: в нём есть `Everything` |
| Запомненную строку переименовали | Фокус возвращается на неё под новым именем |

| Граф | Всё как над лентой, кроме возврата: на графе в фокусе ничего не остаётся (М10) |
| Перезагрузка | Запрос остаётся, запомненная строка и показ для клавиатуры нет |
| Нижняя панель, фокус в поле | Записей строки нет, стоят записи страницы, как при каретке в поле |
| Нижняя панель, строка без запроса | Записи М6 |
| Нижняя панель, строка с запросом | Записи М6, но `esc` называется `Clear`, потому что первый Escape очищает запрос |

## Graph

Граф это курсорная поверхность (решение 23.08.2026): выбор, открытие, перетаскивание и
панорамирование это жесты мыши. Холст не фокусируем, своего клавиатурного фокуса у графа нет.
Единственная клавиша, которая на нём что-то значит, это `ArrowLeft`: она переводит фокус в боковое
меню (М10, решение пользователя 06.11.2026). Из меню `ArrowRight` с любой строки возвращает на граф,
и маршрут не меняется (решение пользователя 07.11.2026), а `Enter` открывает коллекцию, и вид остаётся
Graph. Глобальные команды работают над графом, поскольку слушают окно.

## Нижняя панель при сужении окна

Записи скрываются целиком; усечение запрещено. Факт переполнения берётся из
раскладки (`scrollWidth > clientWidth` на панели), а не вычисляется из ширин.

Порядок: справочные (`Navigate`, `Switch collection`) → esc-записи (`Close`,
`Clear selection`, `Unfocus`) → заученные (`Settings`, `Hide Sidebar`,
`New Collection`, `Find elements`, `Commands`) → ситуативные (`Command`, `Feed`,
`Focus`, `Open`).

Тесты: `src/lib/bottomBarOverflow.test.ts` закрепляет порядок,
`src/App.test.tsx` («hides bar entries by worth when the window is too narrow»)
прогоняет настоящий путь измерения и проверяет, что остаток действительно
помещается.

## Переназначение

**Что переназначается.** Любая команда, кроме помеченных `fixed`:

- `structural` — стрелки, `Enter`, `Escape`, `Tab`, `⇧↵`, `⌘⌥↕`. Это язык
  интерфейса, а не сочетания; подмена ломает саму модель работы. В настройках
  не показываются.
- `system`: `⌘,` на Settings, с 03.10.2026 сочетания вкладок и окон
  (раздел «Вкладки и окна») и с 09.11.2026 `⌘V` на Paste («Вставка в ленту»).
  macOS ожидает их на этих командах. В настройках
  показываются строкой только для чтения: подписи сочетаний без записи.

Переопределение для `fixed`-команды игнорируется реестром: молча не
работающая настройка хуже её отсутствия.

**Ввод.** Поиск фильтрует список при каждом вводе по названию команды,
отображаемым символам сочетания и текстовой записи клавиш, например `cmd+f`.
Несколько слов запроса могут совпасть с разными частями одной записи. Пустая
выдача прямо сообщает, что совпадений нет. Список ограничен по ширине до 720
пикселей. Каждая обычная строка имеет высоту не менее 40 пикселей. Короткое
сочетание занимает компактную кнопку высотой 24 пикселя, кнопки выровнены по
правому краю. Нажатие на действующее сочетание переводит эту же строку в режим
записи. Допустимое сочетание сразу сохраняется, отдельные кнопки подтверждения
и отмены не нужны. `Escape` или уход фокуса отменяют запись, `Tab` сохраняет
обычную навигацию. Запись другой строки закрывает предыдущую. При возврате к
исходному сочетанию переопределение удаляется. Кнопка сброса видна только для
изменённой команды рядом с её названием. Она не занимает общую колонку и не
сдвигает сочетание. Сбросы используют компактные вторичные кнопки.

Пока запись активна, нативное меню macOS временно снимается, поскольку его
акселераторы перехватывают нажатия до окна настроек. При сохранении, отмене,
потере фокуса окна или его закрытии меню пересоздаётся из действующих
сочетаний. Если сохранение в конфигурацию не удалось, прежняя привязка
остаётся действующей и ошибка показана в строке. Голая клавиша отклоняется.
Структурные команды отсутствуют в списке настроек, системные показаны в нём
только для чтения. Скобки записываются по физической клавише (`event.code`
`BracketLeft` и `BracketRight`): ⇧⌘[ на раскладке США приходит как `{`.

**Проверки.** Отклоняются системные сочетания macOS (`⌘Q`, `⌘W`, `⌘M`, `⌘H`,
`⌘Tab`, `⌘Space`, `⌘⇧3/4/5` и прочие) и конфликты внутри одновременно активных
контекстов: `feed`, `element`, `selection` и `sidebar` взаимоисключающи, поэтому одно
сочетание может значить в них разное, но глобальная команда не может занять
сочетание, используемое любой поверхностью. Конфликт блокирует назначение и
называет команду-соперника. Конфликт считается со всеми сочетаниями команды,
включая `alternates`.

С 03.10.2026 список запрещённых сочетаний (`RESERVED` в
`src/lib/shortcutValidation.ts`, записан привязками и сравнивается через
`bindingId`) дополнен сочетаниями вкладок и окон: ⇧⌘W, ⌘1 по ⌘9, ⇧⌘[ и ⇧⌘]
(а также `{` и `}`, которые раскладка США отдаёт при Shift), ⌃⇥ и ⌃⇧⇥; ⌘T,
⌘N и ⌘W в нём уже были. Переназначение, сохранённое прежней сборкой на одно
из этих сочетаний, отбрасывается при чтении (`reserved_for_tabs` и
`load_overrides` в `src-tauri/src/commands/shortcuts.rs`): команда
возвращается к своему сочетанию по умолчанию, в журнал пишется событие.
⌘[ и ⌘] без Shift остаются за историей страниц.

**Хранение.** `config.json` на стороне Rust, не `localStorage`: переопределения
читает нативное меню, и очистка данных сайта не должна их терять. Сохранение
рассылает `shortcuts-changed` всем страницам: вкладки, полосы вкладок и окно
настроек перечитывают реестр без перезапуска.

**Нативное меню.** `Settings`, `Find Elements`, `Find Collections`,
`Hide Sidebar` продублированы акселераторами. Пункты вкладок и окон
переопределений не читают: их сочетания закреплены. Меню собирается из тех же
переопределений (`build_app_menu`) и перестраивается при сохранении: в macOS
акселератор меню перехватывает событие раньше webview, поэтому устаревшее меню
вызывало бы старую команду или глотало новую.

**Сброс.** По одной команде и всё сразу. У изменённой команды появляется
кнопка `Reset`. Ошибка сохранения оставляет прежнее сочетание действующим.

## Решения, принятые сознательно

- Удаление и переименование элементов не имеют прямых сочетаний: покрытие —
  меню ⌘K. Разрушающее действие за меню — защита от случайного нажатия.
- `Navigate` и `Switch collection` — справочные записи панели, не кнопки: у
  перебора есть направление, одного действия для клика нет.
- Пары esc/↵/⌘K значат разное в лентe, элементе, выделении и боковом меню — контексты
  взаимоисключающие, внутри одного контекста плюс Global сочетание значит одно
  (юнит-тест уникальности в `commandRegistry.test.ts`). ⇥ элемента сознательно
  затеняет глобальный ⇥.
