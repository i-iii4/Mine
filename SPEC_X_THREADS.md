# Сборка тредов X в клиппере

Связанные документы: [SPEC_CLIPPER.md](SPEC_CLIPPER.md), [PLAN.md](PLAN.md), [SPEC_SAVE_CORE.md](SPEC_SAVE_CORE.md).

Статус: реализация подготовлена 13.09.2026; автоматические проверки пройдены. Ручная проверка на актуальном X остаётся отдельной приёмкой, а не подменяется fixtures.

## Реализованный транспорт

Исправление ложного лимита: нормализатор сохраняет `moduleId` каждого указателя и набор постов модуля. Загрузчик следует только продолжениям модулей, содержащих выбранную авторскую цепочку. Общие Bottom/ShowMore/ShowMoreThreads не означают продолжение этой цепочки и не запрашиваются. Общий Top используется только для недостающего родителя. При `TimelineAddToModule` принадлежность сохраняется по `moduleEntryId`. Недоступный пост чужого модуля не делает авторский тред неполным. Это контракт сбора предоставленной X авторской ветки, а не доказательство отсутствия скрытых веток автора в общей выдаче.

Регрессия: четыре части уже в первом ответе плюс бесконечный общий Bottom → ноль дополнительных запросов и нет предупреждения. Продолжение авторского модуля → догрузка; продолжение чужого модуля → пропуск. Проверены 1109 Vitest-тестов и 8 тестов упаковки.

- `xThreadPage.js` подключается в MAIN world на `document_start` только для X/Twitter и наблюдает ответы `TweetDetail`/`ConversationTimeline` через fetch и XHR. Исходный ответ страницы сохраняется без изменений.
- Шаблон запроса берётся из запросов самой страницы: operation ID, переменные и заголовки не зашиты в расширение. Повторные запросы выполняются с текущей сессией на том же origin. Заголовки остаются в памяти страницы, не передаются в popup/native host и не сохраняются на диск. FxTwitter не используется.
- Нормализатор читает связи автора и родителя, полный note-текст, фото, MP4 и цитаты. Отбор цепочки не зависит от порядка DOM; повторные страницы объединяются по ID. Ответ автора на чужой комментарий не входит в цепочку.
- Пределы: 15 секунд на сбор, 20 запросов продолжений, 1000 записей, 8 страниц-постов в краткоживущем кэше. Ошибка, повтор cursor и недоступные записи отмечаются внутренним состоянием неполной загрузки, без предупреждения и блокировки Save в превью. Смена URL отбрасывает результат; уход со страницы отменяет запрос.
- Save сохраняет содержимое превью независимо от оценки полноты треда. Галочка, блокировка частичного сохранения и вывод технического `threadWarning` в превью удалены. Ошибки фактической записи остаются видимыми. Повторные медиа в разных частях не удаляются глобальной дедупликацией preview.
- После обновления расширения требуется перезагрузить открытую страницу X: старые вкладки не имеют нового наблюдателя `document_start`. Идентификатор расширения не меняется.

Проверки: 1106 тестов Vitest, 8 тестов упаковки, lint и TypeScript прошли. `extension/lib/xThread.test.ts` проверяет состав и медиа; `useClipperState.standalone.test.tsx` — сохранение превью без блокировки по полноте. `node scripts/x-thread-smoke.mjs` запускает собранное расширение во временном Chromium и перехватывает все сетевые запросы; проверены fetch, XHR, продолжения, исключение комментариев, ошибка загрузки, повтор cursor и отсутствие данных. Личный браузер и Computer Use не используются. Для установленного тестового Chromium поддерживается `MINE_TEST_CHROMIUM`. Отдельный worker smoke прошёл 19 fixtures и сохранение в OPFS с перезапусками браузера и worker; это не проверка доступа к пользовательской папке.

Ограничение: исчерпание доступных продолжений X не доказывает наличие скрытых/недоступных постов. Изменение внутреннего API X требует повторной проверки адаптера. Живая авторизованная сессия в этом прогоне не проверялась.

Ручная приёмка: release `target/release/bundle/macos/Mine.app` собран, подписан локальной ad-hoc подписью, проверен `codesign --verify --deep --strict`; runtime-компоненты сверены с manifest. Это не Developer ID/notarized distribution. Закрыть текущий Mine, открыть эту сборку, перезагрузить существующее расширение Mine в Dia и страницу X. Проверить контрольный тред: четыре авторских части без чужих комментариев; затем тред с медиа в продолжении. Установка в `/Applications` и управление личным браузером в этот прогон не выполнялись.

### Ограничение, которое нельзя закрыть тестами парсера

X ранжирует ответы и группирует их в подветви; счётчик означает прямые ответы,
а не длину всего треда: [описание X](https://help.x.com/en/using-x/x-conversations).
Отсутствие новых постов или исчерпание конкретной выдачи не является
универсальным доказательством отсутствия скрытых/невыданных продолжений.

Поэтому прежнее требование «доказать полный тред из данных страницы» остаётся
незакрытым. Нельзя выдавать проверку чистого алгоритма за готовность функции.
Для прямого источника нужен отдельный тест транспорта расширения с обработкой
дозагрузки; без него допустим только вывод о доступности формата данных.
Computer Use запрещён пользователем. Авторизованные запросы через извлечение
cookies из профиля в CLI не используются как обход этого ограничения.

Проверка выполнена без изменений кода, установки расширения или пользовательских
заметок. Новая внешняя зависимость FxTwitter не принята.

## Задача

Сохранять авторский тред одной Markdown-карточкой: связанные сообщения в порядке продолжения, полный текст и вложения каждого сообщения. Не включать комментарии других людей, рекомендации и элементы интерфейса. Не выдавать частичный результат за полный.

Область: Content для обычных X status URL. Link, Screenshot, выбранный текст, photo lightbox и X long-form articles сохраняют свои сценарии. Автоматическое обновление ранее сохранённых заметок и изменение хранилища не входят в работу.

## Подтверждённое текущее поведение

- `extension/lib/twitterThreadSelection.js` выбирает соседние timeline cells одного автора. Cell без поста или чужой автор прекращает обход. Связь ответа с родителем не проверяется.
- `extension/content.js:extractTwitterThread` запрашивает полный текст для выбранных частей, но API-медиа использует только для target; продолжения зависят от DOM-медиа.
- Существующие тесты проверяют непрерывность DOM, а не принадлежность к цепочке ответов.
- Контрольный пример: [пост michaelmicasso](https://x.com/michaelmicasso/status/2099105293938708797). Сохранённая заметка содержит только первый пост; на скриншоте видны ещё два сообщения автора. Точный DOM-элемент, остановивший сбор, пока не установлен.

## Граница авторского треда

Здесь «тред» означает связную цепочку ответов одного автора, а не определённую
по смыслу историю. Позднее дополнение автора к собственному посту включается,
если выполняет правило связи. Фильтрация по теме, времени между постами или
предполагаемому намерению автора не применяется. Это ограничение результата,
а не ошибка загрузки. AI-классификатор для определения «конца рассказа» не нужен.

1. Якорь — точный ID открытого поста. Подмена первым видимым постом автора запрещена.
2. При открытии середины треда пройти по родителям того же автора до начала авторской цепочки; затем собрать её продолжения. Ответ на чужое сообщение начинает отдельную авторскую цепочку: чужой родитель не включается.
3. Включать пост только при подтверждённых совпадении автора и связи `replyToId` с уже включённым постом. Использовать стабильный ID автора; одного отображаемого имени недостаточно.
4. Чужие ответы не включаются и не прекращают поиск авторских продолжений. Ответ автора чужому комментатору также не включается: его родитель вне цепочки.
5. Если у автора несколько прямых ответов на включённый пост, включать все подтверждённые ветви. Родитель идёт раньше потомка; среди одновременно доступных узлов — порядок времени публикации, затем ID. Это детерминированное правило, не попытка угадать литературный замысел автора.
6. Цитата остаётся внутри поста, который её цитирует. Её ID не становится узлом цепочки.
7. Повторы объединяются по ID; циклы и противоречащие связи отклоняются с диагностикой. Текстовая похожесть, соседство DOM, счётчик ответов и название секции не доказывают принадлежность.

`conversation_id` охватывает всё обсуждение, включая чужие комментарии. Для отбора нужны также автор и родитель ответа: [официальное описание полей X](https://docs.x.com/x-api/fundamentals/conversation-id). Наличие полей в официальном API не означает, что они доступны через нынешний syndication endpoint расширения.

## Источник данных и разделение ответственности

Три последовательных шага внутри существующего клиппера:

- **Получение данных X:** нормализовать записи, связи, страницы продолжения и ошибки доступа. DOM допустим для текста/превью, но сам по себе не доказывает связь или полноту.
- **Отбор цепочки:** чистая функция без DOM, сети и записи файлов; принимает нормализованные посты, возвращает упорядоченные ID и недостающие связи.
- **Сборка содержимого:** получить текст, цитаты и медиа каждого выбранного ID; сформировать один результат для текущего preview/save path.

Не создавать новый сервер, отдельную базу тредов или альтернативный механизм сохранения. Повторно использовать существующие средства получения медиа и save core. Desktop не должен становиться обязательным только из-за сборки текста треда; недоступность конкретного медиа отражается отдельно.

### Проверка источника — обязательный первый этап

На контрольном примере установить, откуда расширение действительно может получить ID автора, ID родителя, полный текст, вложения и продолжения. Зафиксировать минимальные обезличенные fixtures ответов, без cookies и токенов.

Проверить источник в доступных режимах авторизации. Не объявлять внутренний endpoint X стабильным публичным API. Если нужных данных нет без нового платного API, сервера или расширения разрешений, остановить этот этап и согласовать зависимость; не заменять доказательство цепочки эвристикой по экрану.

### Условие готовности к реализации

До подключения нового сборщика к пользовательскому сценарию заполнить результаты
следующих проверок. Сейчас все они открыты; наличие документа не закрывает их.

| Проверка | Необходимое доказательство | При отсутствии |
|---|---|---|
| Идентичность и родитель | Реальные записи target и продолжений с ID автора и родителя | Не реализовывать отбор по соседству вместо связей |
| Начало цепочки | Различимы отсутствие родителя и недоступный родитель | Состояние partial, не выдуманный корень |
| Полнота выдачи | Источник перечисляет релевантные ответы, а не только ранжированную выборку; понятен сигнал исчерпания | Не присваивать complete даже после последней страницы |
| Доступ из расширения | Проверены контекст запроса, действующие разрешения и режим авторизации | Согласовать новую зависимость, если без неё задача не решается |
| Текст и вложения | Для каждой части известны полнота текста и состав вложений, включая видео | Явная неполнота конкретной части |
| Ограничения загрузки | Зафиксированы численные лимиты и поведение при 429/timeout/повторе cursor | Не подключать неограниченный загрузчик |

Результат этапа — короткая запись здесь: источник и область его покрытия,
проверенный режим доступа, ожидаемые ID контрольного треда, fixtures,
численные лимиты и оставшиеся ограничения. Если источник умеет только
ранжированные ответы и не позволяет доказать полноту, это не основание
выпустить функцию, постоянно требующую ручного частичного сохранения.
Сначала пересмотреть способ получения данных и согласовать его ограничения.

Сетевые особенности X остаются в одном адаптере. Изменение формата ответа
должно приводить к типизированной ошибке разбора, а не к пустому «полному» треду.
Не сохранять cookies, токены и полные авторизованные ответы в логах/fixtures.

### Внутренний контракт

Нормализованный пост: `id`, `authorId`, `replyToId`, время публикации, текст, список медиа и цитата. Для `replyToId` различать известное отсутствие родителя и неизвестную связь. `conversationId` — дополнительная проверка, не критерий включения.

Результат получения: записи, непрочитанные продолжения и явный признак того, что источник исчерпан. Повторяющийся cursor, сетевая ошибка или пустая страница с продолжением не означают конец.

Результат сборки: `targetId`, упорядоченные посты, состояние `loading | complete | partial | failed`, причины неполноты и ID затронутых постов/вложений. Это состояние извлечения, а не новая схема frontmatter и не замена состояния операции сохранения.

## Полнота и остановка

`complete` допустим, только если восстановлено начало цепочки, проверены доступные продолжения в области источника, нет непрочитанных страниц/неизвестных связей и получено содержимое выбранных сообщений. Полнота относится к доступным данным на момент сбора, не к будущим, удалённым или скрытым постам.

В иных случаях: `partial`, если подтверждён хотя бы target, либо `failed`, если target получить нельзя. Причины различать: недоступный пост, неизвестная связь, неполный текст, недоступное вложение, ошибка загрузки, исчерпание лимита, неподдерживаемый источник.

Загрузчик обязан иметь именованные ограничения времени, числа страниц/постов и параллельных запросов; их значения закрепить по результатам проверки источника до реализации. Достижение ограничения всегда даёт `partial`, а не `complete`. Отмена закрывает запросы; результат старого URL/старого запуска не заменяет новый preview.

## Текст и вложения

- Для каждого поста применять существующее правило выбора полного текста, сохраняя форматирование, где это возможно.
- Для каждого поста получать все фото, GIF и видео, а не только для target. Сохранять порядок вложений внутри поста.
- Дедуплицировать одну и ту же запись медиа между DOM/API внутри поста; не удалять осмысленное повторное вложение в другом сообщении.
- `blob:` и poster не подменяют оригинальный видеофайл. Ошибка разрешения медиа делает результат частичным.
- Общий скан видео всей страницы не добавляет файлы за пределами выбранных постов/их цитат.
- Части разделяются `***`. Frontmatter, привязка к коллекциям, раскладка Cards/Media и идемпотентность записи остаются в существующем save path.

## Пользовательский сценарий

При открытии Content начинается сбор, preview показывает полученное содержимое и состояние загрузки. Обычное Save сохраняет содержимое preview без подтверждения полноты треда.

При частичном результате внутренний статус загрузчика не выводится красным дисклеймером в превью и не блокирует Save. Сохраняется показанное содержимое; дополнительного выбора «сохранить часть» нет. При `failed` нельзя подменять target чужим fallback-постом. Проверки ошибок записи и защита от дубликатов остаются без изменений.

Повтор извлечения до сохранения не создаёт карточку. После запуска записи применяется существующий контракт повторов save core: пересборка не меняет содержимое уже отправленной операции. Ошибка скачивания при записи не превращается в успешное полное сохранение.

Автоматический результат не перезаписывает пользовательские правки preview. При повторе после редактирования явно предложить заменить текст результатом нового сбора, сохранив прежний черновик до выбора.

### Защита существующего preview и Save

Использовать существующего владельца состояния клиппера; не вводить второй
независимый store или параллельный save pipeline.

- Каждый запуск извлечения связан с URL, target ID и поколением запроса.
  Применяется только результат актуального поколения. Смена страницы,
  режима захвата или закрытие отменяет запуск; даже если отмена сети не
  сработала, запоздавший результат игнорируется.
- Пока идёт loading, сохранение собираемого треда недоступно. Link и Screenshot
  не ждут его завершения и не наследуют ошибки треда.
- Состав частей и состояние полноты обновляются вместе: нельзя показать новый
  текст со старым complete. При редактировании результат загрузки хранится
  отдельно до явного принятия; редактирование не снимает признак неполноты.
- Save фиксирует неизменяемый снимок содержимого и выбранных коллекций.
  Поздняя загрузка не меняет этот снимок. Повтор отправки использует ту же
  операцию; повтор извлечения не запускается внутри неизвестного исхода Save.
- Отдельного согласия на частичное сохранение нет: Save сохраняет текущий снимок.
  Новый сбор не наследует это согласие. Состояние извлечения не добавляет
  технический текст в Markdown и не меняет пользовательский frontmatter.
- Одиночный пост проходит тот же сборщик: если подтверждено отсутствие
  продолжений, обычное Save работает без дополнительных шагов.

## Проверки и критерии приёмки

| Сценарий | Ожидаемый результат |
|---|---|
| Контрольный пост michaelmicasso | Все доступные связанные части, включая два видимых продолжения; ожидаемые ID устанавливаются по данным, не по скриншоту |
| Форма ответа/сортировка между частями | Не обрывают цепочку |
| Чужой ответ между продолжениями | Ответ исключён, продолжения найдены |
| Рекомендация того же автора | Исключена без связи с цепочкой |
| Автор отвечает чужому комментатору | Не включается в исходную цепочку |
| Открыта середина; разветвление | Восстановлено начало; стабильный порядок без повторов |
| Вложенная цитата | Содержимое внутри родителя, не отдельная часть |
| Длинный текст, несколько фото, GIF/видео в продолжении | Полный текст и все доступные оригинальные вложения |
| Target отсутствует, неизвестный родитель, цикл | Нет подмены или ложного статуса complete |
| Несколько страниц, повтор cursor, timeout, лимит | Дочитывание либо явный partial; нет бесконечного цикла |
| Скрытый/удалённый пост или недоступное медиа | Конкретная причина неполноты |
| Закрытие overlay, смена URL, повтор, правка preview | Отмена/изоляция запусков, правки не теряются |
| Частичное сохранение и повтор Save | Только явный выбор части; сохранён прежний контракт идемпотентности |
| Link, Screenshot, selection, photo lightbox, long-form | Прежние сценарии без регрессии |
| Последняя страница ранжированной выдачи | Не считается доказательством complete |
| Позднее дополнение автора к собственному посту | Включено по связи, без смыслового фильтра |
| Старый ответ загрузчика после нового URL/режима | Не меняет preview и доступность Save |
| Смена коллекций во время загрузки | Выбор пользователя сохраняется |
| Ответ загрузчика после начала Save | Payload и ID операции остаются прежними |
| Одиночный пост без продолжений | Прежний простой сценарий Save |

Сначала unit-тесты нормализации/отбора/композиции на fixtures и интеграционные тесты preview/save с подставной сетью. Затем изолированный браузерный тест загруженного расширения: сообщения, отмена, preview и временное хранилище. Реальный контрольный URL проверяется отдельно; записать полученные ID и сравнить текст/медиа с сохранённым Markdown. Тестовые fixtures не доказывают доступность живого X.

### Условия выпуска

1. Проверка источника завершена; нет неподтверждённого обещания полноты.
2. Старые тесты извлечения и сохранения проходят вместе с новой матрицей.
   Тесты непрерывного DOM заменяются тестами принадлежности, а не удаляются
   ради зелёного результата. Сценарий исключения рекомендаций сохраняется.
3. Интеграционные тесты сравнивают preview и фактический save payload:
   порядок частей, текст, медиа, коллекции и отсутствие служебного текста.
4. Контрольный тред и одиночный пост проверены в собранном расширении;
   результат сохранён во временное пространство и прочитан обратно.
5. Установленная стабильная копия проверена отдельно. ID, путь подключения,
   native-host registration и пользовательские данные не меняются ради теста.

Гарантии «регрессий не будет» нет. Условия выше — обязательные доказательства
перед выпуском, а не утверждение о уже выполненных проверках. Основная проверка
автоматизируется через fixtures и изолированный браузер; Computer Use не
является обязательным способом тестирования.
