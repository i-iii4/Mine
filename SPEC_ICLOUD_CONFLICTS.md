## Как iCloud оформляет конфликты

Источник: Apple Technical Note TN2336 «Handling version conflicts in the
iCloud environment».

- **Конфликт версий.** Один и тот же файл правили на двух устройствах. Файл в
  папке остаётся один: iCloud выбирает текущую версию, а остальные хранит как
  неразрешённые версии конфликта (`NSFileVersion`). В папке их не видно, ни
  Mine, ни Obsidian их не показывают. Пока их не разрешить и не удалить, они
  синхронизируются на все устройства и занимают место в iCloud.
- **Конфликт нового файла.** С другого устройства пришёл новый файл с тем же
  именем и другим содержимым (например, оба устройства без сети создали
  `Note.md`). В папке `Documents` контейнера, где лежат хранилища Obsidian,
  iCloud даёт пришедшему файлу имя с числом: `Note 2.md`, `Note 3.md`. Это два
  отдельных файла; версии конфликта у них нет. При одинаковом содержимом второй
  файл не появляется.
- Сразу после одновременной правки текущая версия на двух устройствах может
  различаться (Apple Developer Forums, тема 804253). Поэтому окно называет,
  какая версия текущая на этом Mac.

Следствие. Угадывание по имени не ловит ни один из двух случаев: `Note 2.md`
это не правка одного файла, а два файла, и оба законно видны как две карточки;
настоящий конфликт правки файлом не является вовсе. Сегодня проигравшие версии
правок Mine не видит, а пользователь о них не знает.

## Решение

**ВК1. Конфликт определяет система, а не имя.** Конфликт это файл `.md`
пространства, у которого есть неразрешённые версии конфликта `NSFileVersion`.
`detect_icloud_conflict` и все его вызовы удаляются. Файл с любым именем,
включая `Note 2.md` и `Note (conflicted copy).md`, индексируется как обычная
карточка или страница коллекции. Угадывание по имени не возвращается ни при
каком исходе живой проверки (ВК14).

**ВК2. Что проверяется.** Каждый файл `.md` пространства: карточки, страницы
коллекций, обычные заметки Obsidian. Медиа не проверяются: Mine не правит медиа
после записи, а правка картинки на двух устройствах вне этой задачи. Файл с
конфликтом индексируется как обычно, по текущей версии; отдельной записи в
`blocks` для версий нет.

**ВК3. Какие пространства.** Только пространство в iCloud Drive. Признак:
путь корня содержит `/Mobile Documents/` (то же правило, что у помощника
процента загрузки, `icloud_progress_helper.swift`) или
`FileManager.default.isUbiquitousItem(at:)` для корня возвращает истину (папки
Desktop и Documents, синхронизируемые iCloud). Живая проверка (ВК14, вопрос 4)
подтверждает оба признака на пространствах пользователя; признак, который
солгал, из реализации убирается. Для остальных пространств помощник не
запускается, таблица `vault_conflicts` пуста.

**ВК4. Когда.** Проверка идёт в фоне и никогда не задерживает ленту,
индексацию и уведомление о ходе открытия:

- после каждого прохода сверки пространства (`commands/freshness.rs`): при
  открытии после первого интерактивного кадра (SPEC_STARTUP_PERFORMANCE.md) и
  при возврате в окно;
- после событий наблюдателя по файлам `.md`: пути пачки одного окна задержки
  наблюдателя проверяются одним запуском помощника.

На пространство одновременно идёт одна проверка; запрос во время неё ставит
ровно один повтор после неё. Конфликт, пришедший без события файловой системы,
находится не позже следующей сверки (возврат в окно, SPEC_TABS.md, В42).

**ВК5. Помощник.** `src-tauri/native/icloud_conflicts_helper.swift`, исполняемый
файл `icloud-conflicts-helper`. Собирается в `build.rs` так же, как
`icloud-progress-helper`, и лежит в бандле рядом с ним. Прав iCloud у
приложения нет, и помощнику они не нужны (это проверяет ВК14). Запуск только
через `tool_process.rs`, `run_with_deadline`, в своей группе процессов. Все
операции с файлом идут через `NSFileCoordinator` (требование TN2336).
Команды:

| Команда | Вход | Выход (одна строка JSON на ответ) |
|---|---|---|
| `scan` | абсолютные пути `.md` в stdin, по одному на строку | для каждого файла с конфликтом: `{"path", "current": {"modified", "device"}, "versions": [{"token", "modified", "device"}]}`; последней строкой `{"done": true, "checked": N}` |
| `read <path> <token> <dest>` | версия конфликта файла | содержимое версии записано в `dest`; ответ `{"sha256": "…"}` |
| `settle <path> <token>…` | версии конфликта файла | каждая версия получает `isResolved = true` и удаляется вызовом `remove()`; ответ `{"settled": […], "missing": […]}` |

- `modified` это ISO 8601 с часовым поясом, `device` это
  `localizedNameOfSavingComputer` или `null`.
- `token` это `persistentIdentifier` версии, упакованный `NSKeyedArchiver` и
  записанный в base64; обратно версия находится через
  `NSFileVersion(itemAt:forPersistentIdentifier:)`.
- `scan` не читает содержимое файлов и версий: выгруженный файл остаётся
  выгруженным (SPEC_CLOUD_STORAGE.md, Х1 и Х4).
- `settle` удаляет только перечисленные версии, а не
  `removeOtherVersionsOfItem`: тот удаляет и прочую историю файла.
  Ненайденная версия (её уже разрешило другое устройство) идёт в `missing` и
  ошибкой не считается.
- Ошибка: строка `{"error": "<kind>", "message": "…"}` и ненулевой код выхода;
  Rust переводит её в `VaultConflictError::HelperFailed`.
- Сроки: `read` и `settle` 10 с. Срок `scan` задаётся по замеру ВК14 (вопрос
  5): удвоенное время прохода по самому большому пространству пользователя, но
  не меньше 30 с.

**ВК6. Индекс.** Миграция индекса (`storage/migrations.rs`) заменяет таблицу:

```sql
DROP TABLE IF EXISTS vault_conflicts;
CREATE TABLE vault_conflicts (
    path TEXT PRIMARY KEY,      -- путь от корня с папками, NFC: Cards/Note.md
    detected_at TEXT NOT NULL   -- ISO 8601, когда проверка впервые нашла конфликт
);
```

Прежние строки отбрасываются: это производные данные. Проход проверки
заменяет множество строк по проверенным путям одной транзакцией: новый путь
вставляется с текущим временем, путь без конфликта удаляется, оставшийся
сохраняет `detected_at`. Полный проход (после сверки) заодно удаляет строки
путей, которых больше нет. После изменения множества пространство шлёт своим
вкладкам событие `vault-conflicts-changed { count }`; события
`vault-conflict-detected` и `vault-conflict-resolved` удаляются.

**ВК7. Список для окна.** `list_vault_conflicts()` берёт пути из
`vault_conflicts` и одним запуском `scan` по этим путям читает версии заново.
Ответ: `Vec<VaultConflict>`, где

```rust
pub struct VaultConflict {
    pub path: String,               // Cards/Note.md
    pub name: String,               // Note
    pub detected_at: String,
    pub current: ConflictVersion,   // token = None
    pub versions: Vec<ConflictVersion>,
}
pub struct ConflictVersion {
    pub token: Option<String>,
    pub modified: String,
    pub device: Option<String>,
}
```

Путь, у которого `scan` версий не нашёл (конфликт разрешили на другом
устройстве), удаляется из таблицы и в ответ не попадает. Порядок: новые по
`detected_at` первыми.

Уведомлению версии не нужны: `list_vault_conflict_paths() -> Vec<String>`
отдаёт пути из таблицы без запуска помощника.

**ВК8. Решение.** `resolve_vault_conflict(path, choice, expected_tokens)`,
где `choice` это `KeepVersion { token: Option<String> }` (`None` значит
текущая версия) или `KeepAll`, а `expected_tokens` это версии, которые
показало окно. Шаги:

1. `path` проверяется: относительный, `.md`, внутри корня, строка в
   `vault_conflicts` есть. Абсолютный путь это `vault.root().join(path)`;
   имя основы из имени файла больше не выводится.
2. Свежий `scan` этого пути: множество версий должно совпасть с
   `expected_tokens`, иначе отказ `VersionsChanged`.
3. Читаются байты файла и через `read` байты каждой версии во временную папку
   производного хранилища пространства (`vaults/<vault-id>/tmp/conflicts/`).
4. Запись одной `StagedSourceMutation` с подавлением наблюдателя:
   - `KeepVersion(None)`: файл не меняется; каждая другая версия создаётся
     отдельным файлом (ВК9);
   - `KeepVersion(Some(t))`: файл заменяется байтами версии `t` только при
     байтах, прочитанных на шаге 3 (`SourceFileWrite::replace`, иначе
     `SourceChanged`); прежние байты файла и каждая версия, кроме `t`,
     создаются отдельными файлами;
   - `KeepAll`: файл не меняется; каждая другая версия создаётся отдельным
     файлом.
5. Для `KeepVersion` созданные отдельные файлы сразу уходят в Корзину
   (`SourceFileWrite::delete_if_unchanged` с их байтами). Файл уходит в
   Корзину из папки оригинала, поэтому Put Back в Finder возвращает его рядом
   с заметкой отдельной заметкой. Если Корзина отказала, файлы остаются в
   пространстве отдельными заметками: ничего не потеряно, и ответ это говорит.
   Для `KeepAll` отдельные файлы остаются в пространстве.
6. `settle` всех версий конфликта, включая выбранную: её содержимое уже в
   файле.
7. Индекс: файл переиндексируется, новые файлы `KeepAll` индексируются,
   строка `vault_conflicts` удаляется, вкладки получают
   `vault-conflicts-changed` и `space_changed_by_tab`.

Сбой `settle` после шага 4 оставляет файл с выбранной версией и строку на
месте; следующий `scan` снова покажет конфликт, повтор безопасен.
Служебной папки `conflicts-archive` больше нет; уборка старой папки входит в
миграцию: её файлы переносятся в Корзину, затем папка удаляется.

**ВК9. Имя отдельного файла.** `{имя} ({устройство} {ГГГГ-ММ-ДД ЧЧ-ММ}).md` в
той же папке, что и оригинал: устройство из `device` версии (без него
`another device`), время это `modified` версии по местному времени. Символы,
недопустимые в имени, убирает `sanitize_for_filename`. Имя уникально во всём
пространстве по общему правилу (`mine_core::save::select_unique_file_stem`,
SPEC_IDENTITY_ROBUSTNESS.md, «Запись и уникальность имён»).

**ВК10. Уведомление вместо плашки.** Плашка в шапке бокового меню удаляется
(`headerSlot` у `Sidebar` больше не получает `VaultConflictsBanner`). Конфликты
показывает уведомление ведущей вкладки пространства (SPEC_TABS.md, В19) в общем
углу уведомлений, при любом состоянии бокового меню:

- `NotificationCard`, заголовок `iCloud sync conflict` при одном конфликте и
  `{N} iCloud sync conflicts` при нескольких;
- текст `text-sm text-muted-foreground`: `“{name}” has versions from more than
  one device.` при одном и `{N} notes have versions from more than one
  device.` при нескольких;
- кнопка `Review` (`Button size="sm"`, как `Reveal in Finder` у пометки первой
  карточки) открывает окно;
- крестик прячет уведомление, пока множество путей с конфликтом не получит
  путь, которого не было в момент закрытия, или пока пространство не откроется
  заново. Память закрытия живёт в странице вкладки и в файлы не пишется;
- компонент `VaultConflictsBanner` становится `VaultConflictsNotice` (файл
  `VaultConflictsNotice.tsx`, окно `VaultConflictsDialog` в нём же) и стоит в
  стопке уведомлений `NotificationAnchor` в `App.tsx` при `lead`, как
  `CloudRecommendation`; число конфликтов он читает `list_vault_conflict_paths`
  (пути из таблицы, без запуска помощника) при открытии вкладки и по событию
  `vault-conflicts-changed`.

**ВК11. Окно `Resolve iCloud sync conflicts`.** `Dialog`, ширина `content`,
крестик, `Cancel` нет, ряда кнопок внизу нет: окно закрывают крестик и Escape
(DESIGN_SYSTEM.md, «Окна»). Описание:

`iCloud kept more than one version of these notes. Keep one version of each:
the others go to the Trash. Keep all puts the other versions next to the note
as separate notes.`

Группа на каждый конфликт, в рамке, как сейчас:

- строка имени `text-base text-foreground`, обрезка многоточием;
- путь `Cards/Note.md` строкой `MODAL_DETAIL_CLASS`;
- строка на каждую версию: подпись `{устройство} · {дата}, {ЧЧ:ММ}`, у текущей
  впереди `Current · `; дата как у открытой карточки
  (`toLocaleDateString("ru-RU", { day: "numeric", month: "short", year:
  "numeric" })`), без устройства `Unknown device`; справа кнопка `Keep`
  (`size="xs"`): у текущей версии `default` (главная, решение пользователя
  11.10.2026 «главная кнопка оставляет то, что на диске»), у остальных
  `secondary`;
- под строками кнопка `Keep all` (`secondary`, `size="xs"`);
- пока группа решается, её кнопки недоступны, нажатая показывает `Keeping…`;
- ошибка строкой `MODAL_ERROR_CLASS` под своей группой;
- решённая группа уходит; после последней окно закрывается.

**ВК12. Ошибки.** `VaultConflictError` (Specta), тексты окна:

| `Internal { message }` | `{message}` |

**ВК13. Проверки.** Rust:

- миграция: старая таблица и папка `conflicts-archive` уходят, новая пуста;
- `Note 2.md` и `Note (conflicted copy).md` индексируются как карточки, строк
  `vault_conflicts` не дают;
- проход по ответу помощника вставляет, удаляет и сохраняет `detected_at` по
  ВК6;
- решение в плоском пространстве и в раскладке `Cards/` для
  `KeepVersion(None)`, `KeepVersion(Some)`, `KeepAll`: содержимое файла,
  имена и место отдельных файлов, Корзина;
- отказ `SourceChanged` при файле, изменённом после чтения, и
  `VersionsChanged` при другом множестве версий: ни один файл не меняется;
- сбой `settle`: файл с выбранной версией, строка на месте, повтор проходит;
- совпадение имени отдельного файла с существующим даёт уникальное имя.

Помощник в автоматических проверках подменяется поддельным исполняемым файлом,
который отвечает заданным JSON: настоящий конфликт вне живого iCloud не
создать. Vitest: уведомление видно при свёрнутом меню и только в ведущей
вкладке; закрытие и возврат по новому пути; строки версий, главная кнопка,
`Keep all`; одна кнопка закрытия; ошибка под своей группой.

**ВК14. Живая проверка (этап 45.2, до кода).** Нужны второе устройство с тем же
iCloud (Mac или iPhone с Obsidian) и временное пространство в
`iCloud~md~obsidian/Documents/`. Агент запускает прототип помощника,
пользователь делает шаги на втором устройстве. Вопросы:

1. Правка одной заметки на обоих устройствах без сети, затем сеть: видит ли
   `scan` из процесса без прав iCloud версии конфликта; что лежит в папке;
   какие `device` и какая версия текущая на каждом устройстве.
2. Новый файл `Same.md` с разным содержимым на обоих устройствах без сети:
   появляется ли `Same 2.md`; пусто ли `NSFileVersion` у обоих файлов.
