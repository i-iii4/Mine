# Settings Window — отдельное окно настроек

Related documents: [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) | [SPEC_FRONTEND.md](SPEC_FRONTEND.md) | [SPEC_STORAGE.md](SPEC_STORAGE.md) | [SPEC_IDENTITY_ROBUSTNESS.md](SPEC_IDENTITY_ROBUSTNESS.md) | [ARCHITECTURE.md](ARCHITECTURE.md)

## Shortcuts

Раздел появился 24.08.2026; заменил оверлей `⌘/`, который был вторым местом с тем
же списком.

Содержимое: поиск по команде или сочетанию и изменяемые команды из реестра,
сгруппированные по контексту (Global, Feed, Element, Selection). Поиск
фильтрует при вводе и сообщает о пустой выдаче. Список ограничен шириной
720 пикселей. Обычная строка имеет высоту не менее 40 пикселей. Имя стоит
слева, компактная кнопка сочетания высотой 24 пикселя выровнена справа.
Структурные команды (стрелки, `Enter`, `Escape`, `Tab`) скрыты.

С 03.10.2026 системные команды (`fixed: "system"`: Settings, команды вкладок и
окон) показаны только для чтения в группе Global, после изменяемых команд
(`FixedShortcutRow`). Вместо кнопки записи у строки стоят подписи сочетаний в
том же месте справа (`buttonVariants` `reference`, `font-sans text-base`,
`text-muted-foreground`), по одной на каждое сочетание команды: `⇧⌘]` и `⌃⇥`
у `Show Next Tab`, `⇧⌘[` и `⌃⇧⇥` у `Show Previous Tab`; `⌘1…⌘8` у
`Select Tab 1 to 8` одной подписью. Нажимать в такой строке нечего: человек
видит, что сочетание занято. Поиск находит и эти строки, в том числе по любому
из их сочетаний ([SPEC_KEYBOARD.md](SPEC_KEYBOARD.md), «Вкладки и окна»).

Нажатие на сочетание включает запись в той же кнопке. Допустимое сочетание
сохраняется сразу. `Escape` и уход фокуса отменяют запись, `Tab` оставляет
клавиатурную навигацию доступной. Форма под строкой и отдельные кнопки
подтверждения и отмены отсутствуют.

Отказ выводится в той же строке и называет причину: системное сочетание macOS,
голая клавиша, конфликт с конкретной командой.

Сброс доступен только для изменённой команды рядом с её именем и не сдвигает
кнопку сочетания. `Reset all` в заголовке виден только когда есть что
сбрасывать и оформлен как компактная вторичная кнопка.

Окно открывается сразу на разделе: `open_settings_window(section)` кладёт
раздел в URL для нового окна и шлёт `settings-section` уже открытому.

Контракт переназначения, хранение и перестройка нативного меню —
[SPEC_KEYBOARD.md](SPEC_KEYBOARD.md).

## Goal

### Меню логотипа в main chrome

В правом верхнем углу страницы вкладки постоянно видна кнопка с существующим
логотипом Mine. Она доступна при скрытом нижнем баре, открытой карточке и
загрузке хранилища. Правый отступ от **видимого знака** до края окна —
`--chrome-edge-pad` (16px). Внешний отступ кнопки — 8px, ещё 8px занимает
внутренний padding: их сумма, а не каждый отступ отдельно, равна 16px.
Внутри штатная hover/open/focus-плашка `MenuTextTrigger` высотой 24px.
Логотип вписан в 16×16px без искажения пропорций; используется точный SVG-контур
`m` из Redaction 100 Italic, без подложки и зависимости от установленных шрифтов.
Заливка `currentColor` от `text-foreground` контрастна обеим темам уже в покое.
Hover/open не меняют положение или размер знака.

Нажатие открывает штатный `DropdownMenu` вниз с выравниванием по правому краю.
Пункты и порядок совпадают с навигацией окна настроек: Appearance, Shortcuts,
Graph, Spaces, Folders, Updates, Orphans. Раздела Extension нет
с 30.09.2026 (SPEC_ONBOARDING.md, О16), раздела Design system нет с 07.10.2026
(решение пользователя; витрина `ComponentTestBench` удалена из кода в тот же
день, примитивы смотрятся на страницах dev-сервера, DESIGN_SYSTEM.md «Где
смотреть примитивы и токены»). Оба интерфейса
используют один реестр разделов. Выбор закрывает меню и вызывает существующий
`open_settings_window(section)`: новое окно открывается сразу на разделе,
уже открытое переключается и фокусируется. Второй механизм настроек не создаётся.

Кнопка имеет доступное имя `Mine settings`; меню поддерживает клавиатуру,
Escape и закрытие снаружи. После закрытия клавиатурой фокус возвращается на
кнопку, после закрытия мышью не остаётся залипшей подсветки. Нижняя кнопка
Settings и `Cmd+,` сохраняются. Прежняя условная текстовая кнопка Settings
в top chrome заменяется постоянным логотипом.

Проверки: все восемь переходов; deep link нового/существующего окна;
клавиатура и Escape; постоянное размещение при скрытом bottom bar и в Detail.

### Содержимое окна

Отдельное компактное окно настроек с системным заголовком и перетаскиванием.
Слева — список разделов, справа — контент раздела. Четыре раздела:

1. **Appearance** — отображение контента (тема и режимы интерфейса; сюда
   переезжают пункты нынешнего Settings-дропдауна).
2. **Graph** — видимость collection, wikilink и related-note слоёв графа.
3. **Spaces** — список пространств: добавить новое, забыть старое.
4. **Orphans** — все медиа-файлы vault, на которые не ссылается ни один
   элемент, с групповыми действиями: перемещение в системную Корзину или превращение
   в элементы.

## Non-Goals

- Смена пространства вкладки из окна настроек: это задача `VaultSwitcher` во
  вкладке. Строка Spaces только показывает пространство во вкладке
  (`show_space`, Р-9 в редакции 03.10.2026).
- Никакого поиска/фильтра/сортировок в Orphans в этой итерации.
- Настройки article audio voices (живут в config.json) — UI не строим.
- Undo для удаления сирот (удаление идёт в системную корзину — отмена
  средствами ОС).
- Windows/Linux-специфика окна — целимся в macOS.

## Окно

| Параметр | Значение |
|---|---|
| label | `settings` |
| Хром | **консистентен с хромом вкладок**: `ChromeShell` + `ChromeRow as="header" separator="bottom"`, свободная область 30px, отдельный Separator 1px; `titleBarStyle: Overlay`, `hiddenTitle`, `bg-chrome`, резерв traffic lights 80px, видимой подписи нет (решение пользователя 07.10.2026): ряд это только место для перетаскивания окна и резерв светофоров; нативный заголовок окна `Settings` скрыт (`hiddenTitle`) и остаётся для меню Window и Mission Control; `data-tauri-drag-region`; цвет chrome-токена страница сообщает бэкенду (`report_window_surface`, SPEC_TABS.md, В25) |
| Размер | 760×560 по умолчанию; `minWidth 640`, `minHeight 460`; resizable |
| Открытие | единственный экземпляр: повторное открытие фокусирует существующее окно |

Точки входа:

- кнопка `Settings` (`⌘,`) в нижнем баре вкладки вместо нынешнего
  дропдауна `ThemeMenuButton` (дропдаун удаляется, его пункты переезжают в
  Appearance);
- нативный пункт меню приложения `Settings…` с акселератором `Cmd+,`
  (стандарт macOS) — работает из любого окна.

Реализация открытия — Rust-команда `open_settings_window`
(`WebviewWindowBuilder`): создаёт окно с url `settings.html` или фокусирует
существующее. `src-tauri/capabilities/default.json` выдаёт права по меткам
страниц: `webviews: ["tab-*", "tabbar-*", "settings"]` (SPEC_TABS.md, В24).
Окно настроек одно на приложение и окном вкладок не считается. Close Tab (⌘W)
и Close Window (⇧⌘W) закрывают его, когда оно в фокусе. Закрытие последнего
окна вкладок завершает приложение и закрывает окно настроек (SPEC_TABS.md,
В33).

Фронтенд окна — **отдельный Vite-entry** (`settings.html` +
`src/settings/main.tsx` + `SettingsApp.tsx`): не тянет App/Grid/Detail,
импортирует `global.css` (те же токены/тема) и `@/lib/commands`.

  общему правилу меню (13px, DESIGN_SYSTEM.md, «Текст интерфейса 13 px»).
  Замер в WebKit 07.10.2026: во всех разделах каждый видимый текст 14px
  `system-ui`.

## Appearance

Доступные настройки:

| Настройка | Контрол | Ключ |
|---|---|---|
| Theme: System / Light / Dark | пилюля `Tabs` (size `panel`) | `theme` |
| Card corners: Square / 4 | пилюля `Tabs` (size `panel`) | `mine.cardRadius` |
| Fade content under the chrome | `Checkbox` + подпись | `mine.scrollEdgeFade` |
| Hide bottom menu | `Checkbox` + подпись | `mine.bottomActionBarHidden` |

`Spacing` (`mine.spacing`) с 30.09.2026 живёт в панели `Display` ленты
([SPEC_FEED_DISPLAY.md](SPEC_FEED_DISPLAY.md), Д17).

Скругление карточек `3` совпадает со скруглением интерфейса (`--radius-1`);
значение `4`, сохранённое 02.10.2026, когда интерфейс на день стал 4px,
читается как `3`. Настройки показа коллекций
карточки при наведении нет: коллекции видны в нижнем ряду самой карточки, а
пилюли `Connected` в боковом меню показывает только клавиатурный фокус
([SPEC_CARD_STATES.md](SPEC_CARD_STATES.md), С4, С8.9). Ключ
`mine.hoverCollectionPills` больше не читается.

Оформление использует только Alt 1, системный шрифт интерфейса и системный
шрифт статьи (решение пользователя 06.10.2026). Нижняя панель использует только стандартные кнопки. Сохранённые
значения удалённых вариантов при запуске заменяются действующими. Значение
отступа `2` читается как `16`. Карточка метаданных в просмотре статьи
использует тот же `--radius-card`, что и карточки ленты.

Каждая строка настройки: лейбл слева (`text-base`), контрол справа; подпись
вторичным текстом (`text-base text-muted-foreground`) под лейблом, если нужна.

Логика темы выносится из `ThemeMenuButton` в общий модуль
`src/lib/themeMode.ts` (`getStoredTheme` / `applyTheme` c `setTauriTheme`) —
оба окна применяют тему сами при старте и при изменении.

**Межоконная синхронизация**: после каждого изменения settings-окно пишет
localStorage (общий для origin) и эмитит Tauri-событие `settings-changed`
(`{ key, value }`). Главное окно слушает событие, записывает `value` к себе
(`adoptSettingsChange`) и перечитывает значения (тема применяется через
`applyTheme`, видимость нижней панели через существующий сеттер). Событие
выбрано вместо DOM `storage` как гарантированный канал в Tauri.

Значение едет в событии с 29.09.2026. Каждое окно работает в своём процессе
WebKit, запись одного окна доходит до хранилища другого позже события, и
перечитывание на месте возвращало старое значение: выключенный переключатель
действовал до перезапуска приложения.

## Graph

Graph View не содержит собственного поиска, scope switcher или settings menu.
Оставшиеся persisted-параметры находятся только здесь:

| Настройка | Контрол | Значение по умолчанию |
|---|---|---|
| Collections | `Checkbox` + подпись | `true` |
| Wikilinks | `Checkbox` + подпись | `true` |
| Related notes | `Checkbox` + подпись | `true` |

Все три значения хранятся одним объектом под ключом
`mine.graphPreferences`. Settings использует общий
`getStoredGraphPreferences` / `storeGraphPreferences` контракт и эмитит один
`settings-changed` с этим ключом. Главное окно перечитывает объект и передаёт
его в Graph View; Graph View не владеет второй persisted-копией.

### Ожидание доступа к файлам

`space_stats(path)` выполняет весь обход файлов в `spawn_blocking`. Список
пространств читается из конфигурации и остаётся доступным, даже если macOS ждёт
решения о доступе к одному из каталогов. Незавершённый подсчёт показывает
знак ожидания только в своей строке. Отказ в доступе скрывает статистику только в ней.
Переход к другому разделу настроек не ждёт завершения подсчёта.

### Поведение

- Список — `known_vaults` из config (`list_known_vaults`), порядок как в
  config; рендерится мгновенно. Строка: имя папки (`basename`, `text-base`),
  под ним полный путь (`text-base text-muted-foreground truncate`), под ним
  сводка `N elements · N markdown · N media · N files · size`; справа по
  hover/focus-within — `⋯` (слот фиксированной геометрии, opacity-канон
  карточек).
- Над списком нет инструкции по клику и перетаскиванию. Под списком нет
  постоянной карточки iCloud. Раздел содержит только управление пространствами.
- Пространства, открытые во вкладках, отмечены `bg-active` (Р-12); остальные
  строки `bg-accent` + `hover:bg-active`. Все доступные строки кликабельны,
  открытые тоже: клик и клавиши Enter и пробел вызывают `show_space(path,
  false)` (Р-9). Ошибку показа раздел выводит под списком. Событие
  `spaces-open-changed` обновляет отметку и перечитывает список (вкладка могла
  создать или добавить пространство), `space-moved` перечитывает список с
  новым путём.
- Строки перетаскиваются (dnd-kit, PointerSensor `distance: 8` — клик не
  начинает drag): optimistic `arrayMove` → `reorder_known_vaults(paths)`.
  Порядок в config канонический: `VaultSwitcher` вкладки перечитывает
  `list_known_vaults` при каждом открытии меню.
- Статистика: `space_stats(path) -> SpaceStats { file_count, markdown_count,
  media_count, total_bytes, element_count: Option }`, вызывается per-row после
  рендера списка. До ответа сводка — `…`; `element_count: null` → `—`;
  ошибка команды → сводка `—`.
- `Remove Space` в `⋯`-меню — **detach-семантика** (`variant="detach"`,
  иконка `Unlink`): забыть из списка, данные на диске не трогаются
  (пояснение `Files stay on disk` находится в самом пункте меню). Доступен
  для любого пространства, открытого во вкладках или нет (Р-6): раздел
  вызывает только `forget_known_vault(path)`, бэкенд переводит вкладки
  забытого пространства к выбору пространства.
- `Add Space` внизу (`Button default`): нативный directory-picker
  (plugin-dialog `open`) → `add_known_vault(path)` — добавляет в
  `known_vaults` **без открытия** во вкладке.
- Команды `add_known_vault(path)`, `forget_known_vault(path)`,
  `reorder_known_vaults(paths)` (set-equality с config) мутируют только
  config.json; `forget_known_vault` дополнительно переводит вкладки забытого
  пространства к выбору пространства и рассылает `spaces-open-changed`.

## Пространство разделов Orphans и New files

С 03.10.2026 разделы Orphans и New files (`OrphansSection`, `LayoutSection`)
действуют на пространство, выбранное в самом разделе, а не на текущее
пространство процесса, которого с вкладками нет ([SPEC_TABS.md](SPEC_TABS.md),
В71).

- Выбирать можно только пространство, открытое хотя бы в одной вкладке: только
  у него открыт индекс. Список даёт `useOpenSpaces`: `spaces_in_tabs()` и
  `list_spaces()` при входе, затем событие `spaces-open-changed` (с повторным
  чтением списка пространств) и `space-moved` (новый путь для превью).
- Выбор стоит первой строкой раздела: `SettingRow` `Space` с подписью
  `One of the spaces open in tabs` и выпадающим списком
  (`OpenSpaceSelect`, `DropdownMenuRadioGroup`). По умолчанию выбрано первое
  открытое пространство; если выбранное закрылось, раздел переходит на первое
  открытое.
- Команды раздела получают `vault_id` явно: `list_orphan_media(vault_id)`,
  `promote_orphan_media` и `delete_orphan_media` с `vault_id` в
  `OrphanMediaBatchRequest`, `get_vault_write_layout(vault_id)`,
  `set_vault_write_layout(layout, vault_id)`.
- Содержимое раздела строится заново для каждого пространства (ключ React по
  `vault_id`): выделение сирот и черновик поля папки одного пространства не
  попадают в другое, а ответ, пришедший для прежнего пространства, никуда не
  ложится.
- Без открытых пространств раздел показывает `Open a space to find its orphan
  media.` (Orphans) или `Open a space to configure its folders.` (New files).
- Изменения в пространстве (`promote_orphan_media`, `delete_orphan_media`)
  доходят до всех вкладок этого пространства событием `vault-changed`
  (`effects::space_changed_in`, SPEC_TABS.md, В16).

## Orphans

**Определение сироты**: файл верхнего уровня vault с медиа-расширением
(канон `preview_plan`: image + video; `.md` и служебные файлы исключены), на
который не ссылается ни один блок ни одним способом учёта媒иа — frontmatter
`file`/`thumbnail` и inline-ссылки тела (wikilinks/markdown) через тот же
`MediaResolver`, что использует delete-план (`collect_delete_media_for_block`).

Команда `list_orphan_media(vault_id) -> OrphanMediaList { vault_id, orphans:
Vec<OrphanMedia { file_name, size_bytes, modified_at }> }`: один проход по
всем блокам индекса собирает referenced-set,
затем `readdir` vault; **никаких O(n²)**. Запускается при входе в раздел и по
кнопке Refresh; не на keypress.

Сканирование и удаление выполняются через `spawn_blocking`, с отдельным
read-only SQLite-соединением. Общий `vault_state` mutex нужен только для
снимка выбранного VaultLayout и не удерживается во время сканирования/Trash.
Запрос привязан к пространству, выбранному в разделе (`vault_id`).
Перед удалением worker заново
собирает referenced-set и проверяет пути; повторные имена исключаются.
Проверка ссылок является снимком перед операцией, не транзакцией с внешними
редакторами Markdown.

Проверенные пути передаются одним пакетом в `trash::delete_all`, а не отдельным
вызовом Finder на файл. Ошибка Trash возвращается пользователю; переход к
`remove_file` запрещён также в общей функции `delete_user_file`. На платформе
без Trash удаление завершается ошибкой, а не безвозвратным удалением.
При частичном успехе оставшиеся файлы сохраняются, UI обновляет список даже
после ошибки. Восстановление перемещённых файлов — через системную Корзину.

UI:

- Заголовок раздела + счётчик (`N files`, голое число — язык счётчиков).
- Список строк: `Checkbox` · превью `size-8` (для изображений —
  `asset://`-миниатюра самого файла `object-cover`; для видео/прочего —
  placeholder-слот `bg-component-fill`) · имя файла (`truncate`) · размер
  (`text-base text-muted-foreground`, right).
- Шапка списка: `Checkbox` «select all» (indeterminate при частичном выборе)
  + счётчик выбранного.
- Панель действий под списком (видна при выборе ≥1):
  - `Convert to Elements` — `Button default`: батч-команда
    `promote_orphan_media(request: OrphanMediaBatchRequest) -> Vec<IndexedBlock>`;
  - `Delete` — `Button destructive`: `AlertDialog` подтверждение
    («Delete N files? Files are moved to the system Trash.»), затем
    `delete_orphan_media(request: OrphanMediaBatchRequest)` (crate `trash`).
- Пустое состояние: центрированное `No orphan media`
  (`text-base text-muted-foreground`).
- После любой операции список перезагружается; прогресс батча — кнопка в
  disabled с «Working…», без отдельного прогресс-UI в этой итерации.

**Promote-семантика** (`promote_orphan_media`): для каждого файла создаётся
`.md` **рядом, без копирования медиа** (файл уже в vault — этим отличается от
`create_block(file_path)`, который копирует внешний источник):

- slug = stem имени файла; коллизии — по существующим правилам identity
  (semantic collision suffix, SPEC_IDENTITY_ROBUSTNESS);
- `type`: image/video по расширению, иначе file; frontmatter `file:` указывает
  на медиа; body пустое; `saved_at` = now;
- индексация штатной цепочкой; вкладки пространства подхватывают новые
  элементы через `vault-changed` от команды, без специальной синхронизации.

Защиты: команды валидируют, что каждый `file_name` — top-level файл vault
(никаких путей с разделителями), существует и действительно сирота на момент
операции (revalidation внутри команды; устаревшие имена возвращаются в
ответе как skipped, UI показывает итог «Converted N, skipped M»).
